# 机关解谜玩法规划：底部钥匙与颜色盖布

更新日期：2026 年 10 月 10 日。底部钥匙与颜色盖布已纳入开发规划，尚未授权实现、生产正式题库或改变现有玩法。本文沿用原文件路径，是机关解谜的唯一方案正文；关联创意 71、73、75、76、79、80，编号继续保留在[创意清单](gameplay-ideas.md#通过整理逐步解锁棋盘)。

## 开发目标与范围

让玩家通过整理液体达成阶段目标，打开新的瓶子或瓶组，再利用新增的液体与空间解开后续任务。一关内形成“准备 → 突破 → 新局面 → 再突破 → 完成”的过程，前后阶段共享同一个持续变化的棋盘。

本轮规划以两类机关为主：底部钥匙分组展开、完成对应颜色揭开盖布。未开放的瓶子可以装有液体，不限于空瓶。“完成任意颜色打开空瓶”的创意 72 保留为独立候选，不作为这两类机关的共同限制。

现有经典千关、副关、记忆百题和内部调色保持各自规则。机关模式建议使用独立入口、关号与进度，具体入口布局待评审。本题内展开的“区域”指瓶组，与[主页四区域候选](gameplay-ideas.md#四个游戏区域题库规模与提示资源讨论方向)无关。首轮不叠加记忆黑块、凝固、配方杯、变色、变容量或新的商业门槛。

## 两种展开方式

| 方式 | 阶段目标 | 开放结果 | 主要决策 |
| --- | --- | --- | --- |
| 底部钥匙 | 解放瓶底钥匙所在位置，取得钥匙 | 打开与该钥匙对应的一组瓶子，可继续连锁 | 怎样移走覆盖液体、安排中转并取得下一把钥匙 |
| 颜色盖布 | 整理出一整瓶指定颜色 | 揭开与该颜色对应的瓶子或瓶组 | 优先完成哪种颜色，先取得哪组液体与空间 |

### 底部钥匙：分阶段探索

用户给出的代表结构是十二瓶按 **6 + 3 + 3** 展开：开局六瓶可操作，第一把钥匙开放三瓶，第二把钥匙再开放三瓶。六瓶包含本阶段实际需要的周转空间，不表示六瓶全部装满。第二把钥匙可以在后续瓶组中，以形成阶段依赖；具体位置由出题与完整验证决定。

钥匙与目标瓶组的对应关系固定、可辨认。新瓶组预先属于整题，可以带来新液体和新空间，不在解锁时随机生成。新阶段要用到前阶段整理的成果，避免仅把几道互不相关的普通题串起来。

**钥匙的精确触发尚未冻结。** 用户描述包括“对应格被解放／整理后取得钥匙”，不能直接等同于已有确定规则。首轮建议比较：

- **清空瓶子取钥匙：** 钥匙固定在瓶底，最后一份液体移出后触发。因果清楚，优先作为原型建议。
- **解放标记格取钥匙：** 若采用液体格标记，必须先确定是露到顶部、该份移出，还是该份归入指定成果瓶才触发，并定义标记是否随液体移动。冻结一种语义后才能出题，不在同一批题中隐式切换。

钥匙是机关触发标记，不占液体容量，不作为背包资源或消耗道具。十二瓶、每次三瓶是用户举例，不是每题固定配额。

### 颜色盖布：目标与顺序选择

用户给出的形态是四瓶、八瓶或十二瓶的整题布局，其中部分瓶子盖布，例如旁边四瓶暂不可用。盖布上的颜色及辅助符号说明开放条件：形成一整瓶对应颜色后，揭开关联瓶子或瓶组。

同一颜色可关联一瓶或一组；具体映射写入题目，不默认四瓶必须一起打开。若有红、蓝两组条件，可设计两种首色都能推进，也可设计有线索的先后依赖。解锁顺序的价值来自两组所提供资源的差别，不能只换颜色制造表面变化。

“完成颜色”建议定义为同一只普通瓶装满四份同色，不要求放入指定瓶位，也不消耗这瓶液体。之后仍可正常倒水。指定瓶位、多条件合取等变体留待单独评审。

## 共用规则与表现建议

以下是进入实现前需要冻结的建议规则，不把本次文档整理当作全部细节已获批准。

| 项目 | 规划要求／建议 |
| --- | --- |
| 液体规则 | 沿用顶部连续同色、目标匹配、每瓶四份等容量；整题每色四份，含未开放组一起守恒 |
| 内容固定 | 所有瓶子、液体、钥匙、盖布颜色与组映射在离线制作时确定，瓶子具有稳定 ID |
| 未开放组 | 不能倒入或倒出；显示数量、锁／盖布和可理解的条件，不泄露尚未公开的液体颜色 |
| 解锁提交 | 合法倒水后判定机关，液体与机关状态一并提交和保存，再播放开锁／揭布；动画不授予进度 |
| 解锁持续 | 建议触发后保持开放；再从完成色瓶倒水不自动关门，同一触发不重复播放或累计奖励 |
| 整题完成 | 所有必需瓶组已开放，且整题所有非空瓶满且单色；当前可见组完成不等于整关通关 |
| 撤销 | 免费回退液体与机关；撤销触发动作时恢复之前的开放状态，不受锁瓶禁倒限制 |
| 重来 | 恢复整题固定布局、初始开放组与机关；不重复授予首次完成记录 |
| 恢复 | 返回、后台和冷启动恢复液体、开放状态、触发记录与有界撤销历史，不补播机关表现 |
| 提示与权益 | 建议原型一步提示免费、独立于主线钱包；正式提示、奖励、Premium 与推荐映射待定 |

机关访问权限与玩家已知信息分开处理：撤销可重新锁住瓶组，但已经看过的颜色不能被解释为玩家重新未知。是否重新盖布及怎样保留已知内容提示须在原型前明确；如涉及知识记录，须按同一尝试保存，不用遮盖制造重复记忆负担。该规则与现有记忆玩法的揭晓后知识保留原则一致。

保持十五款免费玻璃、同局统一款式、现有轻点倒水、两排且每排至多六瓶的大瓶布局。总瓶数包括未开放瓶，最多十二瓶，逻辑色最多十一种；颜色数和总空容量须另行校验，不由“6 + 3 + 3”推导。建议为未开放瓶保留最终位置，开锁时原位展开，不缩小已有瓶子；具体盖布占位表现需小屏验证。移动美术仍允许横向越界裁切。

当前目标、条件与组映射应有视觉线索和本地化读屏说明，颜色条件同时支持符号；点击锁／盖布可查看一行说明。可以隐藏后续内容，不能要求玩家猜未提示的规则。首轮不增加倒计时、失败惩罚、付费钥匙或独立音效设置。

## 出题与验证

每题先确定要考察的突破，再安排液体、开放组与触发条件。颜色盖布必须能在开放对应组之前取得该完成色；钥匙不能只存在于它自身打开的组内。阶段依赖和初始周转空间必须实际求解验证，不能靠普通布局有解推断机关题有解。

1. **定义整题。** 保存全部布局、初始开放组、钥匙位置／标记、触发类型、目标组、规则版本与可重建来源。手工原型保存完整固定定义；生成题必须支持确定性来源重建。
2. **按机关规则求完整解。** 搜索状态包含液体、开放组和触发记录；提示使用同一规则。只把角色、条件和组关系等价的瓶子作对称合并，并将路线映射回真实瓶 ID。
3. **独立回放所有阶段。** 检查每步合法性、液量守恒、触发时机、组开放及最终完成；覆盖一个动作可能满足多个条件的情况，明确同步触发顺序，不能由动画回调接力解锁。
4. **检查顺序和信息公平性。** 比较可达钥匙／首色及其完整后续。早段优先允许多种选择完成，或提供清楚的顺序线索；不能要求玩家依据盖布下未知颜色判断唯一安全分支。具体验证方法随最终信息规则冻结，不能用全知求解路线替代这一检查。
5. **核查展开价值。** 记录新增瓶和液体实际参与的动作、阶段之间的依赖与关键选择；与全部开放的版本对照。永久关闭组的研究只检查当前阶段可达目标，不能把“未全开不能整题完成”当作机关必要性的证据。
6. **去重与导出复验。** 结构键包含液体、机关类型、标记位置及瓶组关系；换瓶位、换颜色或换盖布外观不能直接算新题。相近派生题归为同一家族。SQLite 导出后逐项读回全部定义与完整路线。

搜索超预算、取消或尚未完成统一记为未知，不视为高难、无解或已验证。必需可解证明未知的候选不进入正式题库；用于选题的顺序后果证据也须明确其已知范围。不进行每次倒水的全局搜索。

## 难度与内容节奏

机关题不直接套用经典 human-decision-v1、记忆双轴分或其等级。首轮记录每阶段达成距离、可行解锁顺序、准备依赖、实际选择后果、新空间使用、后续决策以及操作量，分别判断探索负担与整理负担。

内容顺序建议为：单机关教学 → 同规模的准备与取舍 → 两段连锁 → 解锁顺序变化。先分别体验钥匙与盖布，再评审两者组合。每次主要增加一个因素，不同时加颜色、加机关并减少空间；挑战之间安排熟悉、宽松的恢复题。新增阶段必须带来新决策，不能全是机械收尾。

机关等级、步数窗口、正式题量、峰谷阈值与生产规模尚未冻结，须在两种机制试玩后确定，不预先承诺固定配方、百题或千题。

## 开发顺序与验收

| 阶段 | 工作 | 进入下一步的条件 |
| --- | --- | --- |
| 当前：规划整理 | 保留两种方式，列明建议和待定边界 | 本文作为后续评审依据；当前不改代码或题库 |
| 规则与原型定义 | 冻结钥匙语义、盖布映射、撤销知识及完成判定；建议每种 2–3 道固定题 | 每题已有可验证的阶段目标与整题定义，另行确认进入实现 |
| 小规模原型 | 实现共享机关状态、回放、求解、保存和最低限度展开表现 | 完整解与独立回放、撤销／重来／冷启动及内容读回通过 |
| 试玩评审 | 分别体验单次解锁、两段连锁、顺序选择；检验十二瓶 6 + 3 + 3 代表布局 | 玩家能说明条件、主动规划、感到突破；后半局仍有思考，隐藏信息不迫使猜测 |
| 正式内容规划 | 按合格题供给决定题量、节奏、入口及权益 | 规则稳定、机制有变化，真实设备性能与交互通过后再扩充 |

题量和先钥匙后盖布是原型建议，不是已承诺交付。十二瓶是需要检验的代表规模，不要求所有教学题从十二瓶开始。试玩观察两类机关的理解、阶段前后可操作时间、倒水／撤销／重来／提示、触发顺序和新瓶首次使用；沿用[统计方案](gameplay-statistics-plan.md)的时间口径，不把动画或后台计入思考。

## 实施依赖与待定决定

现有 SQLite 新基线与颜色记忆百题均已实现。未来在现有共享规则／会话、分片求解和 SQLite 内容／玩家库边界上增加机关能力；当前经典或记忆路线不能直接充当机关题证明。

新增内容须保存规则版本、机关／组 ID、完整定义、来源及路线证据；玩家库独立保存模式进度、液体与机关快照、有界历史及必要知识状态。初始化只建立该模式数据，不清空经典、记忆、钱包、偏好或统计，不增加旧 JSON／AsyncStorage 导入、双写或开发试验迁移。

进入实现前仍需明确：钥匙精确触发、盖布一瓶／一组映射、同动作多触发处理、撤销后的已知信息呈现、入口与正式辅助／权益。四区域、18／24 瓶、其他机制组合与商业扩展均为各自后续议题，不作为本轮依赖或验收目标。
