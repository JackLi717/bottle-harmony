# 颜色解锁玩法规划

状态：2026 年 10 月 8 日，已授权规划，尚未批准实现或生产正式题库。本文是颜色解锁专题的唯一方案正文，对应创意 72；用户已选定先实施[观察记忆原型](memory-mode-plan.md)，本专题保留为后续候选。所有题量、增长区间和验收数值均为原型假设，试玩后再冻结。

## 体验目标与首批边界

核心体验是先整理出一种颜色，取得新的中转空间，再完成全局。玩家需要选择先突破什么，并感受到自己的整理成果改变了棋盘。

建议首批只采用“完成任意一种颜色，打开一只空瓶”。不同时加入指定颜色钥匙、多锁连锁、隐藏颜色、凝固、变容量或十八瓶；这些会改变出题和评价条件，另行规划。现有主线与副关继续保持原规则，新模式使用独立入口、关号和进度，不替换千关或预先指定其四区域归属。

## 规则与恢复

| 项目 | 建议规则 |
| --- | --- |
| 液体与完成 | 每色四份、每瓶四份容量；所有非空瓶满且单色即完成，空瓶可以留下 |
| 初始空间 | 一只可用空瓶 E=1，一只上锁空瓶 L=1；锁瓶从开局就在固定位置，计入总瓶数 |
| 锁瓶限制 | 未解锁时不能倒入或倒出；可点击查看一行条件说明，不扣资源、不触发动作 |
| 解锁触发 | 一个合法动作首次形成满瓶同色时，立即在逻辑状态中开放锁瓶；动画随后呈现 |
| 解锁持续 | 解锁后保持开放，之后从完成瓶倒出不重新上锁；完成瓶仍可正常倒水 |
| 撤销 | 棋盘与机关一起回到动作前；撤销触发解锁的动作会重新上锁，之后的撤销按历史正常恢复 |
| 重来 | 恢复原排列与锁瓶，保留该题既有首次完成记录；不重复奖励 |
| 后台与冷启动 | 恢复已接受的棋盘、锁状态和撤销历史；不重播开锁，不由动画授予空间或进度 |

不允许开局已有满瓶同色，从而自动开锁。第一批保持每只初始瓶内同色至多两份，包括不相邻层。锁瓶不使用现有“免费点一下启用备用瓶”的行为，也不把瓶塞变成新的禁倒规则。

原型中撤销、重来和按需一步提示免费，独立于正式主线提示券，不发主线奖励。正式模式的免费提示、券、首次完成奖励、Premium 和推荐资格映射须在选择实施前确定；不默认扩张或减少已确认权益。提示必须按当前锁状态求解，预算不足为未知。

## 出题策略

每题先写明一个要考察的决策，再构造候选；锁瓶始终占据位置，颜色与液量守恒。第一批优先以下题型：

| 题型 | 玩家要思考的事 | 选题证据 |
| --- | --- | --- |
| 看见突破 | 如何快速形成第一只完成瓶 | 短且易读的有效开锁路线，用于教学 |
| 先腾空间 | 合并之前先把唯一空瓶安排给谁 | 完成前存在准备动作，并有可恢复的顺序差异 |
| 选择首色 | 两种颜色都可先完成，哪条更顺畅 | 各首色均有完整后续验证，比较真实路线代价 |
| 露出底色 | 先搬走哪些上层，释放分散的目标色 | 路线显示跨瓶依赖，不以颜色多冒充规划深 |
| 保留周转 | 暂缓一个局部合并，为开锁保留位置 | 在具体观察点验证替代动作的后果 |
| 用好新空间 | 开锁后如何使用新瓶解决第二个问题 | 锁瓶实际参与后续，后半局仍有整理决策 |

教学题可主要展示开锁。其他题避免“第一瓶一完成就几乎全局结束”、锁瓶从不使用、反复搬运却没有判断变化，以及依赖不可辨认色差。早段错误选择优先设计为可撤销或短绕路，不集中堆确证死路。

### 候选制作与验收链路

1. 选定颜色数 C、E=1、L=1、题型与角色；总瓶数 B=C+2。利用现有全打乱／一层底色来源构造候选，并记录哪个空瓶上锁。锁角色属于题目来源，不能只记录普通布局。
2. 用新的机关规则求完整解；普通求解器把锁瓶当可用空瓶得到的解不能作为验收。保存包含开锁状态变化的路线，并独立逐步回放。
3. 分别检查可以首先完成哪些颜色、到达开锁的路线，以及各路线开锁后的可解性。“可以完成某色”与“完成后能解全局”分开记录。
4. 做两个对照：全部空瓶从开始开放；锁瓶永远不开放。分别求解并保留 solved／unsolvable／unknown，评估锁的限制和开放后的实际价值。
5. 探测开锁前关键选择、开锁后首次使用新空间及后半局的替代后果。指定路线观察与必要策略证明分别标记，未知候选不填补配额。
6. 全局精确去重，独立复算规则、来源、路线与机制指标；再人工检查关键决策是否看得懂、是否有突破感。改变瓶位或颜色名称不算新结构。

同一液体布局上改变锁角色可能改变规则结构，应在机制键中区分；高度相似的派生题归为同一家族，不能靠换锁位置大量填题。题目编号在验收后固定。

## 难度考察

现有 `human-decision-v1` 的证据与阈值针对普通主线，不能直接用于机关题。先记录下列原始量，用分级选题和试玩校准；不先编一个未经验证的综合总分。

| 维度 | 制作时记录 | 解释边界 |
| --- | --- | --- |
| 开锁距离 | 最少多少步能开锁且仍能完整完成；完整最短解中开锁位置 | 最快开锁路线未必是全局最优，二者分别保存 |
| 首色选择 | 可达首色数、其中可完整完成的首色数、不同首色最佳完整代价 | 选择多可能更宽松，不能单按数量加难 |
| 准备与依赖 | 开锁前连续准备长度、释放底色和中转瓶用途变化 | 一条路线有准备链不证明所有解法都必需 |
| 选择后果 | 观察点各不等价动作的精确绕路或无解结果 | 仍用共享规则重求剩余最短距离；超限为未知 |
| 开锁价值 | 锁瓶实际使用；永不开放的可解性／距离与正常规则比较 | 永不开放无解只说明该对照需要机关，不说明正式题无解 |
| 后半局质量 | 开锁后剩余步数、空间转换与关键选择 | 剩余动作多不自动代表有趣 |
| 视觉与操作 | 颜色、瓶数、参考操作量与识色反馈 | 与规划负担分开，不用放大棋盘替代解谜 |

优先制作同规模、不同开锁依赖的对照题，再检查规模增长。普通棋盘下的旧分只可作为“全部开放”对照，明确标为对照，不能作为本题机关等级。

## 颜色与瓶数增长

每色只对应最终一只满瓶，容量始终四份。C 是逻辑颜色数，B 是总瓶数，包含一只可用空瓶与一只锁瓶。

| 内容段 | 颜色 C | 总瓶数 B | 增长重点 |
| --- | ---: | ---: | --- |
| 1–3 教学 | 2–3 | 4–5 | 学会开锁，形成清楚因果 |
| 4–10 入门 | 3–4 | 5–6 | 在相近规模中比较首色与顺序 |
| 11–20 发展 | 4–5 | 6–7 | 加入底色释放、连续准备和新空间复用 |
| 21–30 检验 | 4–6 | 6–8 | 组合已学思路，仍穿插小棋盘高质量题 |
| 验证后扩充至 60 | 4–7 | 6–9 | 增加题型变化，检验更长依赖 |
| 验证后扩充至 100 | 5–8 | 7–10 | 少量较大棋盘与更深选择，不全段放大 |

后两段只是扩充路线，不承诺题量。首批原型最多六色／八瓶，正式数量按合格供给决定。十二瓶上限下，E=1、L=1 意味着最多十色；现有普通主线的十一色配置不能直接套入此模式。十八／二十四瓶不在本专题首批范围。

“增长”表示逐步引入更高的规模上限，不要求每关加颜色或瓶子。缓冲题可用已经熟悉的较小规模；若保持规模，也可缩短依赖、增加安全路线。每次只提高一个主要因素，再用熟悉题巩固。

逻辑容器首批只有普通瓶和锁瓶两种角色，数量规则固定。十五款玻璃外观仍全部免费、同局统一、自主选择；不会随难度解锁新外观、改变容量或用不同杯形作为隐性难度条件。实际验证覆盖窄口、宽杯和高脚杯。

## 分级与坡度

先使用独立的 U1–U4 制作等级，避免与主线 D1–D4 混淆。以下开锁步数是选题起始窗口，允许因清楚的决策价值调整；它们不是玩家难度测定值，也不是单独的晋级条件。

| 等级 | 可完成开锁路线的参考窗口 | 决策特征 |
| --- | ---: | --- |
| U1 认识 | 约 2–4 步 | 一个清楚目标、少量安全中转；开锁价值立即可见 |
| U2 取舍 | 约 4–7 步 | 比较首色或顺序，一次主要空间安排，错误可恢复 |
| U3 协调 | 约 6–10 步 | 多瓶依赖、用途切换；开锁前后各有有效决策 |
| U4 挑战 | 约 8–12 步 | 更长依赖或两次关键取舍；小棋盘也可入选 |

从 U1 进入 U2 必须体现取舍，从 U2 进入 U3 必须体现协调；只因路线变长不升级。候选不足时缩小交付量，不靠越过窗口或提高颜色数量补齐。

首个 30 题试排采用三个十题单元。每单元位置 1–2 恢复／巩固、3–5 单因素爬坡、6 次峰、7 恢复、8–9 组合爬坡、10 主峰；第一单元位置 1–3 为教学。

| 单元 | 熟悉区间 | 次峰／主峰目标 | 下一单元恢复 |
| --- | --- | --- | --- |
| 1–10 | U1 为主，开始引入 U2 | U2 的单次取舍／完整取舍 | 回到 U1–U2，减少关键依赖 |
| 11–20 | U2 为主，开始引入 U3 | U2–U3／U3 | 回到 U2，保留熟悉规模 |
| 21–30 | U2–U3 为主 | U3／少量 U4 | 若继续扩充，下一单元先回到 U2–U3 |

挑战的区别落实到依赖与选择后果；恢复至少降低一个制作等级，或在同级内明确减少一个关键决策并经试玩确认。第 6 题后第 7 题也须有可感知恢复。主峰规划目标不下降，但最终体验是否变难仍需真人验证；不复制主线“+4／+5／-12 分”阈值。

每关记录角色、主考察维度、颜色／瓶数、机制指标、前后相邻变化理由。不得在同一过渡同时加颜色、延长准备链、缩小可用空间并增加高成本分支。局部曲线允许回落；长范围提高思考深度，不把增长做成连续高压。

实际排题先选各单元的合格主峰与次峰，再匹配恢复题，最后填入逐步接近峰值的爬坡题；同时检查相邻题型变化和新概念是否已教学。非教学段新增一种颜色最多加一色，优先放在单元位置 3，随后用位置 4–5 巩固；位置 8–10 组合已经学过的因素，不临时引入新规则。颜色增加当题先降低依赖，不能直接作为高峰。

验收按每个过渡和连续十题进行：峰的关键决策、恢复所减少的负担、新颜色后的巩固、题型重复及完整路线均须有记录。无法同时找到高峰、恢复和爬坡供给时，先补对应候选或缩短题集，不强行排满三十题；试玩改变等级后重新排题，不保留旧排序过程。若以后扩充到四百题，先按验证后的单元持续增加结构变化，规模上限保持十二瓶，不线性增加颜色或机关数量。

## 原型、试玩与验收

先规划五道结构互异原型：教学开锁、先腾空间、双首色取舍、露底色依赖、开锁后再利用。每题必须完整验证，原型对照只用于研究，不直接充当正式新增关数。试玩通过后才规划 30 题试排，首轮不与记忆或凝固组合。

观察玩家能否解释触发条件，是否有意识选择首色，开锁时是否感到突破，后半局是否值得继续，以及卡住是否可理解。记录开锁前后各自的前台可操作时间、倒水／撤销／重来／提示、首个完成色与锁瓶首次使用；时间口径沿用[统计方案](gameplay-statistics-plan.md)，不把动画或离开手机算成思考。

建议以 6–10 名不同熟悉程度的试玩者做定性评审，所有比例同时报告人数和题目；这个样本用于发现问题，不作留存或普遍难度结论。比较两条方向时交替试玩顺序，并使用规模相近、未玩过的题，避免记住同一布局带来的偏差。

规划进入实现的条件：

- 五题来源、机制状态、路线和独立回放全通过，必需探测没有未知；与小棋盘未做对称合并的参考搜索对照正确。
- 玩家能理解触发且能指出有趣的突破；除教学外，不连续出现锁瓶无用或开锁后纯收尾的题。
- 连续十题的高峰与恢复能被描述出来；新颜色与新依赖的过渡没有集中受阻。
- 撤销／重来／后台恢复、提示、符号与十五款容器的表现可验收；真实设备提示与渲染在既定预算内。

若主要反馈是“开锁很漂亮，但怎么倒都一样”，先修出题；若玩家反复不理解条件，先修规则反馈。技术通过与趣味通过分别判断，不因已经做出动效扩大内容。

## 实施依赖与待评审决定

当前 `LevelDefinition` 只接受普通规则，`GameSession` 的历史只保存棋盘，现有求解器只处理普通／凝固角色。实施时须增加明确的机关规则版本、锁状态快照与搜索状态；只允许同规则角色合并对称，路线要能映射回真实瓶 ID。不能把不同锁状态的同一液体排列视为同一状态。

SQLite 改造正在另一项工作中推进。本专题只定义未来需要保存的题目机制、锁瓶 ID、来源、规则版本、机制路线与指标，以及玩家锁状态、撤销和模式进度；不修改正在建设的 schema。选择实施后再与其稳定接口协调，依然遵守内容导出后读回重验。现有千关与商业规则不因本文自动改变。

| 评审项 | 本文建议 | 实施前要冻结的内容 |
| --- | --- | --- |
| 首批机制 | 任意完成色打开一只固定空瓶 | 是否采纳；指定颜色与多锁留待后续 |
| 规模与题量 | 五题原型，再审 30 题；首批六色／八瓶以内 | 合格供给、设备结果与实际交付量 |
| 难度与节奏 | U1–U4、十题单元 | 试玩后的等级判定与恢复要求 |
| 权益与入口 | 独立入口／进度，原型提示免费 | 正式辅助、奖励、Premium／推荐及区域映射 |
| 开发顺序 | 观察记忆原型先行，本专题暂不实施 | 后续按原型价值、内容供给、实现风险与验收成本重新评审 |

后续评审比较玩家能否理解、是否出现清楚的新决策、是否想再玩、五题是否各有变化、可验证内容供给及实际设备成本。观察记忆先行不表示本专题或组合玩法已经获准实施。
