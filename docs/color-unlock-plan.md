## 开发目标与范围

让玩家通过整理液体达成阶段目标，打开新的瓶子或瓶组，或显露本瓶原先被遮盖的颜色，再利用新增的液体、空间或信息解开后续任务。一关内形成“准备 → 突破 → 新局面 → 再突破 → 完成”的过程，前后阶段共享同一个持续变化的棋盘。

本轮规划包含三种能力：底部钥匙分组展开、完成对应颜色揭开盖布、移走上层后逐层显露本瓶颜色。前两种开放瓶子操作权限，第三种只显露自身液体信息，不打开其他瓶组。未开放的瓶子可以装有液体，不限于空瓶。“完成任意颜色打开空瓶”的创意 72 保留为独立候选，不作为共同限制。

**产品定位已确认：经典排序是一种连续推进的玩法，普通整理和带机关／遮色的关卡共用经典入口、关卡流程与进度。** 不设“揭秘模式”、经典内子模式入口或另一套揭秘关号、进度、钱包。玩家从简单整理逐步进入带有新变化的关卡；“钥匙、盖布、逐层显色”是关卡能力，名称仅用于设计和必要教学，不据此拆分产品玩法。

现有公开千关、副关、记忆百题和内部调色是当前实现；本次决定规划经典后续的逐步扩展；用户进一步明确引擎升级后现有经典排序保持原规则与体验，不要求把新能力强行加入当前千关。未来人工精选内容的组织与付费仍属[设想](gameplay-ideas.md#精选设计关卡与体验门槛设想)，不立即替换闭测中的题目。具体首次出现关号、频率和内容版本待出题与试玩后确定。题内展开的“区域”指瓶组，与[主页四区域候选](gameplay-ideas.md#四个游戏区域题库规模与提示资源讨论方向)无关。首轮不叠加记忆万能块、凝固、配方杯、变色、变容量或新的商业门槛。

## 三种展开方式

| 方式 | 阶段目标 | 开放结果 | 主要决策 |
| --- | --- | --- | --- |
| 底部钥匙 | 清空钥匙所在整瓶，取得钥匙 | 自动打开固定关联的一瓶或一组瓶子，可继续连锁 | 怎样移走覆盖液体、安排中转并取得下一把钥匙 |
| 颜色盖布 | 任意一瓶装满四份指定同色 | 自动揭开固定关联的一瓶或一组瓶子 | 优先完成哪种颜色，先取得哪组液体与空间 |
| 逐层显色 | 移走遮盖在未知色块上方的液体，使其成为顶层 | 只显露该份液体的真实颜色，不打开其他瓶子 | 先探索哪只瓶子，怎样为新显露颜色安排空间 |

### 底部钥匙：分阶段探索

用户给出的代表结构是十二瓶按 **6 + 3 + 3** 展开：开局六瓶可操作，第一把钥匙开放三瓶，第二把钥匙再开放三瓶。六瓶包含本阶段实际需要的周转空间，不表示六瓶全部装满。第二把钥匙可以在后续瓶组中，以形成阶段依赖；具体位置由出题与完整验证决定。

钥匙与目标瓶组的对应关系固定、可辨认。新瓶组预先属于整题，可以带来新液体和新空间，不在解锁时随机生成。新阶段要用到前阶段整理的成果，避免仅把几道互不相关的普通题串起来。

**已确认：清空整瓶取得钥匙。** 钥匙横放在初始底层液体内部偏下，按真实瓶腔底部形状固定位置，呈沉底状态；随瓶子整体倾斜，不在瓶内滑动，也不随液体流走。最后一份倒出时仍留在瓶底；整瓶清空后自动触发，钥匙原位淡出，打开题目预先关联的一瓶或一组瓶子。露出底部液体、移动某个标记液体或将其送到指定位置均不是本轮触发规则。

钥匙是机关触发标记，不占液体容量，不作为背包资源或消耗道具。十二瓶、每次三瓶是用户举例，不是每题固定配额。

### 颜色盖布：目标与顺序选择

用户给出的形态是四瓶、八瓶或十二瓶的整题布局，其中部分瓶子盖布，例如旁边四瓶暂不可用。盖布上的颜色及辅助符号说明开放条件：形成一整瓶对应颜色后，揭开关联瓶子或瓶组。

同一颜色可关联一瓶或一组；具体映射写入题目，不默认四瓶必须一起打开。若有红、蓝两组条件，分析两种先后顺序带来的液体、空间和后续安排，形成有实际区别的选择，不能只换颜色制造表面变化。

**已确认：“完成颜色”指任意一只普通瓶装满四份指定同色。** 不要求放入指定瓶位，也不消耗这瓶液体。之后仍可正常倒水。指定瓶位、多条件合取等变体留待单独评审。

### 逐层显色：只显露自身颜色

**已确认能力：部分下层色块被遮盖，只有其上方液体移走、该色块露到顶部时，才自动显示真实颜色。** 每份液体与真实颜色在出题时固定，不在显露时随机生成。可以连续遮盖多层，随整理逐层显露；不要求开局全部下层都隐藏。

例如从顶到底为“红、未知、未知、蓝”，先移走红色，紧接着的一份未知色块显色；更深一份仍被上层覆盖，继续保持未知。此能力可以单独形成整理题，不需要钥匙或锁瓶。

规划沿用普通颜色匹配与四份容量。遮盖只影响信息，不将液体变成能匹配任意颜色的万能块；它没有记忆模式的开局观察／准备阶段，也不等到全盘外观完成才揭晓。初始可操作瓶的顶层应可见；盖布瓶先按瓶组开放规则处理，再判断其顶层信息。

**已确认的知识规则：**已显露的颜色沿用本规划已确认的信息保留原则，后续被液体覆盖或撤销也不重新隐藏；重来恢复原题初始遮盖。知识按稳定液体份 ID 保存，不能仅按瓶位或层号记录。

**已确认的倒水边界：** 只倒当前已知的连续同色段，下方未知块即使真实同色，本次也在原隐藏边界停止；动作提交后新顶层显色，玩家再次点击继续。游戏、求解、回放和教学必须采用同一边界。

## 已确认规则与实施约束

用户已确认触发、固定映射、隐藏信息、撤销、自动开放、题目质量责任与整题目标。下表同时记录配套的守恒、保存和验证约束；原型提示与商业权益仍明确保留为建议／待定。

| 项目 | 当前规则／约束 |
| --- | --- |
| 液体规则 | 沿用顶部连续同色、目标匹配、每瓶四份等容量；整题每色四份，含未开放组一起守恒 |
| 内容固定 | 所有瓶子、液体、初始遮盖份、钥匙、盖布颜色与组映射在离线制作时确定，瓶子及液体份具有稳定 ID |
| 未开放组 | 开局显示最终位置、数量、锁／盖布与解锁条件，不能倒入或倒出，看不见尚未公开的液体；各瓶原位展开 |
| 自动开放 | 达成条件立即自动打开，无领取操作；同一步满足多个机关时同步开放全部符合条件的目标，点击锁／盖布只查看说明 |
| 解锁提交 | 合法倒水后统一判定机关，液体与机关状态一并提交和保存，再播放开锁／揭布；动画不授予进度 |
| 解锁持续 | 触发后保持开放；再从完成色瓶倒水不自动关门，同一触发不重复播放或累计奖励 |
| 整题完成 | 整理好整题全部液体：包括未开放瓶在内，每只非空瓶均满四份且单色，空瓶允许保留；不额外要求取得全部钥匙或打开全部瓶组。仅可见组整理完成不能代替整题判定 |
| 撤销 | 免费回退液体与机关；撤销触发动作时恢复之前的开放状态，不受锁瓶禁倒限制 |
| 重来 | 恢复整题固定布局、初始开放组与机关；不重复授予首次完成记录 |
| 恢复 | 返回、后台和冷启动恢复液体、开放状态、触发记录与有界撤销历史，不补播机关表现 |
| 提示与权益 | 正式关卡接入经典既有的一步提示、撤销／重来与首次完成奖励流程，不另建机关钱包或额外奖励；具体关卡编排与既有商业资格的适用关系随正式内容方案明确。内部原型不扣经典提示券、不发奖励、不推进经典进度 |

**已确认撤销后的信息规则：** 撤销触发动作时重新锁住瓶组，已看过的液体保持可见，显示锁定标记且禁止操作，不重新用不透明盖布遮住。液体按动作历史回退，已知信息按同一尝试保留并保存；重来恢复开局布局与初始遮盖。这样撤销不会制造重复记忆负担。

保持十五款免费玻璃、同局统一款式、现有轻点倒水、两排且每排至多六瓶的大瓶布局。总瓶数包括未开放瓶，最多十二瓶，逻辑色最多十一种；颜色数和总空容量须另行校验，不由“6 + 3 + 3”推导。未开放瓶从开局保留最终位置，开锁时原位展开，不缩小已有瓶子；具体盖布占位表现需小屏验证。移动美术仍允许横向越界裁切。

当前目标、条件与组映射应有视觉线索和本地化读屏说明，颜色条件同时支持符号；点击锁／盖布可查看一行说明；逐层显色的未知标记不能泄露真实色或对应辅助符号，须与记忆万能块在表现和说明上可区分。可以隐藏后续内容，不能要求玩家猜未提示的规则。首轮不增加倒计时、失败惩罚、付费钥匙或独立音效设置。

## 静态外观：已确认基准与候选变种

用户已确认第一套概念方向作为待实现内容：保留现有冷色玻璃与鲜明液体，蓝灰柔光织物配低饱和金属机关与清楚的条件标记。布盖不透明、贴合容器、三至五道主要褶皱、收窄下摆；正面小色标与四个固定点表示四份同色条件，辅助符号沿用现有设置。瓶底钥匙是不占容量的机关标记，位置适配实际瓶腔，不放在玻璃外、瓶身标签处或高脚杯杯脚里；钥匙与对应锁孔同时以材质和形状配对：青铜圆头、不锈钢菱形头、红铜六角头。青铜使用青绿铜锈、不锈钢使用银灰、红铜使用红棕，避免黄铜与红铜过近；钥匙相对首版放大，按底层空间适配，并以细暗边与高光提高小屏可读性。三组以上保留显式编号，不能只靠复用颜色区分。布盖使用表示目标液体颜色的缝边徽章及四点条件，不画锁孔或锁扣；木匣、百叶、卷帘只显示承载条件的锁具，不再叠加圆形徽章。钥匙条件以锁体材质和锁孔头形配对；颜色条件将目标色、辅助符号和四点直接嵌在锁体上。钥匙机关使用刚性外壳，不把颜色徽章错误配到清空瓶条件。逐层未知份采用统一蓝灰与小问号，避免与记忆黑色万能块混淆；撤销后已见液体仍显示，只增加锁定标记。用户已授权按下述顺序实施；四个外壳家族、共用标记和显色表现已接入内部验收页面。正式机关题库与公开入口尚未交付，设备结论单独记录。

用户已确认柔光布盖、深色薄木匣和百叶护笼的效果稿作为第一版待实现基准。首套[静态基准](../assets/art-direction/unlock/static-baseline-v1.png)与三体系[效果稿](../assets/art-direction/unlock/cover-families-v1.png)保留在 assets/art-direction/unlock/，生成提示词见同目录 prompts.json。效果稿按初次锁定／展开过程／已见重锁展示材质与结构；视觉方向已批准，实际外壳、动画与棋盘适配已有源码实现；原图仍为对照基准，实际效果的设备验收见设备支持。下表其余变种保留为待评审候选。方案正文以“颜色条件解锁”为机制含义，盖布及后续外观不因此变成新规则。

| 候选体系 | 变种及材质方向 | 遮盖与限制的表达 |
| --- | --- | --- |
| 柔性织物 | 首批柔光布盖；候选束口布套，以少量收褶区别 | 完全不透明、贴合瓶形；颜色徽章说明开放条件，达成后自动揭开 |
| 硬质匣罩 | 首批深色薄木匣；候选蓝灰实色磨砂硬罩 | 紧凑贴合的外壳与清楚接缝，小锁扣封闭；只占原瓶槽，不用宽大宝箱形状 |
| 机械护笼 | 首批细框百叶护笼；已见重新锁定时采用通透框架／细栏杆 | 初始关闭的不透明百叶遮住全部液体；已见内容不再遮盖，由护框与门闩表达禁操作 |

刚性外壳使用小挂锁与连接门面／门闩的搭扣，锁体本身表达条件，不另挂徽章；已见重锁时缩小同一锁具并连接底座，保持液体可见。布盖只用缝边颜色徽章。两者是按材料选择的互斥表现，不在同一外壳重复叠加。钥匙条件使用匹配材质和锁孔头形，颜色条件在锁体或布徽章内显示目标色与四份标记；木盒或笼子不强制绑定某一种触发。四点只说明条件数量，不新增逐份累计、消耗或奖励，也不要求手动开门。

普通空栏杆会泄露尚未知的液体，不可直接作为首次遮盖；透明／磨砂材质也不得泄露真实颜色或液量。各体系都遵守“首次未见隐藏、已见重锁保留信息、达成条件自动开放”的同一契约。开放表现结束后让原玻璃成为主体，不保留占空间的盒门／笼架残件；取消、撤销和恢复由既有已提交状态决定，不依赖打开动画回调。

同关优先统一一个遮盖体系，通过条件标记区分瓶组，避免外观种类过多妨碍读题；更多材质变种后续评审。不新增外观商城、玩家设置或正式题库编排。各体系继续核对十五款容器与六列小屏占位，不扩大棋盘、不改 1900 ms 倒水时长或玩家数据。10 月 10 日用户指出第 2、10 款玻璃偏高，已将 moon／flute 瓶口各降低 4 个绘图单位，底部位置不变；其余玻璃保留。

### 容器固定与权限：已确认并独立实现

同一套底座与锁扣按限制对象复用，始终从实际开放状态、已知信息及倒入／倒出权限投影，不能仅凭瓶型、目标名称或 `fixed` 猜测。三种主要状态如下：

| 状态 | 画面 | 实际权限与信息 |
| --- | --- | --- |
| 尚未开放 | 不透明外壳及承载条件的锁具；布盖使用颜色徽章 | 不能倒入或倒出，不显示未见液体 |
| 已见重锁 | 已见液体、固定底座与匹配锁扣；布盖保留颜色徽章 | 两向操作禁止，已知颜色不重新遮盖 |
| 只进不出 | 开放瓶口、固定底座、小锁扣及向内箭头；短标记“只能倒入” | 可作为目标接水，不能作为源瓶倒出；收集颜色／数量或彩虹顺序仍由原题目标说明 |

固定位置与倒水权限独立：仅 `fixed=true` 的容器显示支架和螺钉，不画暗示禁倒出的挂锁，原有源权限继续有效。非机关但两向均禁用的容器显示底座锁扣，不画可倒入箭头。尚未开放或已见重锁优先于永久权限标记，避免同瓶重复画两套锁；机关开放后再显示其本身的永久权限。底座不遮瓶口，不盖住已知液体，位置与锁扣不随接水量移动，不新增解锁条件、领取动作、音效或完成奖励。

独立组件 `src/art/ContainerRestraint.tsx` 提供共用底座及永久权限表现，`containerRestraintState.ts` 提供纯状态投影；机关的已见重锁也复用同一底座。已接入内部十二份收集、六份彩虹层序场景和现有机关样板，标签／点击说明／读屏与真实权限一致。倒水、撤销、重来、提示与保存仍使用现有引擎；没有替换正式题库或向公开经典入口增加玩法。源码实现与设备验收分开，当前证据见[设备支持](device-support.md)。

## 出题与验证

制作关卡时使用共享规则完成求解、独立回放与导出复验。评价重点是关卡的设计质量、思考要求和游玩节奏。

每题先确定要考察的突破，再安排液体、开放组与触发条件，并实际验证阶段依赖和周转空间。

1. **定义整题。** 保存全部布局、初始开放组、初始液体遮盖与份 ID、钥匙位置／标记、触发类型、目标组、规则版本与可重建来源。手工原型保存完整固定定义；生成题必须支持确定性来源重建。
2. **按机关规则求完整解。** 搜索状态包含液体、开放组、触发记录与已显露信息；逐层显色在原隐藏边界停止，提示使用同一规则且不能以隐藏答案指导玩家选择。只把角色、条件和组关系等价的瓶子作对称合并，并将路线映射回真实瓶 ID。
3. **独立回放所有阶段。** 检查每步合法性、液量守恒、触发时机、逐份显色、知识保留、组开放及最终完成；覆盖一个动作可能满足多个条件的情况，同一步满足的多个机关同步开放，不能由动画回调接力解锁。
4. **分析选择与信息。** 比较钥匙／首色顺序的资源差异、准备要求及后续安排；记录逐层显色带来的新线索和计划调整，为质量与难度指标提供证据。
5. **核查展开价值。** 记录新增瓶和液体实际参与的动作、阶段之间的依赖与关键选择；与全部开放版本按同一全盘整理目标对照。
6. **去重与导出复验。** 结构键包含液体、初始遮盖分布、机关类型、标记位置及瓶组关系；相近派生题归为同一家族。SQLite 导出后逐项读回全部定义与完整路线。

制作验证记录实际覆盖和计算预算，完成后方可导出内容；手机不进行每次倒水的全局搜索。

## 难度与内容节奏

带机关或遮色的经典关卡不能直接沿用只按普通整理规则计算的 human-decision-v1 分数，更不能套用记忆双轴分或其等级。首轮记录每阶段达成距离、可行解锁顺序、准备依赖、实际选择后果、新空间使用、后续决策以及操作量，分别判断探索负担与整理负担。

**整体节奏已确认：从前期普通经典排序，随关卡推进逐渐引入变化，后期通过机关和信息探索丰富同一种玩法。** 新能力首次出现时安排简单易懂的教学关，不通过新入口或重新选模式来引入。

具体编排建议为：普通整理 → 单项能力的简单教学 → 同规模的准备与取舍 → 两段连锁／顺序变化 → 经验证的能力组合。先分别验证钥匙、盖布与逐层显色，再评审组合；逐层显色可以单独用于一题，组合规则尚未冻结。普通整理关仍可穿插出现，不要求后期每题叠加机关。每次主要增加一个因素，不同时加颜色、加机关并减少空间；挑战之间安排熟悉、宽松的恢复题。新增阶段必须带来新决策，不能全是机械收尾。

机关等级、步数窗口、正式题量、峰谷阈值与生产规模尚未冻结，须在三种机制分别试玩后确定，不预先承诺固定配方、百题或千题。

步数是当前规则下离线最短路线，不是人类难度评分。第 1／8、2／11、7／10 各是同一家族的能力变体，其他六题分别组织，共九个设计家族；不把十二题称为十二种独立结构创意。精确结构键枚举瓶位排列并规范化颜色，保留遮盖、机关位置／条件与组映射，十二份完整定义无结构重复；不以换色／换皮充数。后半段加强准备、阶段依赖与信息整理，尚不能称为真人校准的偏难等级。

`npm run unlock:verify` 只复验这十二份固定手工内容，不生产候选或计算综合难度分。已穷举 **323,958 个等价正向局面、3,492,934 条合法转移**，覆盖两种首色顺序、两段依赖与同步触发。保持钥匙来源、目标组及规则角色，只合并等角色瓶和同色同公开行为液体，完成时终止扩展。这些是固定内容的技术证据，不代替质量与难度评分。

十二条路线共 130 步，另以独立单位／边界／机关规则逐步回放并核查守恒、同步开放、知识、恢复和完成；离线隔离 SQLite 逐题写入、逐字段读回定义与路线，再完整回放。每题与全部开放版本按同一全盘目标对照，记录解锁阶段与新增瓶的实际参与；阶段结构不另增通关目标。验收内容证据为 `assets/levels/unlock-trial-evidence.json`；完整诊断与隔离数据库在忽略的 `builds/unlock-trial/`。手机不运行穷举或加载这些离线证据。

内部提示沿用现有共享引擎契约。第三步的指标与占比建议见下节；当前固定题验收工具不是质量与难度评价器。实际界面与设备检查另见[设备支持](device-support.md)。

## 第三步：质量与难度指标方案

**状态：离线证据提取、对照报告、D6 自动分档、取舍／阶段／底题自动测量和仅接受自动算法的评分入口已实现。** 最终单题判别不接受人工填分、补分或覆盖；人参与方案制定、算法校准和结果验证。指标、权重与语义档位沿用已认可方案；其余自动分档映射尚未确认，不填默认分。当前工具覆盖十二关、八题阶段对照、六题经典基准配对及同规则、至多八瓶的四份／全盘整理对照题，包含普通排序、钥匙、颜色盖布、逐层显色及组合；不是已验证的全自动质量评价器。

分别输出 **质量 Q（0–100）** 与 **难度 D（0–100）**，各自百分制，不合并成一个总分。Q 衡量设计是否精炼、有意义、清楚和有变化；D 衡量玩家需要投入多少思考、统筹与操作。简单教学题可以质量高、难度低，复杂挑战题也可能质量一般、难度高。

### 首轮人评与评价器缺口

2026 年 10 月 11 日，用户对十二关给出整体体验反馈：解谜过程清楚，也有整理过程，但每个环节周转空间宽松，感觉“怎么玩都可以”，操作机械、缺少挑战与解出题目的自我成就感。用户要求后续内容兼顾有趣、视觉美观与通过思考获得的成就感，并明确需要另一批能体现游戏价值的题目。此为当前十二关的整体人评锚点，不是逐题分数；未提供逐题美观评分，也不扩展为所有玩家的结论。

现有证据与反馈的关系：十二题所有最短路线观察点的非等价合法后继，精确额外成本均为 0 或 1 次倒水，未出现更大绕行成本；部分题存在没有整空瓶的区间，因此不能只用“空瓶数量”解释难度。这个结果支持“选择后果很轻”的诊断，不能单独证明所有玩法都无需思考。逐题原始数据及例子抽查在忽略的 `builds/unlock-rating/feedback-analysis.json`。

**现有评价器存在语义缺口，回归通过不表示它已能识别有趣的题。** Q／D 分开、操作量低权重和证据来源约束继续保留；需要修正的是判断的程序定义、部分统计解释，以及校准题的覆盖。

- 后果类别包含等价局面的自循环及只多一次操作的差别。类别多不代表有值得比较的方案；v1 据类别分支统计出的“最后选择后尾段”在十二题均为零，不能据此声称全程都在作实质判断，或不存在机械收尾。修订时须区分中性搬运、直接进展、可恢复但需要重新安排的选择及跨阶段计划，保留原始动作，不能仅靠删掉坏动作制造有趣。
- “到任一合并／开组／显色的距离”不能代表必要前瞻。需用具体例子说明：玩家为何不能只看当前一步、哪项准备对后面的空间或目标实际必要。机关发生、打开新瓶或出现新颜色本身均不证明有设计价值。
- 设计角色是题目意图，不是验收结论。原先声明为 challenge 的题目尚未证明达到挑战要求；本批作为规则教学与低挑战反例保留，不能继续作为唯一校准题集或正式挑战质量的证明。
- 公平、可恢复与挑战可以并存。保持当前不要求猜隐藏内容、免费撤销／重来的规则；挑战来自可读的取舍、准备和资源统筹，不能把死路数量、惩罚或大幅拖长操作直接当作乐趣分。用户已确认可解性底线为：**从初始局面至少存在一条合法倒水序列能够完成整题**。不要求所有合法倒法或每个后继局面均能不撤销地继续解完；选错允许免费撤销／重来。必经节点与不强迫猜隐藏内容分别验收，不由全知可解路线自动证明。

### 已确认的阶段难度方向

用户确认：钥匙是所有完成解必须经过的阶段节点，但准备倒法可以多种；方法、路线或解法的数量不作为难度目标，也不自动加分或扣分。设计重点是发现取得钥匙所需的准备关系，想通后产生突破感。控制节奏主要控制玩家承担的思考难度，不限制玩家采用哪种合法方法。

钥匙前的准备与解锁后的整理分别设计、分别评价，目标是前后都保有接近经典排序的挑战。突破后可以短暂舒展，但不能只靠大量新空瓶把后段化为机械归色。前后操作数相近不证明难度相近；整体平均分也不能遮盖某一阶段过易。“豁然开朗”与成就感必须经试玩确认。阶段节点的必要性由完整完成图验证，不将“全部机关必须打开”新增为游戏通关规则。

### 新校准题的设计要求

先制作少量可逐题解释的内部对照题，再修订判断识别和评分映射。下列为持续的设计与验收目标；首批八题已接内部体验，正式题库未替换，难度阈值与评分映射仍待试玩校准。

| 对照方向 | 希望体现的有效结构 | 必须保留的低挑战／机械对照 |
| --- | --- | --- |
| 普通整理的空间取舍 | 某个兼容接收位置需要留给后续颜色，玩家能从公开局面理解原因；过早占用后仍可恢复，但需要重新安排 | 同底题增加周转余量后，主要取舍消失；不能仅按空瓶总数给难度 |
| 取得钥匙前的准备 | 清空钥匙瓶需要先安排可解释的中转，取得的新资源随后改变整理计划 | 钥匙顺手取得、开组后只是继续机械归色 |
| 颜色开组的顺序 | 两种可行先后顺序带来不同的空间／液体需求；可以明确解释选择依据 | 两组独立、先开哪组都近乎相同 |
| 阶段之间的联系 | 前段保留的颜色或位置确实服务后段，突破后出现新的、有区别的整理任务 | 几段互不相关的小题串联，或开组只增加更多空瓶 |
| 显色后的推理与安排 | 显色前有公开可推断线索或合理探索选择，显色后需要具体调整，且不依赖猜答案 | 遮色只增加再次点击，揭晓后直接归位 |
| 思考量与操作量的区分 | 较短题中有明确的准备或取舍，解出关键结构后收尾紧凑 | 较长题只有强制动作／重复搬运，不能因步数多而获得思考分 |

各组至少需要能说明预期差异的样题；少数空间紧张并不要求每道都紧张，也不要求每步都分叉。单一行动段可以承载必要准备或教学，不能一律判机械。关键是玩家是否能发现关系、作出安排，并在突破时理解“为什么这样就解开了”。成就感最终需要实际试玩验证，程序只能提供支持或反驳它的结构证据。

美观目前由与题目结构并行的试玩验收验证，不作为人工分数输入评价器：沿用已批准玻璃与大瓶布局，检查机关、目标、未知份是否清楚，画面是否拥挤，展开前后的构图和反馈是否协调。源码图结构不能自动证明美观；清楚也不等于已经美观。新校准题须有实际画面及试玩反馈，不借新增装饰、更多机关或总分补偿缺少核心取舍的挑战题。原有 Q／D 权重暂不改动，修订算法或映射另升方法版本；不根据本次整体反馈编造逐题档位。

### 已确认：经典底题加机关，再复评成题的生成方法

用户完成本批体验后反馈：加入钥匙后，题目总体倾向变简单；开局可操作范围缩小、阶段目标明确，部分探索选择被排除，减少了找方向的负担。用户同时认可这条出题方法合理、题目质量相对较高。这是本批配对的整体主观反馈；上述简化原因是待进一步对照验证的解释，不推广为所有机关必然降难，也不把路线数量减少直接换算成难度下降。

**评价方向已确认：机关数量、约束增多或隐藏内容增多均不自动加难。** 需同时检查机关增加了哪些准备与统筹，又提供了哪些目标线索、排除了哪些原有取舍，按最终成题实际需要的思考量评价。最高难度档尤其不能仅凭经典底题分数或机关数保证挑战；应从更难的经典底题中筛选候选，抵消机关可能带来的简化，再验证成题是否达到目标。需要提高多少底题分数、最高档的最终阈值及映射仍待配对校准，不先规定固定加分或折扣。

已确认的制作闭环为：

1. **先选或生成经典底题。** 独立验证来源、守恒、完整解与经典难度，保留未加机关的定义和评级作对照。
2. **加入阶段节点或隐藏内容。** 按设计目的选择钥匙／盖布／显色位置及映射；准备倒法可以多种，不以固定唯一解为目标。
3. **重新验证最终成题。** 按实际机关、信息与转移规则确认至少一条合法完整解并逐步回放；另外验证指定节点必经、信息公平性及结构去重，预算未知不得当作已通过。
4. **复评质量、难度并试玩筛选。** 分别检查取钥前和开组后的思考负担、突破感、节奏与画面表达，与经典底题对照；达不到目标则调整节点／底题或淘汰，不沿用底题分数、不用步数接近代替思考难度相当。

该闭环是已确认的生成方向；当前六题及离线验收已实践它的一轮，批量候选搜索、自动质量／难度分档和正式题库生产仍未完成。本次记录反馈和方法，不自动生产下一批或替换闭测内容。

### 质量指标与占比建议

质量先声明本题的教学／恢复／挑战角色，再评价是否实现该角色的设计目的。普通关按颜色与空间结构评价，不因没有机关而扣分；教学关不因简单而扣分。

| 指标 | 满分／占比 | 评价题目的哪一方面 |
| --- | ---: | --- |
| Q1 有效决策 | 25 分／25% | 玩家做的判断是否有实际作用，选择之间是否有区别，思考是否围绕本题设计目的 |
| Q2 结构与机制价值 | 25 分／25% | 液体、空间、整理目标与机关是否有效配合，前后步骤是否相互联系 |
| Q3 信息表达与反馈 | 20 分／20% | 条件与关联是否清楚，已知／未知是否易辨，动作结果与新线索是否帮助理解 |
| Q4 节奏与精炼程度 | 20 分／20% | 准备、突破、后续整理及收尾是否自然，有多少机械重复或拖长的动作 |
| Q5 变化与辨识度 | 10 分／10% | 本题是否有清楚的设计特点，与比较题集是否存在有意义的玩法区别 |
| **合计** | **100 分／100%** | **设计质量** |

质量每项先评 0–5 档，再按满分换算。下面各档是设计评价标准，不能将“更复杂”“更多机关”直接当作更高质量。

| 指标 | 0 档 | 1 档 | 2 档 | 3 档 | 4 档 | 5 档 |
| --- | --- | --- | --- | --- | --- | --- |
| Q1 有效决策 | 几乎只有无目的的机械重复 | 仅少数判断有明确作用 | 有有效判断，但夹杂较多无关操作 | 判断作用明确、数量适当 | 主要判断紧扣目标，取舍清楚 | 关键判断精炼且各有作用，充分服务教学／恢复／挑战目的 |
| Q2 结构与机制价值 | 配置松散，关键结构主要是装饰 | 只有少数局部配置发挥作用 | 局部有效，前后联系较弱 | 主体结构与目标配合明确 | 颜色、空间或阶段之间有效呼应 | 关键配置都有明确用途，整体紧凑、联系自然 |
| Q3 信息表达与反馈 | 条件关系和结果难以辨认 | 多处条件或反馈不清楚 | 基本能理解，仍有重要歧义 | 条件与反馈基本清楚 | 关键关联、已知未知和新线索清楚 | 表达简洁准确，玩家能理解动作原因与结果 |
| Q4 节奏与精炼程度 | 全程堆叠同类重复操作 | 主要体验单调，少有变化 | 部分自然，部分明显拖长 | 起步、主体、收尾符合本题角色 | 突破与后续衔接清楚，收尾紧凑 | 思考、操作与舒缓安排精炼，符合本题角色 |
| Q5 变化与辨识度 | 与比较题集结构重复 | 主要只换色或换外观 | 同家族轻微结构变化 | 同家族出现有意义的新取舍 | 有清楚的新结构或有效组合 | 核心想法鲜明，变化有实际玩法价值 |

`Q = 5×Q1档 + 5×Q2档 + 4×Q3档 + 4×Q4档 + 2×Q5档`。

Q5 报告必须注明比较题集与家族，同一题在不同题集中的重复程度可能不同。现有十二题共九家族；同底题的能力变体按实际新增判断评价，不自动称为新创意。图形款式、颜色名称和瓶 ID 的变化不增加设计分。

### 难度指标与占比建议

| 指标 | 满分／占比 | 评价玩家需要承担哪一方面的挑战 |
| --- | ---: | --- |
| D1 前瞻与准备 | 25 分／25% | 为作出当前关键判断，需要提前考虑多远、安排多少有意义的准备 |
| D2 选择辨别 | 25 分／25% | 同时有多少值得考虑的方案，表面相似的选择有多难区分 |
| D3 空间调度 | 15 分／15% | 可用中转空间有多紧，需要多精细地腾挪和保留空位 |
| D4 目标统筹 | 15 分／15% | 同时需要兼顾多少整理／解锁目标，它们怎样竞争资源、形成先后依赖 |
| D5 信息推理与再规划 | 15 分／15% | 需要结合多少已知线索推断、安排探索，并在显色后调整计划 |
| D6 操作量 | 5 分／5% | 完成本题所需的基础倒水数量，作为较低权重的操作负担 |
| **合计** | **100 分／100%** | **挑战程度** |

难度每项同样先评 0–5 档。前瞻计有意义判断所需的准备，不把一串无需选择的机械动作当作深思考；选择辨别计方案宽度与相似性；目标统筹计并行目标和依赖关系，三者分别评价。

| 指标 | 0 档 | 1 档 | 2 档 | 3 档 | 4 档 | 5 档 |
| --- | --- | --- | --- | --- | --- | --- |
| D1 前瞻与准备 | 无需预先安排 | 看当前一步即可判断 | 需要考虑两步配合 | 需要考虑三至四步准备 | 需要考虑五至六步准备 | 需要考虑七步以上的连续准备 |
| D2 选择辨别 | 基本只有一种有意义的选择 | 少数选择，区别直观 | 少数相近方案，需要比较 | 多种合理方案，需要区分用途 | 多种相近方案，涉及不同取舍 | 多种高度相似方案，取舍密集且贯穿关键段 |
| D3 空间调度 | 中转空间始终宽松 | 偶尔需要简单腾挪 | 局部需要安排中转 | 多个关键位置需要保留空位 | 较长关键段持续空间紧张 | 关键段几乎没有余量，需要精细安排 |
| D4 目标统筹 | 目标基本独立 | 简单先后，不争用资源 | 两个目标需协调颜色或空间 | 多个目标存在明确依赖 | 多段依赖并伴有资源竞争 | 多个并行目标与长依赖链交织 |
| D5 信息推理与再规划 | 信息充分，无额外推理 | 显色后可直接处理 | 需要简单库存／位置推断 | 需要组合线索或局部调整计划 | 多轮探索与计划调整相互联系 | 持续比较多种解释，并规划后续探索 |
| D6 操作量 | 最短倒水数 ≤6 | 7–12 次 | 13–18 次 | 19–24 次 | 25–30 次 | ≥31 次 |

`D = 5×D1档 + 5×D2档 + 3×D3档 + 3×D4档 + 3×D5档 + D6档`。

D1–D5 先按关键判断的要求评价，机械收尾不稀释思考项，也不能通过刻意绕路抬高难度。只有一个短峰值与多个持续难点的区别在解释中注明；具体取点与聚合方法在指标确认后的算法设计中规定。D5 根据推理和计划调整的要求评分，隐藏层数量与反复点击不直接加信息分。没有遮色时该项可为 0，各指标维持固定满分，不重新分配权重。

D6 使用共享规则验证的最短倒水数，避免人为加长参考解法。动画时长、设备快慢、搜索耗时不计分。辅助符号、玻璃款式与屏幕尺寸的可读性另外做设备检查。上述 D 与现有千关 `human-decision-v1` 使用不同指标和口径，不能直接套用旧 D1–D4 分档或改写当前千关评级。

### 程序化表征：已实现证据，待校准评分映射

下表保留指标的解释和待确认映射；首版实际算法、观察覆盖与输出范围见下文。前述权重与语义档位保持不变。同一定义、角色、比较题集、方法版本和预算产生可复算的结果；程序确定性不证明质量含义或玩家难度已经校准。

每个指标均分三层：**原始事实 → 可检验的解释 → 0–5 档映射**。报告保存事实数值、局面／动作例子、映射规则、来源和版本。尚未确定映射时只输出证据与待评状态，不填默认 3 档，也不把缺项权重分给其他指标；分项未齐时不输出完整 Q／D 总分。

#### 质量如何落到数据

| 指标 | 建议计算的表征与操作 | 不能直接据此下的结论／待确认处 |
| --- | --- | --- |
| Q1 有效决策 | 对观察局面的合法后继去除等价瓶位动作，分别记录后续操作成本、机关可达顺序、可用中转位置及新信息；把这些后果相同的动作归为一类。报告不同后果类别、判断在各阶段的分布，并用具体动作展示取舍。设计目的另外声明为可检查事件，如首次取钥、选择开组顺序、显色后腾挪 | 合法动作多不等于有效判断多，成本不同也不自动说明有趣。类别如何划分、什么判断服务教学／恢复／挑战，以及适量判断对应哪一档，须先用对照题固定 |
| Q2 结构与机制价值 | 建立“条件 → 开放资源 → 后续使用／目标”的关系图。逐项比较原题与去掉该限制的版本：开组时机、资源使用、不同方案和后续准备怎样改变；普通题对颜色分布与中转结构作对应比较。记录配置的实际作用及前后联系 | 新瓶在某条路线被用过只证明参与，不证明设计价值；多出步数也不证明好。教学机关可因清楚展示规则有价值，不能要求每个配置都增加挑战 |
| Q3 信息表达与反馈 | 规则层核对触发条件、对应瓶组、公开／隐藏状态与动作事件是否一致；表现层核对条件与目标关联是否可见、显色是否对应事件、已见重锁是否区分。每项保存检查结果及画面／交互证据 | 规则数据正确不等于玩家看得懂。当前只自动核对规则事实；须补可计算的布局、条件关联和事件反馈检查，尚不能只读关卡定义就自动给完整 Q3 档。人工体验验证模型，不提供单题分数 |
| Q4 节奏与精炼程度 | 按开组、显色、颜色整理完成标记阶段，记录准备长度、不同后果的判断分布、连续只有一种非等价行动的长度，以及最后一次实质判断后的收尾长度。不同路线分别统计，输出范围 | 单一行动段可能是必要演示或舒缓；最长段短也不一定节奏好。需按教学／恢复／挑战规定适宜范围，再映射分档，不能一律扣机械操作分 |
| Q5 变化与辨识度 | 先对完整结构精确去重，再按底题结构、条件／资源依赖、信息边界和关键选择特征比较家族；列出最近邻题及实际差异。绑定比较题集的内容哈希 | 结构不同不等于新颖，结构距离大也不等于质量高。程序可先提供重复、近似及差异证据；“有意义的新取舍”的自动特征与分档仍需对照验证；人工核对用于改进统一算法，不参与单题评分 |

Q1 评价判断的作用与精炼，D2 评价辨别这些选择的负担。Q2 评价配置之间是否配合，D4 评价协调它们有多费力。两边可以使用同一份事实，但必须使用不同评分解释，不能将一份复杂度特征同时当作高质量和高难度。

#### 难度的计算边界

| 指标 | 第一版建议表征 | 当前确定程度 |
| --- | --- | --- |
| D1 前瞻与准备 | 在关键判断处记录到下一次合并／取钥／开组的最短准备段；另测试只观察 1、2、3–4、5–6、7 步时能否区分候选方案，保存需要进一步观察的实例。机械单一路径单独标记 | 准备段长度可计算，但不等于玩家必须前瞻的长度；“观察到什么才足以区分”与取点方法仍须明确，不能直接照搬最短准备步数为档位 |
| D2 选择辨别 | 使用 Q1 后果类别；用玩家当时可见的颜色、空间、条件与线索描述候选动作，报告表面相近而实际后果不同的方案数量、差异及出现位置 | “表面相近”的特征和距离阈值需要对照题确认。不同方案多只能作为宽度证据，不能单独定档 |
| D3 空间调度 | 按局面记录当前已开放且具接收权限的容量、整空瓶数和各顶色真正兼容的接收余量；记录紧张区间持续长度及需要腾挪的实例。锁住或颜色不兼容的空格不计可用余量 | 原始量可直接实现；余量多少算紧张、怎样跨不同规模比较及映射到各档，尚待确认。不能只算总空格 |
| D4 目标统筹 | 记录颜色整理、开组及资源需求的依赖图；区别瓶内已有钥匙造成的确定先后，与必须经过动作图验证的动态依赖；列出同时争用接收位置／指定颜色的目标及实例 | 依赖链可验证，资源竞争需要明确判据；不能仅按机关个数或链长给分，也不新增开完机关的通关目标 |
| D5 信息推理与再规划 | 只使用当时可见的信息和公开库存规则，记录可推断出的颜色／位置、新显色后候选计划的变化及探索之间的联系；同底题公开版作对照 | 隐藏数量与显色次数不能替代此指标；知道完整答案的最短路线不能证明需要推理。当前先输出公开线索与显色轨迹；公开信息推理／再规划的自动模型待实现并以样题验证，不接受人工分档 |
| D6 操作量 | 已验证最短倒水数 N，直接按前表区间换为 0–5 档 | 数据与映射已明确，可直接实现 |

首版在起点及每个开组／显色／合并／完整颜色形成后的局面取证；结构统计覆盖所有并列最短路线经过的等价局面，另计算最多额外两步完成的路线集合。所有观察均计算全部非等价合法后继，包含偏离这些路线的动作；汇总全量分布，逐题每组保留最多十二个完整候选例子。此范围不是所有真人玩法。信息线索使用独立的公开投影，完整答案成本不作为玩家已知信息。

同时报告峰值、分布和持续区间；取哪些值映射为档位尚须对照题确认。搜索预算不足的证据标为 unknown，不由状态数量或耗时推导高分。第一版范围限本十二关和同规则的对照题，不声称已支持通用容量、收集或层序目标的完整评级。

#### 一致性如何验证与首版交付建议

1. 固定输入：关卡内容哈希、规则版本、角色与可检查设计目的、比较题集哈希；角色由编排声明，不由评分器为了高分自动选择。
2. 固定解释：每个原始字段有单位、等价合并规则、观察范围、聚合方式和分档表。改阈值或取样算法也升级方法版本，保留改动理由。
3. 对照验证：换颜色名、换瓶 ID 或等价重排不变；换外观不变；重复题不能借改名提高 Q5；增加单纯操作不得自动抬高其他思考项；新加机关须展示改变了什么。
4. 路线验证：并列最短路线不能因枚举顺序得出不同分数；报告保留分布和可回放例子。规则测试与评价测试分开，评价测试使用事先确认的对照预期。

### 已确认并实现：自动取舍、阶段与经典对照

用户已确认先实现自动测量和对照报告，再校准分档。`consequence-stage-v1` 完全由固定算法计算，不接收逐题人工分数；本轮没有修改 Q／D 权重或补出未校准总分。

- **后果取舍：**每个局面按不同后继去重，回到同一等价状态的搬运标为中性。分别统计精确剩余成本不同／死路风险、可解后继的兼容资源分配不同、沿可完成路线取得指定节点的最短准备距离不同。两个以上非中性后继且存在上述差异，标为后果不同的选择局面；另统计多个最优成本后继仍有资源／节点差异的计划选择。两者分开，不把绕路或陷阱多当作质量高。兼容资源按颜色和未完成源瓶分组，不将已完成整瓶的闲置容量算作待整理源需求；它描述资源变化，尚不证明某个空位为后续必需。
- **阶段与节奏：**覆盖全部最短和最多 N+2 步完成路线。每个钥匙／盖布单独检查是否必经，并以实际触发划分前后；触发动作计入前段，同步触发不强排顺序。分别输出动作数、取舍数、等成本计划选择数、无整空接收瓶动作数及其独立最小／最大值，整题另输出取舍动作比例、连续峰值与最后一次后果取舍后的尾段。保留每个实际经过步数的局面分布，不只按最早到达深度取样，不按解法条数加权。各项极值可能来自不同路线，不能拼成一条虚构体验；尾段只相对于本算法定义，不宣称真人无需思考。
- **节点突破证据：**输出各开组边的最早触发位置、后续最短整理长度、空接收瓶、开放接收总容量与实际空格的变化及各源兼容余量；容量不重复累加多个源共用的接收位置，保留至多十二个合法动作实例。准备距离只统计最终仍能完成的分支。资源释放是“豁然开朗”的候选结构证据，不自动证明真实突破感。
- **有限前瞻：**`public-progress-v1` 固定依次优先完整颜色数、较少颜色段数、较多整空接收瓶；逐步检查 1–7 次倒水，找出其全部并列最佳动作均具有最优实际后续成本的首个深度。所有非中性候选本来都最优时记 0。策略选动作不读取精确解成本，精确成本只用于事后审计。仅当前全部瓶内容可见时适用；隐藏局面 unavailable，七步内未区分为 unresolved，均不换成高分。此值是一个固定策略的辨别能力，不是已证明的人类必需前瞻。报告分别保留全局与取舍局面的分布、峰值，避免容易的收尾稀释关键判断；可见性覆盖不完整时不输出前瞻差值。
- **统一对照：**最终题、经典底题、全部开放、全部显色和逐个机关消融都运行同一测量。比较保留原定义和对照定义哈希；真正经典配对按规范底题结构自动识别并绑定双方证据哈希，不按家族名或旧经典分数配对。输出原题减对照的各项差值和区间端点差值，允许变化方向相反；不据单一差值判更难／更好，不继承经典分，不加机关奖励。

`report.md` 提供取舍、阶段和经典对照表；逐题 JSON 保留最短／N+2 曲线、节点分段、峰值／持续区间、前瞻适用状态、完整候选动作与消融差值；`summary.json` 包含测量摘要及真正经典配对。它们是离线制作证据，不进入手机、正式题库或玩家保存。

### 权重理由与讨论顺序

质量的 50% 放在有效决策与结构作用上，40% 放在表达和节奏上，10% 用于变化，鼓励精炼、清楚、有想法的设计。难度的 50% 放在前瞻与选择，45% 放在空间、统筹和信息，操作量仅占 5%，避免长操作成为高难的主要来源。

质量与难度独立解读。例如 `Q=85、D=25` 可以是优秀的轻松题，`Q=85、D=75` 可以是优秀挑战题；这些数字只是解释组合含义，不是对现有十二题的实评分。两套分值都须保留分项与得分理由，不能仅凭总数说明题目。

当前指标与权重已认可，最终判别全自动，按 **程序化表征与对照预期 → 证据提取 → 自动分档映射验证 → 自动汇总评分** 推进。先用同一张表核对十二题，尤其核对同步数不同思考量、同规模不同结构、普通与机关题的区别。实际试玩用于校验标准，不能在未声明的情况下改权重迎合结果。改指标、权重或算法口径须升级方法版本；人工反馈独立记录，只用于验证和改进统一算法，不进入单题计算。

评价器现读取离线固定关卡定义并独立计算证据，输出分项、D6、未实现／未知／阻断项目、得分理由和方法版本；全部分项由自动算法完成后才汇总 Q／D。其余自动映射与试玩验证待推进，不改手机功能、既有千关、副关或玩家数据。
