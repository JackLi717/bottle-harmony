# 经典排序关卡扩展规划：钥匙、盖布与逐层显色

更新日期：2026 年 10 月 10 日。用户确认经典排序本身随关卡推进逐步加入变化：前期普通整理，后续逐渐出现钥匙、盖布和逐层显色，与颜色记忆保持两种玩法的区分。三种能力的核心规则已确认，共享引擎与内部验收场景已实现；正式机关题库生产与现有千关更新尚未安排。本文沿用原文件路径，是经典排序这些关卡能力的唯一方案正文；关联创意 51、71、73、75、76、79、80，编号继续保留在[创意清单](gameplay-ideas.md#通过整理逐步解锁棋盘)。

## 开发目标与范围

让玩家通过整理液体达成阶段目标，打开新的瓶子或瓶组，或显露本瓶原先被遮盖的颜色，再利用新增的液体、空间或信息解开后续任务。一关内形成“准备 → 突破 → 新局面 → 再突破 → 完成”的过程，前后阶段共享同一个持续变化的棋盘。

本轮规划包含三种能力：底部钥匙分组展开、完成对应颜色揭开盖布、移走上层后逐层显露本瓶颜色。前两种开放瓶子操作权限，第三种只显露自身液体信息，不打开其他瓶组。未开放的瓶子可以装有液体，不限于空瓶。“完成任意颜色打开空瓶”的创意 72 保留为独立候选，不作为共同限制。

**产品定位已确认：经典排序是一种连续推进的玩法，普通整理和带机关／遮色的关卡共用经典入口、关卡流程与进度。** 不设“揭秘模式”、经典内子模式入口或另一套揭秘关号、进度、钱包。玩家从简单整理逐步进入带有新变化的关卡；“钥匙、盖布、逐层显色”是关卡能力，名称仅用于设计和必要教学，不据此拆分产品玩法。

现有公开千关、副关、记忆百题和内部调色是当前实现；本次决定规划经典后续的逐步扩展；用户进一步明确引擎升级后现有经典排序保持原规则与体验，不要求把新能力强行加入当前千关。未来人工精选内容的组织与付费仍属[设想](gameplay-ideas.md#精选设计关卡与体验门槛设想)，不立即替换闭测中的题目。具体首次出现关号、频率和内容版本待出题与试玩后确定。题内展开的“区域”指瓶组，与[主页四区域候选](gameplay-ideas.md#四个游戏区域题库规模与提示资源讨论方向)无关。首轮不叠加记忆万能块、凝固、配方杯、变色、变容量或新的商业门槛。

## 三种展开方式

| 方式 | 阶段目标 | 开放结果 | 主要决策 |
| --- | --- | --- | --- |
| 底部钥匙 | 清空钥匙所在整瓶，取得钥匙 | 自动打开固定关联的一瓶或一组瓶子，可继续连锁 | 怎样移走覆盖液体、安排中转并取得下一把钥匙 |
| 颜色盖布 | 任意一瓶装满四份指定同色 | 自动揭开固定关联的一瓶或一组瓶子 | 优先完成哪种颜色，先取得哪组液体与空间 |
| 逐层显色 | 移走遮盖在未知色块上方的液体，使其成为顶层 | 只显露该份液体的真实颜色，不打开其他瓶子 | 先探索哪只瓶子，怎样为新显露颜色安排空间 |

### 底部钥匙：分阶段探索

用户给出的代表结构是十二瓶按 **6 + 3 + 3** 展开：开局六瓶可操作，第一把钥匙开放三瓶，第二把钥匙再开放三瓶。六瓶包含本阶段实际需要的周转空间，不表示六瓶全部装满。第二把钥匙可以在后续瓶组中，以形成阶段依赖；具体位置由出题与完整验证决定。

钥匙与目标瓶组的对应关系固定、可辨认。新瓶组预先属于整题，可以带来新液体和新空间，不在解锁时随机生成。新阶段要用到前阶段整理的成果，避免仅把几道互不相关的普通题串起来。

**已确认：清空整瓶取得钥匙。** 钥匙横放在初始底层液体内部偏下，按真实瓶腔底部形状固定位置，呈沉底状态；随瓶子整体倾斜，不在瓶内滑动，也不随液体流走。最后一份倒出时仍留在瓶底；整瓶清空后自动触发，钥匙原位淡出，打开题目预先关联的一瓶或一组瓶子。露出底部液体、移动某个标记液体或将其送到指定位置均不是本轮触发规则。

钥匙是机关触发标记，不占液体容量，不作为背包资源或消耗道具。十二瓶、每次三瓶是用户举例，不是每题固定配额。

### 颜色盖布：目标与顺序选择

用户给出的形态是四瓶、八瓶或十二瓶的整题布局，其中部分瓶子盖布，例如旁边四瓶暂不可用。盖布上的颜色及辅助符号说明开放条件：形成一整瓶对应颜色后，揭开关联瓶子或瓶组。

同一颜色可关联一瓶或一组；具体映射写入题目，不默认四瓶必须一起打开。若有红、蓝两组条件，须验证各可达解锁顺序的后续；若某条分支陷入死局，应修正题目设计，不能将其作为机关玩法的必需代价。解锁顺序的价值来自两组所提供资源的差别，不能只换颜色制造表面变化。

**已确认：“完成颜色”指任意一只普通瓶装满四份指定同色。** 不要求放入指定瓶位，也不消耗这瓶液体。之后仍可正常倒水。指定瓶位、多条件合取等变体留待单独评审。

### 逐层显色：只显露自身颜色

**已确认能力：部分下层色块被遮盖，只有其上方液体移走、该色块露到顶部时，才自动显示真实颜色。** 每份液体与真实颜色在出题时固定，不在显露时随机生成。可以连续遮盖多层，随整理逐层显露；不要求开局全部下层都隐藏。

例如从顶到底为“红、未知、未知、蓝”，先移走红色，紧接着的一份未知色块显色；更深一份仍被上层覆盖，继续保持未知。此能力可以单独形成整理题，不需要钥匙或锁瓶。

规划沿用普通颜色匹配与四份容量。遮盖只影响信息，不将液体变成能匹配任意颜色的万能块；它没有记忆模式的开局观察／准备阶段，也不等到全盘外观完成才揭晓。初始可操作瓶的顶层应可见；盖布瓶先按瓶组开放规则处理，再判断其顶层信息。

**已确认的知识规则：**已显露的颜色沿用本规划已确认的信息保留原则，后续被液体覆盖或撤销也不重新隐藏；重来恢复原题初始遮盖。知识按稳定液体份 ID 保存，不能仅按瓶位或层号记录。

**已确认的倒水边界：** 只倒当前已知的连续同色段，下方未知块即使真实同色，本次也在原隐藏边界停止；动作提交后新顶层显色，玩家再次点击继续。游戏、求解、回放和教学必须采用同一边界。

## 已确认规则与实施约束

用户已确认触发、固定映射、隐藏信息、撤销、自动开放、题目质量责任与整题目标。下表同时记录配套的守恒、保存和验证约束；原型提示与商业权益仍明确保留为建议／待定。

| 项目 | 当前规则／约束 |
| --- | --- |
| 液体规则 | 沿用顶部连续同色、目标匹配、每瓶四份等容量；整题每色四份，含未开放组一起守恒 |
| 内容固定 | 所有瓶子、液体、初始遮盖份、钥匙、盖布颜色与组映射在离线制作时确定，瓶子及液体份具有稳定 ID |
| 未开放组 | 开局显示最终位置、数量、锁／盖布与解锁条件，不能倒入或倒出，看不见尚未公开的液体；各瓶原位展开 |
| 自动开放 | 达成条件立即自动打开，无领取操作；同一步满足多个机关时同步开放全部符合条件的目标，点击锁／盖布只查看说明 |
| 解锁提交 | 合法倒水后统一判定机关，液体与机关状态一并提交和保存，再播放开锁／揭布；动画不授予进度 |
| 解锁持续 | 触发后保持开放；再从完成色瓶倒水不自动关门，同一触发不重复播放或累计奖励 |
| 整题完成 | 整理好整题全部液体：包括未开放瓶在内，每只非空瓶均满四份且单色，空瓶允许保留；不额外要求取得全部钥匙或打开全部瓶组。仅可见组整理完成不能代替整题判定 |
| 撤销 | 免费回退液体与机关；撤销触发动作时恢复之前的开放状态，不受锁瓶禁倒限制 |
| 重来 | 恢复整题固定布局、初始开放组与机关；不重复授予首次完成记录 |
| 恢复 | 返回、后台和冷启动恢复液体、开放状态、触发记录与有界撤销历史，不补播机关表现 |
| 提示与权益 | 正式关卡接入经典既有的一步提示、撤销／重来与首次完成奖励流程，不另建机关钱包或额外奖励；具体关卡编排与既有商业资格的适用关系随正式内容方案明确。内部原型不扣经典提示券、不发奖励、不推进经典进度 |

**已确认撤销后的信息规则：** 撤销触发动作时重新锁住瓶组，已看过的液体保持可见，显示锁定标记且禁止操作，不重新用不透明盖布遮住。液体按动作历史回退，已知信息按同一尝试保留并保存；重来恢复开局布局与初始遮盖。这样撤销不会制造重复记忆负担。

保持十五款免费玻璃、同局统一款式、现有轻点倒水、两排且每排至多六瓶的大瓶布局。总瓶数包括未开放瓶，最多十二瓶，逻辑色最多十一种；颜色数和总空容量须另行校验，不由“6 + 3 + 3”推导。未开放瓶从开局保留最终位置，开锁时原位展开，不缩小已有瓶子；具体盖布占位表现需小屏验证。移动美术仍允许横向越界裁切。

当前目标、条件与组映射应有视觉线索和本地化读屏说明，颜色条件同时支持符号；点击锁／盖布可查看一行说明；逐层显色的未知标记不能泄露真实色或对应辅助符号，须与记忆万能块在表现和说明上可区分。可以隐藏后续内容，不能要求玩家猜未提示的规则。首轮不增加倒计时、失败惩罚、付费钥匙或独立音效设置。

## 静态外观：已确认基准与候选变种

用户已确认第一套概念方向作为待实现内容：保留现有冷色玻璃与鲜明液体，蓝灰柔光织物配低饱和金属机关与清楚的条件标记。布盖不透明、贴合容器、三至五道主要褶皱、收窄下摆；正面小色标与四个固定点表示四份同色条件，辅助符号沿用现有设置。瓶底钥匙是不占容量的机关标记，位置适配实际瓶腔，不放在玻璃外、瓶身标签处或高脚杯杯脚里；钥匙与对应锁孔同时以材质和形状配对：青铜圆头、不锈钢菱形头、红铜六角头。青铜使用青绿铜锈、不锈钢使用银灰、红铜使用红棕，避免黄铜与红铜过近；钥匙相对首版放大，按底层空间适配，并以细暗边与高光提高小屏可读性。三组以上保留显式编号，不能只靠复用颜色区分。布盖使用表示目标液体颜色的缝边徽章及四点条件，不画锁孔或锁扣；木匣、百叶、卷帘只显示承载条件的锁具，不再叠加圆形徽章。钥匙条件以锁体材质和锁孔头形配对；颜色条件将目标色、辅助符号和四点直接嵌在锁体上。钥匙机关使用刚性外壳，不把颜色徽章错误配到清空瓶条件。逐层未知份采用统一蓝灰与小问号，避免与记忆黑色万能块混淆；撤销后已见液体仍显示，只增加锁定标记。用户已授权按下述顺序实施；四个外壳家族、共用标记和显色表现已接入内部验收页面。正式机关题库与公开入口尚未交付，设备结论单独记录。

用户已确认柔光布盖、深色薄木匣和百叶护笼的效果稿作为第一版待实现基准。首套[静态基准](../assets/art-direction/unlock/static-baseline-v1.png)与三体系[效果稿](../assets/art-direction/unlock/cover-families-v1.png)保留在 assets/art-direction/unlock/，生成提示词见同目录 prompts.json。效果稿按初次锁定／展开过程／已见重锁展示材质与结构；视觉方向已批准，实际外壳、动画与棋盘适配已有源码实现；原图仍为对照基准，实际效果的设备验收见设备支持。下表其余变种保留为待评审候选。方案正文以“颜色条件解锁”为机制含义，盖布及后续外观不因此变成新规则。

| 候选体系 | 变种及材质方向 | 遮盖与限制的表达 |
| --- | --- | --- |
| 柔性织物 | 首批柔光布盖；候选束口布套，以少量收褶区别 | 完全不透明、贴合瓶形；颜色徽章说明开放条件，达成后自动揭开 |
| 硬质匣罩 | 首批深色薄木匣；候选蓝灰实色磨砂硬罩 | 紧凑贴合的外壳与清楚接缝，小锁扣封闭；只占原瓶槽，不用宽大宝箱形状 |
| 机械护笼 | 首批细框百叶护笼；已见重新锁定时采用通透框架／细栏杆 | 初始关闭的不透明百叶遮住全部液体；已见内容不再遮盖，由护框与门闩表达禁操作 |

刚性外壳使用小挂锁与连接门面／门闩的搭扣，锁体本身表达条件，不另挂徽章；已见重锁时缩小同一锁具并连接底座，保持液体可见。布盖只用缝边颜色徽章。两者是按材料选择的互斥表现，不在同一外壳重复叠加。钥匙条件使用匹配材质和锁孔头形，颜色条件在锁体或布徽章内显示目标色与四份标记；木盒或笼子不强制绑定某一种触发。四点只说明条件数量，不新增逐份累计、消耗或奖励，也不要求手动开门。

普通空栏杆会泄露尚未知的液体，不可直接作为首次遮盖；透明／磨砂材质也不得泄露真实颜色或液量。各体系都遵守“首次未见隐藏、已见重锁保留信息、达成条件自动开放”的同一契约。开放表现结束后让原玻璃成为主体，不保留占空间的盒门／笼架残件；取消、撤销和恢复由既有已提交状态决定，不依赖打开动画回调。

同关优先统一一个遮盖体系，通过条件标记区分瓶组，避免外观种类过多妨碍读题；更多材质变种后续评审。不新增外观商城、玩家设置或正式题库编排。各体系继续核对十五款容器与六列小屏占位，不扩大棋盘、不改 1900 ms 倒水时长或玩家数据。10 月 10 日用户指出第 2、10 款玻璃偏高，已将 moon／flute 瓶口各降低 4 个绘图单位，底部位置不变；其余玻璃保留。

三份效果稿分别为[联格薄木匣](../assets/art-direction/unlock/grouped/wood-linked-v1.png)、[卷帘木盒](../assets/art-direction/unlock/grouped/wood-roller-v1.png)、[联体百叶护栏](../assets/art-direction/unlock/grouped/metal-louver-v1.png)，每张按双瓶／三瓶与关闭／展开过程作四格对照；提示词与来源见同目录 prompts.json。图中以同一把钥匙为共同条件示例，具体外壳也可表达既有颜色条件；没有增加钥匙需求。材质与结构作为实现参考，瓶子尺寸、槽距及回收结构仍须在真实棋盘校准。组合共享一个条件，不暗示每瓶分别取得钥匙、逐扇手动开启或额外付费。分格负责显示瓶数与最终位置，组锁具负责解释一并开放的关系；所有达成目标仍由原引擎原子提交，表现不接力授予权限。

联体外壳只用于实际布局中同排相邻、锁定与信息状态适合共同遮盖的瓶槽，跨排或不相邻目标用独立外壳与相同组标记联系，不改变底层一瓶／一组的任意固定映射，不为凑盒重排、移动或缩小瓶子。分格从开局可数，不泄露液量；门、卷帘和顶轴只能在原有槽位覆盖范围内表现，不能扩大两排间距或遮住其他瓶。撤销后已见内容保持可见；局部知识状态不一致时按瓶／份显示所知内容，不用整组不透明外壳遮掉已知信息。开放结束撤掉外壳，继续使用原棋盘；组合外观不扩大正式内容、布局、交互或存档范围。

已实现的时间线在可见出水完成后、原回位阶段启动：外壳展开 440 ms，逐层显色 160 ms，均在原 1900 ms 倒水内完成，不加手动领取或额外等待。同一步目标同步表现；逻辑先提交，动画不授予权限。返回、后台、撤销、重来、窗口变化与新动作使旧表现失效，减少动态效果直接落终态；恢复不补播。已见重锁只显示固定件／通透护框，继续显示已知液体。

运行美术采用可编辑 SVG 路径、渐变与固定纹理，配合 UI 线程平移、缩放、裁切和透明度；没有实时布料／逐叶物理模拟。源码为 src/art/UnlockCover.tsx、ProgressiveReveal.tsx 与 unlockPresentation.ts。联格木匣门片围绕两侧收拢，卷帘进入顶轴，刚性百叶向上叠收，蓝灰布盖收拢提起。关闭门板向边框内重叠，首次未见的玻璃不绘出高光，避免第 8／12／13 款宽口杯的边缘漏光；展开在出水结束后显示原玻璃。原概念 PNG 不作为运行整图贴图，也未被改写。

内部页面提供四个外观家族、一／二／三瓶样板、三组钥匙配对样板、十五款容器切换以及默认折叠的测量工具，不保存外观选择、不写玩家进度。cloth 多瓶仍是多个独立布盖，选择布盖时使用颜色条件样板，钥匙条件自动使用刚性外壳；跨排／不相邻／不同条件／不同知识状态回退独立外壳。默认固定八动作短验收使用相同十二瓶布局和钥匙／颜色条件；执行中禁手动倒水与提示，可随时取消。旧大规模测量入口只保留诊断能力，不自动运行。

验收分四道：① 原图并排核对关闭、展开中段、完全开放、已见重锁与取消终态；② 静态布局覆盖十五款容器、4–12 瓶、最小窗口及六列边缘，组合额外覆盖双／三格和跨排独立壳回退；③ 同一引擎事件下验证钥匙／颜色、同步打开、知识、撤销／重来、后台取消、减弱动画和恢复，检查表现不改内容、钱包或存档；④ Release 真机按固定动作做短对照，同时检查闪烁与实际呈现间隔。

本轮性能固定八个动作做原表现／新增表现两组、最多 16 次倒水，保持相同包／设备／场景／镜像与采集策略；不录屏计时、不在倒水中轮询。完成即停；位置异常、闪烁、内容泄露、采集不完整或进程改变立即停止，未找到有效改善／成本解释不自动反复重测。视觉逐帧检查另做短录屏，不混入计时。其他款仅在引入新绘制技术或异常时追加事前声明的小样本，不恢复大规模重复压力测试。既有 p95 ≤33.3 ms／p99 ≤50 ms 目标和未达标事实保留；短对照用于识别新增成本，功能／外观通过不等于全局性能或上线验收通过，验收证据仍归[设备支持](device-support.md)。

## 出题与验证

**题目质量责任已确认：如果陷入错误或死局，按题目设计缺陷处理，不归因于机关玩法错误。** 应修正布局、机关依赖或组配置，不用改动已确认的触发规则、强制解锁或临时补瓶掩盖问题。出题验收须检查可达分支及后续，不以只有一条完整解为充分证据。

每题先确定要考察的突破，再安排液体、开放组与触发条件。颜色盖布必须能在开放对应组之前取得该完成色；钥匙不能只存在于它自身打开的组内。阶段依赖和初始周转空间必须实际求解验证，不能靠普通布局有解推断机关题有解。

1. **定义整题。** 保存全部布局、初始开放组、初始液体遮盖与份 ID、钥匙位置／标记、触发类型、目标组、规则版本与可重建来源。手工原型保存完整固定定义；生成题必须支持确定性来源重建。
2. **按机关规则求完整解。** 搜索状态包含液体、开放组、触发记录与已显露信息；逐层显色在原隐藏边界停止，提示使用同一规则且不能以隐藏答案指导玩家选择。只把角色、条件和组关系等价的瓶子作对称合并，并将路线映射回真实瓶 ID。
3. **独立回放所有阶段。** 检查每步合法性、液量守恒、触发时机、逐份显色、知识保留、组开放及最终完成；覆盖一个动作可能满足多个条件的情况，同一步满足的多个机关同步开放，不能由动画回调接力解锁。
4. **检查可达分支、顺序与信息公平性。** 比较可达钥匙／首色及其完整后续，检查机关循环依赖和解锁后的阻塞。发现死局的题目退回修改；不能把选错解锁顺序或猜错隐藏颜色作为玩法要求。逐层显色题也须验证仅依已公开颜色能合理探索，不以一条提前知道所有隐藏颜色的路线当作公平性证明。具体验证工具须报告覆盖范围与未知分支，不能用一条全知解法替代分支质量检查。
5. **核查展开价值。** 记录新增瓶和液体实际参与的动作、阶段之间的依赖与关键选择；与全部开放的版本对照。对照研究按同一个全盘液体完成目标检查可达性；未打开本身不是未完成，不能以缺少开锁记录代替新增液体／空间实际参与的证据。
6. **去重与导出复验。** 结构键包含液体、初始遮盖分布、机关类型、标记位置及瓶组关系；换瓶位、换颜色或换盖布外观不能直接算新题。相近派生题归为同一家族。SQLite 导出后逐项读回全部定义与完整路线。

搜索超预算、取消或尚未完成统一记为未知，不视为高难、无解或已验证。必需可解证明未知的候选不进入正式题库；用于选题的顺序后果证据也须明确其已知范围。不进行每次倒水的全局搜索。

## 难度与内容节奏

带机关或遮色的经典关卡不能直接沿用只按普通整理规则计算的 human-decision-v1 分数，更不能套用记忆双轴分或其等级。首轮记录每阶段达成距离、可行解锁顺序、准备依赖、实际选择后果、新空间使用、后续决策以及操作量，分别判断探索负担与整理负担。

**整体节奏已确认：从前期普通经典排序，随关卡推进逐渐引入变化，后期通过机关和信息探索丰富同一种玩法。** 新能力首次出现时安排简单易懂的教学关，不通过新入口或重新选模式来引入。

具体编排建议为：普通整理 → 单项能力的简单教学 → 同规模的准备与取舍 → 两段连锁／顺序变化 → 经验证的能力组合。先分别验证钥匙、盖布与逐层显色，再评审组合；逐层显色可以单独用于一题，组合规则尚未冻结。普通整理关仍可穿插出现，不要求后期每题叠加机关。每次主要增加一个因素，不同时加颜色、加机关并减少空间；挑战之间安排熟悉、宽松的恢复题。新增阶段必须带来新决策，不能全是机械收尾。

机关等级、步数窗口、正式题量、峰谷阈值与生产规模尚未冻结，须在三种机制分别试玩后确定，不预先承诺固定配方、百题或千题。

## 当前实现与验收边界

共享底层已实现三种能力，职责、实际接口、搜索／保存契约及阶段状态见[系统架构](system-design.md#可扩展排序引擎)。`engineExamples.ts` 的钥匙、盖布、逐层显色、十二份收集和层序五题仅为固定技术场景，其中后三类也验证通用容器／目标，不能称为五道正式经典机关题。

内部“排序引擎验收”页面展示锁瓶、已见信息、解锁条件、变容量、目标与原有倒水；不写库、不扣券、不授奖、不推进主线。纯会话和 SQLite 适配的恢复通过自动测试；经典千关与五十副关路线保持原行为。原型全知解已经完整回放；同步触发、显色边界、撤销／重来、错误输入及存储中断分别测试。除用户随后批准的 moon／flute 瓶口微调外，其余四份玻璃保持。新增外观的实际设备交互、持续性能和正式内容的全部分支／信息公平验收仍须完成，不以桌面或浏览器通过代替。

正式关卡仍采用本规划的四份／全盘整理目标；通用引擎的五／六／十二份容量、局部收集和层序目标是另外可配置的基础能力，不暗中改变当前经典题的完成条件。未来正式机关题须接入经典既有内容、顺序进度、提示和奖励适配，不新增玩家模式或钱包。当前生产内容和玩家库受到保护；新 schema 仅增量建表，没有开发存档导入或双写。

## 后续待定安排

核心规则、经典整体定位和渐进引入方向已确认。仍待定的是正式原型题目及数量、首次引入关号和频率、内容更新编排、正式能力组合及分支质量验证的覆盖方法。技术引擎改造已授权并实现，设备验收状态单独记录。既有 1000 主线及 50 副关的编号、布局、存档与结束边界在正式内容更新方案确认前保留，不据此直接插题、重排或增加第 1001 关。人工精选前二十关体验／后续 Premium、圆球排序、四区域及 18／24 瓶均为各自后续设想，不作为本轮引擎能力的实现依赖或验收目标。
