## 开发目标与范围

让玩家通过整理液体达成阶段目标，打开新的瓶子或瓶组，或显露本瓶原先被遮盖的颜色，再利用新增的液体、空间或信息解开后续任务。一关内形成“准备 → 突破 → 新局面 → 再突破 → 完成”的过程，前后阶段共享同一个持续变化的棋盘。

本轮规划包含三种能力：底部钥匙分组展开、完成对应颜色揭开盖布、移走上层后逐层显露本瓶颜色。前两种开放瓶子操作权限，第三种只显露自身液体信息，不打开其他瓶组。未开放的瓶子可以装有液体，不限于空瓶。“完成任意颜色打开空瓶”的创意 72 保留为独立候选，不作为共同限制。

**产品定位已确认：经典排序是一种连续推进的玩法，普通整理和带机关／遮色的关卡共用经典入口、关卡流程与进度。** 不设“揭秘模式”、经典内子模式入口或另一套揭秘关号、进度、钱包。玩家从简单整理逐步进入带有新变化的关卡；“钥匙、盖布、逐层显色”是关卡能力，名称仅用于设计和必要教学，不据此拆分产品玩法。

现有公开千关、副关、记忆百题和内部调色是当前实现；本次决定规划经典后续的逐步扩展；用户进一步明确引擎升级后现有经典排序保持原规则与体验，不要求把新能力强行加入当前千关。未来人工精选内容的组织与付费仍属[设想](gameplay-ideas.md#精选设计关卡与体验门槛设想)，不立即替换闭测中的题目。具体首次出现关号、频率和内容版本待出题与试玩后确定。题内展开的“区域”指瓶组，与[主页四区域候选](gameplay-ideas.md#四个游戏区域题库规模与提示资源讨论方向)无关。首轮不叠加记忆万能块、凝固、配方杯、变色、变容量或新的商业门槛。

## 三种展开方式

| 方式 | 阶段目标 | 开放结果 | 主要决策 |
| --- | --- | --- | --- |
| 底部钥匙 | 清空钥匙所在整瓶，取得钥匙 | 自动打开固定关联的一瓶或一组瓶子，可继续连锁 | 怎样移走覆盖液体、安排中转并取得下一把钥匙 |
| 颜色盖布 | 任意一瓶装满四份指定同色 | 自动揭开固定关联的一瓶或一组瓶子 | 优先完成哪种颜色，先取得哪组液体与空间 |
| 逐层显色 | 移走遮盖在未知色块上方的液体，使其成为顶层 | 只显露该份液体的真实颜色，不打开其他瓶子 | 先探索哪只瓶子，怎样为新显露颜色安排空间 |

### 底部钥匙：分阶段探索

用户给出的代表结构是十二瓶按 **6 + 3 + 3** 展开：开局六瓶可操作，第一把钥匙开放三瓶，第二把钥匙再开放三瓶。六瓶包含本阶段实际需要的周转空间，不表示六瓶全部装满。第二把钥匙可以在后续瓶组中，以形成阶段依赖；具体位置由出题与完整验证决定。

钥匙与目标瓶组的对应关系固定、可辨认。新瓶组预先属于整题，可以带来新液体和新空间，不在解锁时随机生成。新阶段要用到前阶段整理的成果，避免仅把几道互不相关的普通题串起来。

**已确认：清空整瓶取得钥匙。** 钥匙横放在初始底层液体内部偏下，按真实瓶腔底部形状固定位置，呈沉底状态；随瓶子整体倾斜，不在瓶内滑动，也不随液体流走。最后一份倒出时仍留在瓶底；整瓶清空后自动触发，钥匙原位淡出，打开题目预先关联的一瓶或一组瓶子。露出底部液体、移动某个标记液体或将其送到指定位置均不是本轮触发规则。

钥匙是机关触发标记，不占液体容量，不作为背包资源或消耗道具。十二瓶、每次三瓶是用户举例，不是每题固定配额。

### 颜色盖布：目标与顺序选择

用户给出的形态是四瓶、八瓶或十二瓶的整题布局，其中部分瓶子盖布，例如旁边四瓶暂不可用。盖布上的颜色及辅助符号说明开放条件：形成一整瓶对应颜色后，揭开关联瓶子或瓶组。

同一颜色可关联一瓶或一组；具体映射写入题目，不默认四瓶必须一起打开。若有红、蓝两组条件，分析两种先后顺序带来的液体、空间和后续安排，形成有实际区别的选择，不能只换颜色制造表面变化。

**已确认：“完成颜色”指任意一只普通瓶装满四份指定同色。** 不要求放入指定瓶位，也不消耗这瓶液体。之后仍可正常倒水。指定瓶位、多条件合取等变体留待单独评审。

### 逐层显色：只显露自身颜色

**已确认能力：部分下层色块被遮盖，只有其上方液体移走、该色块露到顶部时，才自动显示真实颜色。** 每份液体与真实颜色在出题时固定，不在显露时随机生成。可以连续遮盖多层，随整理逐层显露；不要求开局全部下层都隐藏。

例如从顶到底为“红、未知、未知、蓝”，先移走红色，紧接着的一份未知色块显色；更深一份仍被上层覆盖，继续保持未知。此能力可以单独形成整理题，不需要钥匙或锁瓶。

规划沿用普通颜色匹配与四份容量。遮盖只影响信息，不将液体变成能匹配任意颜色的万能块；它没有记忆模式的开局观察／准备阶段，也不等到全盘外观完成才揭晓。初始可操作瓶的顶层应可见；盖布瓶先按瓶组开放规则处理，再判断其顶层信息。

**已确认的知识规则：**已显露的颜色沿用本规划已确认的信息保留原则，后续被液体覆盖或撤销也不重新隐藏；重来恢复原题初始遮盖。知识按稳定液体份 ID 保存，不能仅按瓶位或层号记录。

**已确认的倒水边界：** 只倒当前已知的连续同色段，下方未知块即使真实同色，本次也在原隐藏边界停止；动作提交后新顶层显色，玩家再次点击继续。游戏、求解、回放和教学必须采用同一边界。

## 已确认规则与实施约束

用户已确认触发、固定映射、隐藏信息、撤销、自动开放、题目质量责任与整题目标。下表同时记录配套的守恒、保存和验证约束；原型提示与商业权益仍明确保留为建议／待定。

| 项目 | 当前规则／约束 |
| --- | --- |
| 液体规则 | 沿用顶部连续同色、目标匹配、每瓶四份等容量；整题每色四份，含未开放组一起守恒 |
| 内容固定 | 所有瓶子、液体、初始遮盖份、钥匙、盖布颜色与组映射在离线制作时确定，瓶子及液体份具有稳定 ID |
| 未开放组 | 开局显示最终位置、数量、锁／盖布与解锁条件，不能倒入或倒出，看不见尚未公开的液体；各瓶原位展开 |
| 自动开放 | 达成条件立即自动打开，无领取操作；同一步满足多个机关时同步开放全部符合条件的目标，点击锁／盖布只查看说明 |
| 解锁提交 | 合法倒水后统一判定机关，液体与机关状态一并提交和保存，再播放开锁／揭布；动画不授予进度 |
| 解锁持续 | 触发后保持开放；再从完成色瓶倒水不自动关门，同一触发不重复播放或累计奖励 |
| 整题完成 | 整理好整题全部液体：包括未开放瓶在内，每只非空瓶均满四份且单色，空瓶允许保留；不额外要求取得全部钥匙或打开全部瓶组。仅可见组整理完成不能代替整题判定 |
| 撤销 | 免费回退液体与机关；撤销触发动作时恢复之前的开放状态，不受锁瓶禁倒限制 |
| 重来 | 恢复整题固定布局、初始开放组与机关；不重复授予首次完成记录 |
| 恢复 | 返回、后台和冷启动恢复液体、开放状态、触发记录与有界撤销历史，不补播机关表现 |
| 提示与权益 | 正式关卡接入经典既有的一步提示、撤销／重来与首次完成奖励流程，不另建机关钱包或额外奖励；具体关卡编排与既有商业资格的适用关系随正式内容方案明确。内部原型不扣经典提示券、不发奖励、不推进经典进度 |

**已确认撤销后的信息规则：** 撤销触发动作时重新锁住瓶组，已看过的液体保持可见，显示锁定标记且禁止操作，不重新用不透明盖布遮住。液体按动作历史回退，已知信息按同一尝试保留并保存；重来恢复开局布局与初始遮盖。这样撤销不会制造重复记忆负担。

保持十五款免费玻璃、同局统一款式、现有轻点倒水、两排且每排至多六瓶的大瓶布局。总瓶数包括未开放瓶，最多十二瓶，逻辑色最多十一种；颜色数和总空容量须另行校验，不由“6 + 3 + 3”推导。未开放瓶从开局保留最终位置，开锁时原位展开，不缩小已有瓶子；具体盖布占位表现需小屏验证。移动美术仍允许横向越界裁切。

当前目标、条件与组映射应有视觉线索和本地化读屏说明，颜色条件同时支持符号；点击锁／盖布可查看一行说明；逐层显色的未知标记不能泄露真实色或对应辅助符号，须与记忆万能块在表现和说明上可区分。可以隐藏后续内容，不能要求玩家猜未提示的规则。首轮不增加倒计时、失败惩罚、付费钥匙或独立音效设置。

## 静态外观：已确认基准与候选变种

用户已确认第一套概念方向作为待实现内容：保留现有冷色玻璃与鲜明液体，蓝灰柔光织物配低饱和金属机关与清楚的条件标记。布盖不透明、贴合容器、三至五道主要褶皱、收窄下摆；正面小色标与四个固定点表示四份同色条件，辅助符号沿用现有设置。瓶底钥匙是不占容量的机关标记，位置适配实际瓶腔，不放在玻璃外、瓶身标签处或高脚杯杯脚里；钥匙与对应锁孔同时以材质和形状配对：青铜圆头、不锈钢菱形头、红铜六角头。青铜使用青绿铜锈、不锈钢使用银灰、红铜使用红棕，避免黄铜与红铜过近；钥匙相对首版放大，按底层空间适配，并以细暗边与高光提高小屏可读性。三组以上保留显式编号，不能只靠复用颜色区分。布盖使用表示目标液体颜色的缝边徽章及四点条件，不画锁孔或锁扣；木匣、百叶、卷帘只显示承载条件的锁具，不再叠加圆形徽章。钥匙条件以锁体材质和锁孔头形配对；颜色条件将目标色、辅助符号和四点直接嵌在锁体上。钥匙机关使用刚性外壳，不把颜色徽章错误配到清空瓶条件。逐层未知份采用统一蓝灰与小问号，避免与记忆黑色万能块混淆；撤销后已见液体仍显示，只增加锁定标记。用户已授权按下述顺序实施；四个外壳家族、共用标记和显色表现已接入内部验收页面。正式机关题库与公开入口尚未交付，设备结论单独记录。

用户已确认柔光布盖、深色薄木匣和百叶护笼的效果稿作为第一版待实现基准。首套[静态基准](../assets/art-direction/unlock/static-baseline-v1.png)与三体系[效果稿](../assets/art-direction/unlock/cover-families-v1.png)保留在 assets/art-direction/unlock/，生成提示词见同目录 prompts.json。效果稿按初次锁定／展开过程／已见重锁展示材质与结构；视觉方向已批准，实际外壳、动画与棋盘适配已有源码实现；原图仍为对照基准，实际效果的设备验收见设备支持。下表其余变种保留为待评审候选。方案正文以“颜色条件解锁”为机制含义，盖布及后续外观不因此变成新规则。

| 候选体系 | 变种及材质方向 | 遮盖与限制的表达 |
| --- | --- | --- |
| 柔性织物 | 首批柔光布盖；候选束口布套，以少量收褶区别 | 完全不透明、贴合瓶形；颜色徽章说明开放条件，达成后自动揭开 |
| 硬质匣罩 | 首批深色薄木匣；候选蓝灰实色磨砂硬罩 | 紧凑贴合的外壳与清楚接缝，小锁扣封闭；只占原瓶槽，不用宽大宝箱形状 |
| 机械护笼 | 首批细框百叶护笼；已见重新锁定时采用通透框架／细栏杆 | 初始关闭的不透明百叶遮住全部液体；已见内容不再遮盖，由护框与门闩表达禁操作 |

刚性外壳使用小挂锁与连接门面／门闩的搭扣，锁体本身表达条件，不另挂徽章；已见重锁时缩小同一锁具并连接底座，保持液体可见。布盖只用缝边颜色徽章。两者是按材料选择的互斥表现，不在同一外壳重复叠加。钥匙条件使用匹配材质和锁孔头形，颜色条件在锁体或布徽章内显示目标色与四份标记；木盒或笼子不强制绑定某一种触发。四点只说明条件数量，不新增逐份累计、消耗或奖励，也不要求手动开门。

普通空栏杆会泄露尚未知的液体，不可直接作为首次遮盖；透明／磨砂材质也不得泄露真实颜色或液量。各体系都遵守“首次未见隐藏、已见重锁保留信息、达成条件自动开放”的同一契约。开放表现结束后让原玻璃成为主体，不保留占空间的盒门／笼架残件；取消、撤销和恢复由既有已提交状态决定，不依赖打开动画回调。

同关优先统一一个遮盖体系，通过条件标记区分瓶组，避免外观种类过多妨碍读题；更多材质变种后续评审。不新增外观商城、玩家设置或正式题库编排。各体系继续核对十五款容器与六列小屏占位，不扩大棋盘、不改 1900 ms 倒水时长或玩家数据。10 月 10 日用户指出第 2、10 款玻璃偏高，已将 moon／flute 瓶口各降低 4 个绘图单位，底部位置不变；其余玻璃保留。

### 容器固定与权限：已确认并独立实现

同一套底座与锁扣按限制对象复用，始终从实际开放状态、已知信息及倒入／倒出权限投影，不能仅凭瓶型、目标名称或 `fixed` 猜测。三种主要状态如下：

| 状态 | 画面 | 实际权限与信息 |
| --- | --- | --- |
| 尚未开放 | 不透明外壳及承载条件的锁具；布盖使用颜色徽章 | 不能倒入或倒出，不显示未见液体 |
| 已见重锁 | 已见液体、固定底座与匹配锁扣；布盖保留颜色徽章 | 两向操作禁止，已知颜色不重新遮盖 |
| 只进不出 | 开放瓶口、固定底座、小锁扣及向内箭头；短标记“只能倒入” | 可作为目标接水，不能作为源瓶倒出；收集颜色／数量或彩虹顺序仍由原题目标说明 |

固定位置与倒水权限独立：仅 `fixed=true` 的容器显示支架和螺钉，不画暗示禁倒出的挂锁，原有源权限继续有效。非机关但两向均禁用的容器显示底座锁扣，不画可倒入箭头。尚未开放或已见重锁优先于永久权限标记，避免同瓶重复画两套锁；机关开放后再显示其本身的永久权限。底座不遮瓶口，不盖住已知液体，位置与锁扣不随接水量移动，不新增解锁条件、领取动作、音效或完成奖励。

独立组件 `src/art/ContainerRestraint.tsx` 提供共用底座及永久权限表现，`containerRestraintState.ts` 提供纯状态投影；机关的已见重锁也复用同一底座。已接入内部十二份收集、六份彩虹层序场景和现有机关样板，标签／点击说明／读屏与真实权限一致。倒水、撤销、重来、提示与保存仍使用现有引擎；没有替换正式题库或向公开经典入口增加玩法。源码实现与设备验收分开，当前证据见[设备支持](device-support.md)。

本轮性能固定八个动作做原表现／新增表现两组、最多 16 次倒水，保持相同包／设备／场景／镜像与采集策略；不录屏计时、不在倒水中轮询。完成即停；位置异常、闪烁、内容泄露、采集不完整或进程改变立即停止，未找到有效改善／成本解释不自动反复重测。视觉逐帧检查另做短录屏，不混入计时。其他款仅在引入新绘制技术或异常时追加事前声明的小样本，不恢复大规模重复压力测试。既有 p95 ≤33.3 ms／p99 ≤50 ms 目标和未达标事实保留；短对照用于识别新增成本，功能／外观通过不等于全局性能或上线验收通过，验收证据仍归[设备支持](device-support.md)。

## 出题与验证

制作关卡时使用共享规则完成求解、独立回放与导出复验。评价重点是关卡的设计质量、思考要求和游玩节奏。

每题先确定要考察的突破，再安排液体、开放组与触发条件，并实际验证阶段依赖和周转空间。

1. **定义整题。** 保存全部布局、初始开放组、初始液体遮盖与份 ID、钥匙位置／标记、触发类型、目标组、规则版本与可重建来源。手工原型保存完整固定定义；生成题必须支持确定性来源重建。
2. **按机关规则求完整解。** 搜索状态包含液体、开放组、触发记录与已显露信息；逐层显色在原隐藏边界停止，提示使用同一规则且不能以隐藏答案指导玩家选择。只把角色、条件和组关系等价的瓶子作对称合并，并将路线映射回真实瓶 ID。
3. **独立回放所有阶段。** 检查每步合法性、液量守恒、触发时机、逐份显色、知识保留、组开放及最终完成；覆盖一个动作可能满足多个条件的情况，同一步满足的多个机关同步开放，不能由动画回调接力解锁。
4. **分析选择与信息。** 比较钥匙／首色顺序的资源差异、准备要求及后续安排；记录逐层显色带来的新线索和计划调整，为质量与难度指标提供证据。
5. **核查展开价值。** 记录新增瓶和液体实际参与的动作、阶段之间的依赖与关键选择；与全部开放版本按同一全盘整理目标对照。
6. **去重与导出复验。** 结构键包含液体、初始遮盖分布、机关类型、标记位置及瓶组关系；相近派生题归为同一家族。SQLite 导出后逐项读回全部定义与完整路线。

制作验证记录实际覆盖和计算预算，完成后方可导出内容；手机不进行每次倒水的全局搜索。

## 难度与内容节奏

带机关或遮色的经典关卡须按阶段实际目标重新评价，不能继承普通底题的 human-decision-v1 分数或记忆评级。难度、整理工作量与视觉布局分开处理，具体口径见第三步。

**整体节奏已确认：从前期普通经典排序，随关卡推进逐渐引入变化，后期通过机关和信息探索丰富同一种玩法。** 新能力首次出现时安排简单易懂的教学关，不通过新入口或重新选模式来引入。

具体编排建议为：普通整理 → 单项能力的简单教学 → 同规模的准备与取舍 → 两段连锁／顺序变化 → 经验证的能力组合。先分别验证钥匙、盖布与逐层显色，再评审组合；逐层显色可以单独用于一题，组合规则尚未冻结。普通整理关仍可穿插出现，不要求后期每题叠加机关。每次主要增加一个因素，不同时加颜色、加机关并减少空间；挑战之间安排熟悉、宽松的恢复题。新增阶段必须带来新决策，不能全是机械收尾。

机关等级、步数窗口、正式题量、峰谷阈值与生产规模尚未冻结，须在三种机制分别试玩后确定，不预先承诺固定配方、百题或千题。

步数是当前规则下离线最短路线，不是人类难度评分。第 1／8、2／11、7／10 各是同一家族的能力变体，其他六题分别组织，共九个设计家族；不把十二题称为十二种独立结构创意。精确结构键枚举瓶位排列并规范化颜色，保留遮盖、机关位置／条件与组映射，十二份完整定义无结构重复；不以换色／换皮充数。后半段加强准备、阶段依赖与信息整理，尚不能称为真人校准的偏难等级。

`npm run unlock:verify` 只复验这十二份固定手工内容，不生产候选或计算综合难度分。已穷举 **323,958 个等价正向局面、3,492,934 条合法转移**，覆盖两种首色顺序、两段依赖与同步触发。保持钥匙来源、目标组及规则角色，只合并等角色瓶和同色同公开行为液体，完成时终止扩展。这些是固定内容的技术证据，不代替质量与难度评分。

十二条路线共 130 步，另以独立单位／边界／机关规则逐步回放并核查守恒、同步开放、知识、恢复和完成；离线隔离 SQLite 逐题写入、逐字段读回定义与路线，再完整回放。每题与全部开放版本按同一全盘目标对照，记录解锁阶段与新增瓶的实际参与；阶段结构不另增通关目标。验收内容证据为 `assets/levels/unlock-trial-evidence.json`；完整诊断与隔离数据库在忽略的 `builds/unlock-trial/`。手机不运行穷举或加载这些离线证据。

内部提示沿用现有共享引擎契约。评价方向见第三步；当前固定题验收工具只证明规则与固定布局可解。实际界面与设备检查另见[设备支持](device-support.md)。

## 第三步：质量与难度评价

**已确认方向，分步实现：先解决排序难度，再用整理量安排节奏、用固定布局模板保证表现质量。** 人参与定义方案、试玩验证和改进统一算法；程序自动判别每道题，不接受人工填分、补分或逐题豁免。当前已实现可解性、阶段整理量、经典对照及首版单钥匙分段规划档位；整理节奏与视觉模板验收尚待实现，不输出最终质量结论。规划档位是自动制作代理，尚未经真人校准。

### 核心经验与边界

- 排序思考是核心体验。第一批十二题过程清楚，但空瓶与周转空间过多，用户感觉几乎不需思考，只是在机械搬运。这批保留为教学和低挑战反例，不能作为挑战题达标的依据。
- 步数多、合法动作多、路径多、机关多或隐藏多，都不等于更难或更好。空瓶数量也不能单独代替难度；要看当前目标需要怎样安排与腾挪。
- 钥匙目标明确、开局范围缩小，可能减少找方向的负担。六题经典配对已有这种整体反馈，因此加机关后必须重新评价，不能继承底题分数或固定加分。
- 可解性底线是初态至少存在一条合法完整解。允许选错后免费撤销／重来，不要求所有合法倒法都能直接解完。设计指定的钥匙节点须为完成解必经，但准备倒法不限；不把全部机关开放新增为通关目标。
- 不强迫猜隐藏真值。固定真值可解不等于公开信息公平，二者分别验证；预算不足保持 unknown，不能判高难、无解或通过。

### 难度：按阶段目标评价，整题取最大

一把必经钥匙的题，拆成两个任务：

1. **取钥前：**从开局出发，以取得这把钥匙为目标，评价找到并完成准备关系的排序难度。不能仍用“整题完成”的目标替代，也不能只统计全局最短完成路线上的前半段。
2. **取钥后：**以实际解锁后的完整局面为新的起点，评价整理全部剩余液体的难度。保留这一局面的液体、开放状态和已知信息，不假设回到原始底题。
3. **整题：**同一可完成方案的难度是两段难度的最大值，不平均、不按操作时长加权。取得钥匙后可能留下不同局面，应成对评价前后段；从可完成方案中确定最低必须跨过的最高难点，不能拼接不同方案的较容易半段。多节点按同一原则扩展，先完成单钥匙版本。

例如方案 A 为前 20／后 70，方案 B 为前 50／后 40，各自难度为 70、50；最低必需挑战为 50，不能拼成前 20／后 40。路径条数不参与加分或扣分，选错后变难或需要撤销可以发生。

**首版已实现：`goal-stage-planning-v1`，输出 1–7 规划档位，已完成任务为 0。** 两段及普通经典对照使用同一策略梯度：准备段最多允许 2／4／6／6／8／10／12 次倒水，再看 0／1／2／3／4／6／8 个后续进展段。档位不是旧 human-decision-v1 的百分制，不能把 4 档换成 50 分，或改写现行千关评级。

**保留原始经典分数作长期对照。** `unlock-classic-reference-v1` 独立复算去机关底题与同一证书实际解锁后的全盘排序局面，保存原 `planning-depth-v1` 检查、`human-decision-v1` 原分数及分项、局面、算法版本、预算与哈希，不以新档位替换旧分数。取钥目标不是全盘排序，旧百分制不能直接套用，前段明确记录 `not-applicable` 与原因，仍保存其目标专属规划档位；不拿底题分数冒充取钥分数。解锁局面未获证书、经典计算限额或旧模型不适用时，不填猜测分数。经典对照不参与新档位或解锁证书的选择。

取钥前的公开进展按“钥匙瓶液体份数更少，其次开放瓶的颜色段更少”判断；触发即结束这一任务，不用新打开的内容反过来挑前段动作。取钥后按全盘颜色段减少判断排序进展。枚举到第一次进展的合法准备段，只用上述公开进展与有限前瞻排除立即卡住的候选，保留最短的全部并列候选并检查它们都能完成阶段；不读取精确解成本或后段档位替策略挑幸运动作。任意合法动作仍可走错，策略验档不增加全动作安全门槛。

按档位从低到高检查，通过的取钥策略所能到达的解锁局面逐一作为后段起点；只对仍可完成整题的前后方案计算最大档位，再找最低的配对最大值。前后使用同一个解锁局面，完整回放证书保存实际稳定 ID、触发步及该步的真实帧；不把全局最短路线的切分当作阶段评价。较低档位未完成检查时，不能用高档解法冒充已评级。

最低档位限定于这套固定策略，不声称穷尽所有人类方法。支持四份全盘排序、至多八瓶的普通可见题或一把必经底部钥匙；锁瓶在取钥前不可用，开锁后全部可见。渐进遮色、颜色盖布、多机关及可选钥匙暂为 unsupported，无档位。搜图／策略预算不足，或七档均未得到策略证书，均为 unknown，不自动升到最高档；穷尽无解为 blocked。固定真值的档位也不证明所有隐藏排列公平。

### 节奏：前后整理量，不作为难度加分

记录阶段需要处理的混杂液体、颜色段与合并量，以及实际倒水量，支持两类结构：前后大致均衡，或前多后少、逐步收束。解锁动作计入前段；取钥后的局面必须与同一前段对应。具体数量范围用对照试玩确定，不先发明权重或精确比例。

整理量用于安排过程长短，不代替思考难度。前后步数相同不证明同样难；打开更多空瓶后只剩机械归色，也不能因整理量大而成为高难。教学／恢复可以轻松，挑战题须达到其难度目标，不能靠视觉模板补偿缺少挑战。

### 视觉质量：固定模板与自动检查

沿用已批准玻璃与统一大瓶布局，先整理现有布盖、单瓶匣、双瓶匣、三瓶匣为固定模板。常用原则是对称、工整、间距一致，条件与关联瓶组清楚，展开前后构图稳定；不追求以装饰数量或机关数量评分。

后续把模板适用条件与布局检查写成统一规则：组内位置、条件标记、关联关系、遮挡和静态边界等。保持每排最多六瓶及现有交互；倒水中的美术允许横向越界裁切，不加入新的移动边界限制。模板尺寸、容许误差与自动检查尚未冻结、实现，不宣称代码结构已经证明美观。

规则／信息验证通过、达到所需难度与整理节奏，并符合经过试玩认可的模板，可作为高质量内容的制作验收标准。先采用通过／不通过／未知，不再设计宽泛的质量百分制。试玩反馈用于改进模板和统一算法，最终单题结果不掺入人工分数。

### 已实现离线工具与复算契约

```sh
npm run unlock:rate
npm run unlock:rate -- --set calibration
npm run unlock:rate -- --set baseline
npm run unlock:rate -- --out builds/unlock-rating-small-budget --max-states 1
```

`unlock-diagnostics-v2` 提供离线证据，`consequence-stage-v1` 保留底层诊断，`goal-stage-planning-v1` 负责分段规划档位，`unlock-classic-reference-v1` 独立保留原经典分数。源码为 `scripts/lib/unlockRatingGraph.ts`、`unlockRatingEvidence.ts`、`unlockRatingFacts.ts`、`unlockDecisionAnalysis.ts`、`unlockStageDifficulty.ts` 与 `unlockClassicReference.ts`，入口为 `scripts/unlock-rating.ts`。保留固定布局完整动作图、合法路线回放、阶段必经性、实际兼容余量、阶段整理量、经典底题对照、精确结构去重和定义／规则／预算哈希绑定。换色、稳定 ID 改名或等价瓶位重排不能改变评价事实。

报告首页显示整题规划档位、同一证书前后档位与同算法经典底题对照，并保留底题原经典百分分与适用阶段的经典对照分；工作量表单独展示。逐题 JSON 保存策略检查、统一预算及完整配对回放证书，经典分数作为独立哈希证据绑定同一阶段证书。后果差异计数及旧公开进展策略前瞻仅作底层诊断，不输出旧加权 Q／D、操作量档位或评分空清单。工作量走廊主要覆盖最短及额外两步完成路线，独立分段规划不受此范围限制。最短步数、搜图规模和机器耗时均不加难度分。

默认每图预算为 250000 状态／4000000 边，每次阶段评价另有 2000000 工作单位；分别用 `--max-states`／`--max-edges`／`--max-stage-work` 指定，策略预算包含准备、前瞻、并列验证及证书路径提取。原经典复算独立使用 100000 搜索状态、1000000 策略工作单位与 30000 ms 限额，阶段限额不改写经典参考结果。定义、方法、比较集与全部预算绑定相应证据哈希。报告、详细原始证据及隔离验证库只写忽略的 builds/，不在 docs/ 堆积逐题流水，不读写玩家库或内容资产。必要计算未知时不判通过；质量验收和真人标尺仍待完善，不据本轮诊断启动正式生产。
