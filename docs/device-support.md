# 当前十二瓶的跨设备支持

2026 年 10 月 8 日。确认目标为 iOS／Android 手机和平板、PC 浏览器、Android TV 与 Apple TV。十八／二十四瓶的自动排布延期，扩展规则见 [布局约定](adaptive-layout-design.md)。本文分别记录已实现的适配、构建证据与设备验收，不能将浏览器窗口样本当成对应原生设备实测。

“覆盖所有设备”以这些设备类型为目标，不等于所有历史系统和机型均兼容。当前生成包的最低系统为 iOS 16.4、tvOS 16.4、Android API 24（Android 7.0），Android target API 为 36；它们是构建声明，不是这些最低系统上的实际性能结论。PC 此轮实际检查 Chromium，Safari／Firefox 仍待补验。

## 当前适配

- 保留 4–12 瓶、两排、每排最多六瓶，同一窗口内所有关卡使用相同瓶子尺寸；十五种容器始终等比缩放。关卡、颜色上限、容量、求解和存档规则没有扩展。
- 手机保留原来的竖屏界面。iPad 支持竖横屏和可变窗口；Android 在最小宽度达到 600 dp 的平板上解除竖屏限制。安全区域使用实际系统边距。
- 宽度至少 600 且超过高度 1.15 倍的窗口使用右侧操作栏，给两排瓶子更多高度。其余窗口保留底栏。TV 固定使用侧栏，并在四周预留至少 5% 安全区域。
- 浏览器支持鼠标、触控和键盘。Tab 进入／退出控件，方向键在瓶子间移动，Enter／空格确认；Escape 先取消源瓶，再返回首页。弹层打开时棋盘键盘处理停用，输入框不截获方向键。
- TV 使用原生方向键焦点和确认键；主页开始、棋盘首瓶和通关继续提供首选焦点。金色焦点框独立于源瓶的抬起与底部标记。动画期间可保留 TV 瓶子焦点，已有同步 busy gate 继续拒绝重复动作。
- TV 字体放大至常规的 1.4 倍，基础按钮增大；纯文字页面提供可被遥控器滚动的区域。首页和完成效果弹层可滚动。
- 关卡菜单顶部控制区限制高度并可滚动，避免小屏展开内部试玩时挤掉关卡列表；软键盘打开时，跳转按钮一次点击即生效。
- TV 关卡列表按实际剩余高度设定列表高度，适配原生焦点容器；Apple TV 在游戏或弹层中启用 Menu 返回处理，首页保留系统离开应用行为。
- 浏览器窗口低于正常可用高度时允许滚动：竖向界面至少按 520 高、侧栏至少按 400 高布局；最小布局宽度为 320。极矮窗口不要求全部控件同时出现，但必须能滚动到达，不能靠重叠点击区容纳。
- 调整窗口、旋转和后台切换继续结束当前视觉动作，显示已提交的逻辑结果。浏览器动画结束后恢复瓶子键盘焦点。原生 Alert 不可用的浏览器也能显示并关闭提示反馈。

## 构建方式

React Native 使用与 Expo SDK 57 同核心版本的 `react-native-tvos@0.86.3-0`，同时支持移动端与 TV。`.npmrc` 使用 `legacy-peer-deps=true`，解决稳定 TV 分支带预发布后缀时既有原生依赖的 peer semver 拒绝；版本和锁文件一并固定。Expo 的 TV 配置插件只在 TV 构建启用。

```sh
npm ci
npm run web
npm run web:export
npm run ios
npm run android
npm run prebuild:tv
npm run ios:tv
npm run android:tv
```

浏览器导出位于 `dist/`，需通过静态 HTTP(S) 服务提供。没有部署到公网。浏览器存档属于当前浏览器和来源站点；更换域名、浏览器或清理站点数据不会同步到其他设备。当前没有云同步。

TV 命令将当前源码、素材和配置复制到忽略的 `builds/tv/`，链接同一套依赖，在该目录生成 TV 原生工程。它是构建快照，不是 Git 分支或 worktree，不清除根目录的手机原生工程。TV 的商店图标、展示素材、签名及发布流程仍须按目标平台完成；现有 Android 政策文本不能直接作为所有新平台的发布验收。

移动端与 TV Android 工程共享依赖中的 Gradle 原生输出，必须依次构建，避免并发构建争用这些输出。本次原生检查使用 `builds/device-compatibility/tv/` 等价快照，脚本默认生成目录为 `builds/tv/`。

十五种容器已逐一切换；德语长文本与阿拉伯语 RTL 在 320 宽窗口检查。键盘倒水、动画中从窄窗改为横屏、焦点恢复、提示及提示券用尽反馈、弹层 Tab／Escape、刷新后的局面和容器偏好恢复均已操作确认。

正式导出的浏览器构建另外完成首关五步通关、完成展示结束后出现继续按钮、提示券奖励与进入第二关；没有内部预览箭头。浏览器观察未出现运行错误；开发构建有既有 shadow／pointerEvents 弃用提示。尚未验证其他浏览器引擎、浏览器声音的听感或长时间性能。

`npm run audit:layout` 使用上述实测舞台，检查九种瓶数 × 十五种容器 × 十一种窗口，共 1,485 组静止填充轮廓与点击区域；均未相贴或越出静止棋盘，最小可见空隙约 4.72。该测量不包括轮廓描边、光晕、焦点和移动中美术，也没有使用未来扩展的最小间距参数。

本机适配检查产物位于忽略目录 `builds/device-compatibility/`；本轮正式包、截图和运行证据位于 `builds/release-0.1.1/`。自动测试 150 项通过，TypeScript 与 ESLint 通过。本轮遵守用户“仅做本地 Expo 检查”的要求，没有重新向 Expo API 或 React Native Directory 发起检查。更改不涉及生成或发布新关卡。

## 正式包与原生模拟器验证

以下均为本机模拟器或构建检查，不是真机验证。移动端正式 Android 包为 0.1.1（versionCode 5），开启 R8，关闭内部入口。TV 为独立正式配置包 0.1.1（versionCode 3）；iOS／tvOS 为 0.1.1 Release 模拟器包。移动端 AAB、AAB 生成的已签名 APK 及一致的混淆映射已核查；当前实际运行验证为 ARM64，其他 ABI 不能由这些结果推定。

- Android 手机：API 36、真实 16384 字节页的独立模拟器安装 AAB 生成的版本 5 APK。关闭 16 KB 兼容回退后启动，第 42 关倒水后三层／一层，撤销后四层／空瓶，均读取实际界面验证；另保存第 910 关带符号画面。
- Android 七英寸平板：API 34，1024×600、density 160、最小宽度 600 dp。版本 5 完成横屏第 42 关及竖屏第 910 关展示；倒水及撤销的实际层数变化均已验证。
- Android 十英寸平板：API 34，2560×1600、density 320、最小宽度 800 dp。版本 4 完成第 279 关横屏、第 42 关竖屏以及倒水。发现并修复清单竖屏锁定导致平板先被信箱化、再被误判为手机的问题：清单先允许旋转，MainActivity 创建后只锁定最小宽度不足 600 dp 的手机。版本 5 包含相同修复，另加 R8；十英寸截图明确标为版本 4，不冒充版本 5 的重新截图。
- iPad Pro 11 英寸 M5／iOS 26.5：0.1.1 Release 完成第 673 关十二瓶横屏、倒水中旋转后逻辑结果保留、撤销，以及第 42 关竖屏。倒水后三层／一层，撤销后四层／空瓶。横屏原图由 Simulator 的 Save Screen 保存，避免 simctl 竖向帧缓冲截出侧倒画面。
- Android TV：专用 API 34、1920×1080 模拟器安装正式签名版本 3。清单含 Leanback 启动入口、必需 Leanback、非必需触屏，以及 320×180 品牌横幅。使用 adb 方向键和确认键完成首页、引导、首关倒水及侧栏撤销，实际三层／一层与四层／空瓶已验证；保存月光瓶首页及金色遥控焦点画面。
- Apple TV 4K／tvOS 26.5：0.1.1 Release 在专用模拟器完成第 910 关进入、遥控焦点移动、倒水与停滞反馈的侧栏操作，并保存第 673 关十二瓶画面。此前适配包已验证首关撤销及 Menu 返回；本轮正式包没有把仅点击撤销按钮计为已核对撤销后的逻辑结果。
- PC 浏览器：正式导出在本机 Chrome 以 1920×1080 和 1024×768 保存第 279／673 关；鼠标及键盘倒水、撤销已操作验证。没有完成 Windows Google Play Games、Safari、Firefox 或公网网站部署验收。

## 截图与重拍

十四张选定原图、对比页、尺寸和 SHA-256 清单均在 Git 忽略的 `builds/release-0.1.1/`。入口为 `gallery.html`，索引为 `screenshots-manifest.json`，场景为 `scene-recipes.json`，重拍辅助脚本为 `capture-android.py`、`seed-apple.py`。前四张使用分散的 279／42／673／910 关与不同容器，分别展示十英寸平板、iPad、PC 浏览器和 Apple TV；后续含 Android TV、七英寸平板和手机。

这些是实际应用像素。预先准备的场景存档用于产品展示，不能作为自然通关证据。可注入场景的专用模拟器原存档均已恢复并核对；Android TV 的生产系统不支持读取私有数据库，使用全新独立测试设备的首关操作，没有注入存档。没有操作数独或用户现有手机。

根据用户要求，本轮新截图只保存在本地，未加入 Git，也未上传 Google Play；商店仍使用此前已批准的手机截图。Android TV 商店轨道和 Apple 商店发行尚未提交。移动端和 TV 构建共享原生依赖输出，仍须串行构建。

完整发布验收仍需真实 iPhone／Android 手机、iPad／Android 平板、Android TV／Apple TV 的持续游玩，以及 TV 实际观看距离下的文字、色层、焦点和遥控器操作检查。最大系统字号、最低系统、其他浏览器引擎和低端设备性能尚未完整验收。
