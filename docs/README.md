## 维护规则

1. 每个主题一份正文；功能变更同步其责任文档，基线和索引只摘要、链接。
2. 当前规则直接写最终行为。删除已被替代的设计、重复修改过程和过时“待实现”，不建档案或重定向占位文件。
3. 已确认方向、建议和未定细节明确标记；规划不等于实现授权，内部／离线能力不等于公开玩法。
4. 版本来自配置，内容来自运行资产；发布状态标明来源：用户明确确认或实际保留的 Console 证据；旧送审观察不能覆盖更新的确认。代码检查、构建、模拟器、真机和真人反馈互不代替。
5. 诊断日志、历史测量和截图留在忽略的 builds/；文档只保留理解当前状态所需的结论、证据位置、精确当前产物与未解决限制。
6. 保留稳定创意 ID、素材来源／许可、必要发布证据与 SQLite 初始化边界。闭测已开始，后续启动与更新必须恢复并保护现有玩家数据；旧的无玩家重建授权不再适用。
