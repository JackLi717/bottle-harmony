# 观察记忆玩法规划

状态：2026 年 10 月 8 日，用户已选定先启动观察记忆玩法，按本文实施五题原型；三十题试排与正式题库须经过原型验收后再定。本文是观察记忆专题的唯一方案正文，对应创意 51–60 中的观察、记忆与揭示方向；[颜色解锁专题](color-unlock-plan.md)保留为后续候选。增长区间和难度阈值仍是原型假设，试玩后再冻结。

## 体验目标与首批边界

玩家先看完整棋盘，主动开始后记住被遮住的颜色位置，再结合逐步揭示的信息完成整理。希望产生“我记得它在这里”的判断与验证感，同时允许探索和恢复。

建议首批采用自主观察、部分下层遮色、顶段始终可见、游玩中新揭示信息保留的温和规则。记忆负担与整理难度分开增加。不开强制观察倒计时，不隐藏整个瓶子，不把错误记忆设为扣生命、收费或限次重试，也不与锁瓶、凝固、变容量或十八瓶一起推出。

严格限时记忆、撤销后重新遮色、从未展示过底色的纯探索均为不同规则候选，不混入首批等级。原型使用独立入口、关号和进度，四区域归属及正式权益后定。

## 观察、揭示与恢复规则

| 时刻或动作 | 建议行为 |
| --- | --- |
| 首次进入尝试 | 完整展示实际颜色与辅助符号；玩家点“准备好了”进入倒水阶段，观察时不能移动液体 |
| 进入倒水阶段 | 按该题固定遮色方案隐藏部分下层的颜色及符号；液量、瓶位、层数和空瓶保持可见 |
| 顶部可操作信息 | 输入前显露每瓶最大连续同色顶段，保证玩家知道倒出的颜色和数量；目标顶色与余量可判断 |
| 新露出的层 | 移走上层后显露新的同色顶段；游玩中揭示的液体信息在本次尝试内永久保留 |
| 液体移动 | 已显露液体随倒水保持已知；同色液体不因混合而重新隐藏 |
| 撤销 | 恢复液体和历史，但保留本次尝试已经揭示的信息；不删除实际倒水、查看和撤销记录 |
| 重来 | 回到原排列与完整观察阶段，重新建立本次尝试的揭示集合；之前尝试计入累计，题目不换 |
| 再看一眼 | 暂时展示当前棋盘全部颜色，倒水暂停；玩家关闭后回到既有遮色状态，不把临时查看变成永久揭示 |
| 后台或返回 | 暂停并恢复原观察／倒水／查看阶段；不能借切后台、重开页面或冷启动自动获得一次完整展示 |
| 完成与重玩 | 完成反馈可展示全部颜色；重玩建立新尝试并重新观察，记录为已经玩过的题 |

“初始完整看过”“临时查看过”“游玩中永久揭示”必须分别表示。若把开局展示算入永久揭示集合，点准备后就无法遮色。临时查看次数在成功展示时记录，重复点击或恢复同一查看界面不重复累计。

底色可以遮住，但合法动作的直接条件必须可见。当前规则会一次倒出最大同色顶段，不能只展示最顶一层却突然倒出多份隐藏液体；每次局面变化先显露完整顶段，再接受下一次输入。遮色位置只影响信息，不改液量、最大倒水规则或完成条件。

原型中撤销、重来、再看一眼和按需一步提示免费，不消耗正式主线资源，也不发主线奖励。一步提示使用完整真实局面，是额外帮助，记录实际执行；不能把“未重新查看”表述成“未使用任何帮助”。正式查看／提示资源、Premium 和推荐关系在选择实施前冻结，不默默减少无限一步提示权益。

## 出题策略

一题由“已验证的普通棋盘 + 固定遮色方案 + 可见性规则版本”组成。记忆玩法先使用较容易的整理结构，让记住位置产生价值，再逐步引入需要跨几次操作保留的信息。

| 题型 | 考察内容 | 出题重点 |
| --- | --- | --- |
| 单点定位 | 记住一只瓶下方的目标色 | 隐藏信息少，揭示后很快形成合并 |
| 两瓶配对 | 记住相同颜色分散在哪两处 | 有清楚的对应关系，不靠相近色混淆 |
| 底层顺序 | 记住一瓶下方两层的顺序 | 顺序确实影响下一段整理，不只是多遮两格 |
| 跨瓶关联 | 释放一处颜色时，记得另一处的去向 | 一次增加关联数量，底层整理仍宽松 |
| 延后使用 | 经过几步熟悉操作后再利用先前信息 | 用动作间隔衡量延迟，不用强制等待制造难度 |
| 记忆与推断 | 将记住的信息与颜色总量结合 | 单独标注可推断线索，不把所有成功归因于记忆 |

不要求每题都让记错导致死局。优先让准确记忆减少无目的探索、查看或绕路；恢复仍然自由。重绘、瓶子形状切换或动画不应改变实际排列，开局观察后不洗牌。

### 候选制作与验收链路

1. 先生成普通四层、颜色守恒且无初始完成瓶的底题，完整求解和路线回放。第一批维持初始每瓶同色最多两层，避免靠三层同色快速自动揭示大部分答案。
2. 按题型选择底部一层或两层遮色，应用完整顶段显露规则后，计算真正仍被遮住的数量；不拿配置中的遮色格数冒充实际负担。
3. 回放解法并追踪各液体单位及其可见性，记录何时揭示、揭示前经过多少有效倒水、哪些已知位置需要关联；至少审阅一条不同路线，避免只适配参考解法。
4. 建立同规模的完全可见对照和不同遮色强度对照，观察记忆版本新增了什么判断。相同底题的多种遮色方案归为题目变体，不宣称它们是不同物理谜题。
5. 小规模原型可构造两道公开可见部分相同、隐藏安排不同且都守恒可解的题，完整求解比较下一步最佳取舍是否不同。用来验证记住隐藏信息可能有实际价值，不要求所有题都是这种陷阱。
6. 独立验证底题来源、路线、遮色约束、顶段显露、知识随移动／撤销传播及恢复；再人工检查信息可读性与记忆价值，完成去重后才进入试排。

每道题保存实际底题、固定遮色方案和来源，不在手机按随机遮色临时决定难度。改色或换瓶位不算新底题；物理结构与遮色结构分别去重、统计。评估记忆差异时可允许有目的的匹配变体，但不能连续安排同底题让熟悉度代替新体验。

## 难度考察

整理和记忆采用两个维度，不先相加为一个未经验证的 0–100 分。底题可在现有范围内离线计算普通 `human-decision-v1` 对照分；它不包括遮色，不能作为记忆模式评级。记忆初期先使用原始量与独立 M1–M4 制作等级。

| 维度 | 记录内容 | 用途与边界 |
| --- | --- | --- |
| 整理负担 | 空瓶、普通代理、最短步数、准备与选择后果 | 判断玩家是否因普通解谜而卡住 |
| 初始遮色量 | 顶段显露后的隐藏份数 H、涉及瓶数 HB、涉及颜色数 HC | 三者分别看；隐藏格多不必然需要记得多 |
| 遮色深度 | 每瓶底部一层／两层、深浅分布 | 区分位置关联与层序负担 |
| 关联范围 | 同色跨瓶对应、需要协调的位置、可由总量推断的线索 | 先人工标注并附例，不宣称已证明记忆必需 |
| 延迟与揭示 | 各隐藏单位首次揭示前的有效动作数、揭示进度曲线 | 只描述被审阅路线，不等于人的记忆保存时长 |
| 辅助与探索 | 再看、实际提示、撤销、重来及揭示速度 | 使用帮助不是失败；多次探索不直接判记忆差 |
| 识别条件 | 颜色数、符号、容器、屏幕与可读性 | 小屏色差造成的困难不算记忆挑战 |

开局观察时长与完整查看时长分开记录，后台不计；解题时间采用前台可操作口径，动画、礼花、覆盖界面等按[统计方案](gameplay-statistics-plan.md)处理。观察时间更长不自动代表题更难或玩家更弱。

不承诺训练效果或“记忆力分数”。通关反馈可显示实际查看／提示次数与完成状态；未查看通关也可能包含探索和撤销，不能称为纯记忆完成。

## 颜色、瓶数与遮色增长

第一批保持两只完全可用空瓶 E=2，每色四份，总瓶数 B=C+2；空间政策先固定，避免同时减少空间和增加记忆负担。H 为开始倒水时真正隐藏的份数，HB 为涉及瓶数；表中范围还须满足底部遮色与顶段可见条件。

| 内容段 | 颜色 C／总瓶数 B | H／HB 起始目标 | 每瓶遮色 | 主要增长 |
| --- | --- | --- | --- | --- |
| 1–3 教学 | 2–3／4–5 | 1–2／1–2 | 底部一层 | 观察、准备、揭示与再看 |
| 4–10 入门 | 3–4／5–6 | 2–4／2–4 | 底部一层 | 记住少数位置的对应 |
| 11–20 发展 | 3–5／5–7 | 4–6／2–4 | 一层为主，部分两层 | 引入顺序与跨瓶关联 |
| 21–30 检验 | 4–6／6–8 | 6–8／3–5 | 至多两层 | 增加关联或延迟，分别考察 |
| 验证后扩充至 60 | 4–6／6–8 | 6–10／3–6 | 至多两层 | 同规模增加记忆结构变化 |
| 验证后扩充至 100 | 5–8／7–10 | 8–12／4–6 | 至多两层 | 少量更大棋盘，穿插熟悉的小题 |

H、HB、颜色区间不是任意笛卡尔组合，例如 H 不能超过 2×HB，HB 不超过 C，也不能遮到可倒顶段；不满足时换候选，不能修改显露规则来凑数。后两段只是扩充路线，首批最多六色／八瓶，不承诺 100 或 400 题。

增加颜色会同时影响辨认和关联，增加瓶数会影响位置查找，增加 H 会影响待记信息。因此同一过渡只提高一项主要负担：先在三四色情况下增加遮色，再引入第五色，降低遮色巩固，然后恢复原负担。大棋盘未必比小棋盘更难。

若未来仍保持 E=2，十二瓶最多十色。单空瓶、三层遮色、更多颜色或十八／二十四瓶属于后续独立检验，不作为首批必然升级终点。现有十五款外观全部免费、统一选择；不通过换陌生瓶形、缩小色层、移位或解锁外观制造记忆难度。底题逻辑只有普通四层瓶。

## 分级与坡度

| 制作等级 | 记忆特点 | 整理控制 |
| --- | --- | --- |
| M1 认识 | 1–2 个单点，看到后较快验证 | 容易整理、少分支 |
| M2 定位 | 多瓶位置或简单配对，底部一层为主 | 保持宽松空间，不同时增加规划 |
| M3 关联 | 部分两层顺序、跨瓶关联或延后使用其中一项 | 用熟悉底题结构承载新负担 |
| M4 综合 | 两种已学信息关系组合，仍可自由再看 | 适度整理选择，避免高规划与高记忆同时封顶 |

M 等级不是隐藏份数分档。同样 H=6，六个很快露出的单点与三只瓶中需延后使用的层序可能不同；须由具体证据与试玩判定。第一批的重点是 M1–M3，M4 少量验证。

首个 30 题试排与机关专题采用相同的十题节奏，便于比较体验：位置 1–2 恢复／巩固、3–5 单因素爬坡、6 次峰、7 恢复、8–9 组合爬坡、10 主峰；首单元前三题教学。

| 单元 | 熟悉区间 | 次峰／主峰目标 | 下一单元恢复 |
| --- | --- | --- | --- |
| 1–10 | M1，开始 M2 定位 | 小配对／多位置 M2 | 减少隐藏位置，保留熟悉颜色 |
| 11–20 | M2，开始 M3 的一种关系 | 单一层序或延迟／M3 | 减少 H 或取消层序，保持底题容易 |
| 21–30 | M2–M3 | M3／少量 M4 | 若继续扩充，回到已熟悉的单一关系 |

恢复采用至少降低一个等级，或在同级内明显减少隐藏量／关联／延迟中的一项，并由试玩确认放松；单纯增加查看额度不代表题目本身已经缓冲。颜色数与普通底题规划不在记忆峰上同时加码。主峰规划目标不下降，普通题允许回落；不套用普通主线的分差阈值。

每题记录底题整理档、M 等级、角色、H／HB／HC、遮色深度、主考察关系和相邻变化。若查看次数突然上升，先判断是记忆、整理还是识色造成；不自动压缩观察时间或削减辅助。

实际排题先固定各单元的底题整理区间和主考察关系，选定次峰／主峰，再找恢复题，最后填入爬坡。非教学段新增颜色最多加一色，优先放在位置 3 并降低遮色，位置 4–5 巩固；一层到两层遮色也单独引入，保持颜色与隐藏总量相近。单次增加 H 先以一至两份为试验步幅；与 HB 必然联动的变化记为一次信息量增长，不能再同时加颜色、层序或延迟。位置 8–10 组合已熟悉因素。

验收逐个过渡检查新增信息、揭示曲线、底题整理稳定性与恢复，再连续试玩十题。候选的 H 很高但迅速全部揭示，不能代替记忆峰；同级题的实际负担不同，按反馈重排。供给不足时缩短题集，不放松可见性规则凑数；若以后扩充到四百题，优先增加配对、层序和延迟结构的变化，规模上限保持十二瓶，不无限叠加遮色或颜色。

## 原型、试玩与验收

先规划五道结构互异原型：单点定位、两瓶配对、两层顺序、跨瓶关联、延后使用。用规模相近的完全可见题作对照；参与者不要先玩同一个底题再玩其记忆版，以免熟悉度污染结果，可交叉分配匹配题。

记录实际观察时间、再看／提示、倒水／撤销／重来、首次揭示时刻、是否记得某个位置，以及记对后的主观反馈。询问玩家“刚才哪一步用了记忆”和“哪里变成了猜测”，区分主动回忆、推断与逐瓶试探。小样本无法仅凭时间或查看次数推断记忆能力。

建议以 6–10 名不同熟悉程度的试玩者发现问题，与颜色解锁采用相同招募口径、交替先后顺序。实际参与人数、完成与帮助情况一起报告，不作留存或训练效果结论。

规划进入实现的条件：

- 五题底题来源、完整路线、遮色、顶段、知识传播与保存恢复独立验证通过；必需校验不存在未知。
- 玩家能主动开始并理解揭示与再看；能指出至少部分记忆真正帮助了自己的操作。
- 同规模不同遮色方案产生可解释的负担差异，恢复题能缓解压力；帮助次数增加不是因为普通底题突然变难或看不清。
- 不依赖后台、撤销、动画、读屏或设置泄露未知颜色；这些通道展示同一可见性状态。允许的永久揭示必须稳定，不能时隐时现。
- 十五款容器、小屏、符号及恢复流程可以验收；切样式不换局面，不闪现隐藏色，真实设备表现满足既定预算。

若玩家始终逐瓶试探，先缩小记忆量并改善记忆信息的实际作用；若记得颜色却仍频繁卡住，先降低底题整理负担。只有视觉遮罩而没有记忆收益的题，不进入正式题库。

## 实施依赖与原型后评审

当前棋盘只有颜色数组，没有液体单位与知识状态。实施时需为每份初始液体建立内部稳定身份，随最大连续段移动与撤销；它不出现在玩家界面。同色单位仍按规则等价，身份仅用于可靠追踪可见性，不能因此虚增物理新题。

保存底题、遮色方案、可见性版本、当前阶段、永久揭示集合、查看与辅助事实，并保证与棋盘／撤销一致。临时完整查看与开局观察不加入永久集合。仅按“某瓶第几层已见过”保存会在倒水或撤销后对应错液体，不能采用。

普通全信息求解仍用于证明物理可解与请求式提示；它不能证明人类容易记住、仅凭当前所见能找出最优路线，或某信息确实必须记忆。可见性测试与玩家对照独立进行。颜色名称、符号、提示文案、动画和读屏都要遵守同一显露规则，不额外在每步启动完整搜索。

SQLite 改造正在另一项工作中推进。记忆原型与其内容、玩家库的稳定接口协调，内容导出后读回重验，恢复知识状态和有效动作事实；不引入旧 JSON／AsyncStorage 运行存储或兼容层。现有主线、商业权益及初次数据库初始化边界不因本文自动改变。
