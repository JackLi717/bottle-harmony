# 后续产品规则与创意

第一版实际行为见[基线](current-baseline.md)。本文仅保留当前决定、待定边界与稳定候选编号；黑色记忆百题已落地，本轮另已设计与体验少量调色、成果呈现及黑色记忆样题，正式产品编排待体验后决定，其他条目收录不代表授权开发。

第 1–20 条的可计算标签和千关编排已实现，不代表二十项玩法全部交付，定义见[特征算法](level-feature-design.md)。102、103、105、106、108 已实现首批表现，见[水声与表现](pour-presentation-design.md)。首版固定明亮十一色，阴影主色 76%、高光混白 55%，无主题或完成效果选择。其余条目及这些方向的进一步扩展仍待评估。

新玩法先明确玩家价值、规则／教学、与主线和辅助的关系、存档兼容及少量原型验收；改变规则时同步会话、求解与回放，正式题必须可解、守恒、来源可重建和精确结构去重。隐藏信息还须验证仅依可见信息能合理推进。保留无广告、免费撤销／重来和可恢复的方向。

用户确认撤销是跨玩法通用的系统回退能力。容器的禁倒、固定位置或只接收规则约束正常游戏动作，不限制撤销已接受的历史动作；不能因为特殊关卡、答案错误或局面无解而取消免费撤销。信息揭晓后的撤销保留已经公开的颜色，只回退排列与动作历史；重新挑战才重新建立观察与隐藏阶段。

当前已实施[颜色记忆](memory-mode-plan.md)及用户授权的百题试排，[颜色解锁](color-unlock-plan.md)保留为后续候选。规则、配方、难度坡度、内容证据与真人校准边界只在对应专题维护；源码交付不等于发布或玩家验收。

## 后续商业规则：无广告、推荐与 Premium

2026 年 10 月 8 日用户确认以下产品边界。规则已确定，推荐结算、关卡资格限制和内购尚未接入当前应用；现有游玩、存档与商店包的实际行为仍以[游玩流程](play-flow.md)和[发布检查](release-readiness.md)为准。该方向沿用当前千关及已有基础体验，后续专属内容另行设计。当前第一版源码可按序玩全部千关，没有 100 关商业门槛。

| 玩家状态 | 可玩的主线范围 | 主线提示 |
| --- | --- | --- |
| 免费，尚无有效推荐 | 前 100 关 | 沿用每关首次免费及现有提示券机制 |
| 累计 1 次有效推荐 | 前 400 关 | 同免费规则 |

| Premium | 全部当前 1000 关 | 不消耗提示券，不限次数使用一步提示 |

所有玩家均无广告，撤销与重来无限免费，现有十五款容器保持免费。获得关卡资格不等于通关，主线仍按顺序完成。前三次有效推荐每次增加 300 关，资格上限为 1000；后续有效推荐不承诺新增关卡奖励。Premium 采用一次性购买方向，US$2.99 为候选价格，最终价格尚未确定。现有免费的一次提示、撤销、重来和备用瓶不改为付费权益；额外瓶子与未来专属内容不纳入本次后续商业规则。

### 颜色记忆的付费边界与近期重点

2026 年 10 月 9 日用户确认：颜色记忆前 100 题免费，后续新增题目仅供 Premium 使用，作为免费与付费体验的主要区别。经典主线的推荐资格规则保持独立，推荐不解锁第 101 题起的记忆内容。未来记忆题库可扩展到 1000 题，须先完成新规则评级、校准和正式出题；当前仍只有已实现的百题，内购与记忆付费资格尚未接入，不宣称已经提供后续题目。

近期优先做好玩法、题目质量与关卡节奏，不围绕购买比例或付费转化优化游戏难度。沿用一次性购买方向，US$2.99 仍为初期候选价，尚未确认最终商店价格。所有玩家的记忆查看、一步提示、撤销和重来继续免费；不出售记忆辅助次数，不收回现有免费百题或器皿。

个人表现展示、按偏好／能力组织练习与专题选集保留为后续想法，暂不作为主要开发项目或主要付费卖点，也不据此承诺新 Premium 权益。现在先准确保存本地作答、辅助、时间和长期摘要；展示方式合适时另行设计。统计口径与保留边界由[统计方案](gameplay-statistics-plan.md)负责，题库的新评级候选由[记忆专题](memory-mode-plan.md)负责。

### 有效推荐与允许重复参与

- 一份推荐参与记录首次完成前 20 道不同的正式主线关卡后，计为一次有效推荐。仅下载、打开或购买不达标；重玩同一关、副关卡及内部预览不累计这 20 关。
- 推荐人可邀请任意数量的参与者；每份记录独立达标，奖励归给该记录首次确认的直接推荐人。同一份记录内不更换推荐归属。
- 用户明确允许自己邀请自己，以及卸载后通过另一个邀请重新参与。重新建立的参与记录仍需实际完成前 20 道主线关卡；不要求证明是另一位自然人。
- 不做跨卸载重装的身份追踪，不强制登录，不增加实名、设备指纹或跨记录的同人去重。
- 同一份参与记录最多结算一次。重复上报、联网重试或撤销后再次完成第 20 关不能重复发奖；这是结算正确性，与允许重新参与是两个边界。
- 离线可以继续游玩；归属确认、达标上报与奖励领取需要在线结算。不能把离线尚未确认的达标当成已到账奖励。

这里的“有效推荐次数”表示完成 20 关的参与记录数，不宣称是独立自然人数。归因只记录首次确认的邀请来源；不证明谁先口头推荐，也不追溯未建立参与记录的分享。分析时分别统计参与记录、达标次数与购买情况，不把这些数字直接描述为独立新增玩家或自然增长。

### 实施依赖与待定事项

允许重复参与降低身份核验要求，但另一份安装的游玩结果仍需通过轻量在线服务送达推荐人，不能仅靠当前本地 SQLite 完成跨安装结算。匿名推荐档案、推荐码及奖励领取凭据如何保存和重新找回，应在实现时明确；允许重装重新参与不代表自动恢复卸载前的档案、关卡资格或进度。

尚待确定的数值和实现细节包括最终 Premium 价格、是否额外赠送受邀者体验权益、匿名档案恢复方式及结算服务部署。受邀者额外奖励未定。接入在线服务和内购后，须同步调整公开构建的网络配置、隐私说明、数据安全和内购声明；目前发布材料描述的是尚无联网及内购的现有包。邀请解锁的商店审核路径仍待核实，不因允许自己邀请自己而视为已经获批。

## 颜色记忆玩法头脑风暴

讨论日期：2026 年 10 月 9 日。现有颜色记忆百题的规则与实现继续由[观察记忆专题](memory-mode-plan.md)维护。隐藏万能块现已选定落实到现有记忆百题，规则归专题维护；彩虹配方核心规则已确认但未接入，其他头脑风暴条目仍为候选。千关及副关不变。

颜色记忆可以围绕位置、层序、跨瓶关系、目标配方和操作后的信息跟踪展开。设计重点是让玩家感到“我记得，所以知道该怎么选”：隐藏份数增加不必然增加趣味，少量但真正影响选择的信息也可能形成好题。不同变种需要分别判断记忆负担、空间规划和操作量，不能直接套用现有 M 等级。

### 让记忆帮助整理决策

这一组保留现有倒水与逐步揭示的基本体验，重点调整题目中隐藏信息的作用。

| 想法 | 玩法与趣味 |
| --- | --- |
| 关键底色 | 两只瓶都能先处理，但记住底色就能判断哪只更值得先腾空，让记忆帮助选择。 |
| 同色搭档 | 记住哪些瓶底藏着相同颜色，把几个位置组织成一组，减少逐格死记。 |
| 记住上下顺序 | 同一瓶隐藏两层，红在蓝上或蓝在红上会影响后续安排，突出层序记忆。 |
| 延后使用线索 | 开局看到的信息在若干次操作后才影响选择，形成记忆被再次用上的时刻。 |
| 少量关键隐藏 | 只遮两三份，但这些位置关系到重要分支，用小棋盘验证记忆价值。 |
| 记忆主题小组 | 几道题分别围绕配对、层序、延后使用线索编排，让题型变化容易被感知。 |

### 让观察与回想成为主动选择

这一组改变信息获取或记录方式，可以分别作为辅助工具或独立变种。

| 想法 | 玩法与趣味 |
| --- | --- |
| 单瓶查看 | 在完整再看之外，可以只看选定的一瓶；自选挑战记录查看瓶数，增加信息选择。 |
| 自选遮色 | 由玩家选择遮色位置或轻中重方案，主动决定本次记忆负担。 |
| 聚光观察 | 观察时逐瓶点亮，可自由来回查看，准备好后整理，需要拼合分散获得的信息。 |
| 带着任务观察 | 观察前先给出“先整理绿色”等目标，让玩家有目的地关注相关位置。 |
| 记忆便签 | 给隐藏层标注自己猜测的颜色，用虚线等形式区别于真实已知颜色；允许修正猜想。 |
| 记忆与推理结合 | 部分未知可凭记忆判断，也能通过颜色总量和已知分布推断，忘记后仍有思考路径。 |

便签会把一部分内部记忆转为外部记录，适合喜欢猜想与验证的体验；不能据此把通关描述为纯记忆完成。单瓶查看与完整查看的关系、额度及提示权益需要另定，不默认改变现有免费辅助。

### 改变完成目标

这一组从完整单色整理扩展到局部收集、还原或配方目标，可能形成独立小游戏。

| 想法 | 玩法与趣味 |
| --- | --- |
| 找回一种颜色 | 观察后只收集指定颜色，不要求整理整个棋盘，适合短题。 |
| 记住后还原 | 记住一个多色目标排列，再把打乱的局面恢复成目标，同时考虑记忆与操作。 |
| 彩虹配方 | 记住目标杯从底到顶的颜色层序，再调配出对应杯子，突出顺序与配方记忆。 |
| 指定归宿 | 观察时展示每种颜色对应的目标瓶，标记收起后需要记住最终位置。 |
| 找出变化 | 看过棋盘后遮住，再改变一处位置，让玩家指出变化，形成短观察题。 |
| 猜下一层 | 少量短题允许玩家自愿预测即将露出的颜色，归位后验证，答错仍能继续。 |

彩虹配方已确定为下文的大目标杯特殊关卡，其容量、只接收和满杯揭晓规则统一按该节维护。“记住后还原”等其他目标变种仍需单独明确规则。逐步回答“下一层是什么”容易打断倒水节奏，宜先作为独立短题讨论。

### 独立挑战与合作变种

| 想法 | 玩法与趣味 |
| --- | --- |
| 记忆侦探 | 部分颜色从未展示，靠“两处同色”“这里没有红色”等线索推断，偏向信息推理。 |
| 记忆接力 | 同一设备上，一人观察并口头描述，另一人整理，让描述、理解和记忆共同发挥作用。 |
| 分工合作 | 两人掌握不同瓶子的颜色，通过交流完成共同棋盘；本地分工与在线实现分别评估。 |
| 瓶子换位 | 观察后沿清楚可见的路线交换瓶位，再开始整理，增加对象跟踪；区别于现有固定瓶位。 |
| 渐隐记忆 | 揭示过的下层在若干次操作后重新遮色，顶段保持可操作信息可见，强调持续更新记忆。 |
| 一眼挑战 | 自选观察时长或倒计时，之后尝试不再查看，需要帮助时可退出挑战继续游玩。 |

还可为同一题设置自愿目标，例如不再完整查看、只查看一瓶或少用提示。完成后展示实际辅助事实，不换算为记忆能力分数。换位、重新遮色和限时会明显改变舒缓体验，应与当前规则分开检验。

### 已落地的隐藏万能块记忆玩法

2026 年 10 月 9 日，用户选定优先把黑色记忆落实到现有颜色记忆入口，并明确遮色须覆盖不同深度、包括顶层且分散。应用源码和百题已采用 `memory-black-v1`／`memory-100-v2`：黑色持续隐藏、单份万能搭配，玩家主动揭晓；答错后只有当前局面经完整解法验证才开放免费继续，撤销不重新遮色。免费查看、撤销和重来保留。

规则、分散策略、两条路线证据、存档和真人校准边界统一见[颜色记忆专题](memory-mode-plan.md)，本处不重复维护；设备交付按[设备记录](device-support.md)判定，源码完成不等于发布或玩家验收。调色及成果模板为独立授权的六题内部试验，见 151 的当前规则。

### 已确认的彩虹配方特殊关卡

彩虹配方已确定为单独的关卡品类，偶尔穿插到普通整理、颜色记忆等玩法环节。核心是一只较大的目标杯，只能倒入，不能通过普通倒水取出；玩家依次装入原料，杯满后自动揭晓并检查最终结果。它可以复用不同玩法的原料棋盘，但不是任意当前局面都能无验证地增加的目标。核心规则已确认，以下待定细节保留为后续设计事项；尚未授权实现或改动现有题库。

| 已明确的项目 | 规则 |
| --- | --- |
| 关卡形态 | 独立的特殊挑战题，可在不同玩法中偶尔出现；具体频率、编号与进度关系待定。 |
| 目标容器 | 一只容量可变的较大配方杯，容量不再限定为普通瓶的四份。用户提出四色、五色乃至十二色的候选规模，具体容量与颜色组合待定。 |
| 目标顺序 | 按配方要求装配，先倒入的原料处于底部，后倒入的原料依次叠在上面。 |
| 接水 | 目标杯允许不同颜色叠入，也接收黑色块；仍须有足够余量。不能根据答案拒绝错误颜色，避免提前泄露对错。 |
| 取出 | 目标杯固定，不能从它发起普通倒水，也不能把它当作可反复倒出的中转瓶。 |
| 撤销 | 系统通用能力，免费回退已接受的动作，包括把倒入目标杯的原料恢复到原来源；不受目标杯禁倒规则限制。 |
| 隐藏信息 | 黑色块进入目标杯后仍隐藏，真实颜色随原料保存，不能因进入目标杯而变色。 |
| 检查时机 | 目标杯装满后自动揭晓，按实际颜色从底到顶比对配方；不再要求手动提交。 |

彩虹星图可作为配方的候选视觉表达，用与目标容量对应的彩色星及辅助符号展示顺序，并清楚标明底到顶的方向。目标杯允许变大，不意味着普通原料瓶也改变容量或缩小尺寸；大杯与原料棋盘的布局需单独设计。配方长度、不同颜色数分别定义，例如十二份配方可包含重复颜色，不必使用十二种不同色；若确实使用十二种不同色，则超出现有产品十一色上限，须明确扩展并验证，不能视为当前能力。

| --- | --- |
| 普通整理原料与配方杯 | 原料全部可见，规划怎样从顶部取得所需颜色，按顺序送入目标杯。 |
| 隐藏万能块与配方杯 | 黑色块移动后仍隐藏，按记忆选择与跟踪，满杯后统一验证。 |
| 凝固原料与配方杯 | 配方所需原料可能在凝固层，结合现有免费融化与先处理可动部分的选择。 |
| 颜色解锁候选与配方杯 | 可讨论解锁取得原料或容器；整杯配方何时触发其他机关须另定，不自动替换候选单色开锁规则。 |

目标杯的特殊接水规则独立于原料瓶之间的规则。原料瓶继续沿用所属玩法的取顶、匹配和移动量；目标杯每次接收多少份尚未确认。候选建议是每次只接收最顶一份，无论显色还是黑色，让每次选择对应一个配方位置，避免显色连续段一次填入多格；该建议不改变原料瓶之间已确认的显色连续倒水、黑色一次一份。

完成目标建议以目标杯匹配为准，其余原料不要求全部成为满杯单色，尚待确认。原料取出量与目标容量仍须守恒：用掉部分颜色后，剩余原料未必能按普通满杯单色要求收尾。制作时必须按目标杯只能倒入、原料所属玩法和实际配方求解，并完整回放；不能直接把原有普通题的可解证明用于配方题。所谓跨玩法穿插，是复用这类关卡规则与表现，不能承诺向任意进行中的棋盘临时插入任意配方都可完成。

配方记忆与原料记忆是不同负担：可先让配方持续可见，只隐藏少量原料；另一变体让原料可见，只要求记住配方；后续再组合两者。长配方还会增加取料操作和目标杯可读性负担，不能只按色数推定等级。

满杯结果正确则完成该配方题。用户确认目标杯不能倒出与系统撤销不矛盾：撤销回退之前的动作，不是让目标杯获得主动倒出的能力。满杯自动揭晓不能取消撤销，答错后仍可撤销装入动作；沿用揭晓后颜色保持公开的原则，不因撤销重新遮黑。揭晓前撤销则按当前尚未公开的信息状态回退，不额外揭示答案。

答错后的结果界面与重新挑战流程仍待明确，不能直接套用前文万能块继续普通整理的完成目标。若判断当前状态能否继续完成，须使用配方目标和实际允许的移动规则；可解性判断只影响相应继续入口，不限制玩家使用通用撤销，也不能要求先证明可解才允许回退动作。

接下来优先明确目标杯的一次接收量、答错后的结果界面与重新挑战、配方是否持续可见，以及其余原料是否参与完成条件，再验证少量短配方题和大杯布局。穿插频率与正式规模在规则验证后决定。

### 调色实验室与成果呈现：当前内部试验规则

2026 年 10 月 9 日，用户批准把调色小样接入实际应用。先通过“设置 → 开发工具 → 调色试验”体验六题；只有显式 `EXPO_PUBLIC_INTERNAL_TOOLS=true` 的内部构建显示。首页仍按经典排序、颜色记忆组织，Levels 在经典内部。调色将来的公开入口、主推顺序、千关插入方式和正式题量保持待体验后决定。

151 调色实验室是一个玩法；152 花朵、彩虹杯与未来作品是它的成果模板，不拆成新玩法或多个首页入口。原料可直接从瓶顶取得，不要求先整理全盘。埋住时才在普通瓶间周转。目标全部可见，空调色杯时自由选择未完成目标；已倒入原料后锁定该目标，直到清空或撤销。

- 普通原料瓶容量四份，顶部连续同色按余量转移；调色杯容量两份，每次倒入一份。两份自动混合，只有颜色身份与两份液量均符合当前目标才自动收集、清空调色杯并选择下个未完成目标。完成全部目标即结束，不要求用尽原料或将剩余原料整理成整瓶。
- 原料为红、黄、蓝、白。等量游戏配方为红黄→杏橙、黄蓝→鼠尾草绿、红蓝→丁香紫、红白→玫瑰粉、蓝白→晴空蓝、黄白→奶油黄；同色相加不改色。这是经过选色的确定游戏规则，不宣称完整模拟物理颜料。验收依赖稳定配方／颜色 ID，不依赖 RGB 距离。
- 一份加一份始终得到两份，保存每份原料的稳定身份与成品批次。错配留在杯中，可免费撤销，也可按同色／余量规则倒回普通空瓶或兼容瓶；生成色暂不允许再次调配。同色原料混合仍是该原料。没有自动丢弃、补料或失败扣费。
- 一次撤销回退最后一次玩家倒水，以及它触发的混合、自动收集和完成状态。选择目标不额外占撤销步骤；重来恢复当前题全部原料。有效成功记录保存目标、两份原料身份及实际交付顺序；撤销的成果不进入作品。
- 全部目标完成后，按照有效成功调色的顺序逐色注入可复用作品。花朵用真实目标色表现花瓣、叶脉、花心与明暗；彩虹成果杯用模板确定色带位置和玻璃高光。玩家不用手工找区域填色，也不用按最终色带顺序调色。多个同色花瓣是表现复用，不重复消耗原料。
- 收集、完成与保存先提交，倒水、短暂混合与约三秒的作品注色只读取结果。可直接显示完整作品；返回、撤销、重来、切后台、改变窗口或减少动态效果均取消表现，恢复真实局面。重新进入已完成局面不自动重播。

这里的彩虹杯是**成果展示杯**，不是前文的**有序现场目标杯**：后者是逻辑容器，倒入顺序影响结果，只接收不能主动倒出，但系统撤销始终可用。两种产品概念都保留，本批六题只实现无序调色与成果展示，不混入黑色盲配。

通用实现分为原料份额／批次、普通容器与调色容器、稳定配方表、目标验收、有效交付记录及只读作品模板。玻璃外观独立于容器角色；经典十一色表保持原样，调色渲染传入独立配色和辅助符号。可扩展更多配方与作品，无须复制规则或为每种颜色绘制瓶子图片。自由比例、三色混合、成品再次混合及 256 色库仍未实施。

调色会话在玩家 SQLite 的四张 `mixing_trial_*` 表保存，和主线／记忆／钱包隔离，共用串行事务队列。按稳定题目 ID 恢复当前局面、目标选择、交付顺序及最近 256 步撤销；验证份数、来源、批次和历史合法转换，损坏显示错误而不清库。没有迁移、旧原型导入、主线奖励或付费限制。当前内部试验新增文案为中英双语，其余系统语言暂回退英语；正式推广前再完善其余十九种语言。

### 扩色与成果精细化：本轮问题及设计建议

用户认可调色方向可做，但指出当前原型的基础色与平涂作品不足以体现创造感，要求解决丰富配色、整理辨识、成品精细度与制作／游玩时长之间的关系。下列为下一轮设计建议，不把 256 色、比例调色或复杂成果美术视为已完成或已冻结规格。

颜色应分开考虑全局配方库、单题参与的逻辑颜色与作品的光影层次。现有十一色是经典整理的固定区分色，不是调色玩法只能使用的全部结果色。可先设计几十种经过美术校准的成品色，后续扩至更多；单题只选少量容易辨认的原料与目标，不因全局有 256 个配色就让同屏出现 256 种相近液体。

建议先试红、黄、蓝与白等清楚的原料，补充粉色、浅蓝及柔和生成色；比例、生成物再次混合、是否引入黑色原料须另行设计，不直接扩大本轮两份调色杯规则。配方输出有稳定逻辑身份与确定液量，不能用显示 RGB 是否相近替代验收，也不能把当前十一色任意混合就假定必然漂亮。普通整理匹配逻辑身份，目标提供名称、色样及可查看的配方辅助，避免把新玩法变成细微色差测试。

屏幕色值插值与颜料混合并非同一种规则，相关原理可参考原作者的[颜料混色研究](https://scrtwpns.com/mixbox.pdf)。建议首期使用经过校准的确定游戏配方，不宣称完整模拟真实颜料；将来再评估更自由的混色模型及其制作成本。现有绘制需由固定色表扩为可传入配色，只为当前实际出现的颜色准备渐变；无需为每种成品色制作一套瓶子图片，性能仍须按实际移动端实现验证。

成果建议采用精细的可复用模板，而非继续停留在平涂单花纹。每件作品仍只需要少量关键配色，例如花瓣粉、叶片绿、花心黄；模板再依据这些真实成果色呈现花瓣的明暗、叠压、细脉、透明边缘，以及玻璃折射与高光。光影层次不是新增配色任务，也不能把玩家实际调出的主色偷偷替换成另一种作品颜色。若深浅配色本身影响作品风格，可把少量关键深浅色明确列为任务，而非要求逐块调出所有阴影。

花瓣与叶片的重复结构、区域遮罩、注色路径和光影可复用，先把一朵花与一个彩虹杯做到值得观看，再变化布局和配色，不以每关制作全新插画扩量。玩法操作量按配色任务和自然取料需要控制；成果逐色注入只重放有效贡献，不重播全部整理历史。下一版应比较丰富实际结果色与精细作品是否增加满足感，同时观察整理负担和庆祝等待，不由画面颜色数量直接决定题目时长。
