# 经典关卡特征算法与题型分布建议

更新日期：2026 年 10 月 8 日。特征模型 `classic-features-v1`，覆盖建议 `classic-coverage-proposal-v1`。

本轮将[创意库](gameplay-ideas.md)第 1–20 条中的可计算部分接入离线制作算法，并按用户反馈重新筛选千关。现行内容为 `mainline-1000-v5`，编排配方 `thousand-mountain-v1`；规则、存档 schema 和 `human-decision-v1` 难度公式保持原状，关卡布局及编号对应已重新编排。

现行采用每 20 关一个主峰、第 10 关一个次峰，峰后明确回落，各轮高峰逐渐升高。完整目录保留波次角色和题型标签，全部经过独立复核。结果、曲线、逐轮分数和不足见[千关重新筛选与节奏评价](level-selection-evaluation.md)。下面的首次覆盖比例仍是审阅参考，早期“约 50% 难度”仍是待真人校准的体验目标。
## 已实现的制作链路

`src/game/levelFeatures.ts` 提供独立特征分析，不依赖界面或存储；`src/game/featureDistribution.ts` 汇总分布、相邻特征相似度和建议缺口。新候选制作脚本 `scripts/mainline-candidates.ts` 在原有求解与评级通过后附加 `features`，候选生成阶段不依这些标签自动淘汰；`waveSelection.ts` 与 `mainline:replan` 选择具备完整特征及备用瓶证据的候选，按角色评分并优化相邻变化。

现有千关通过 `npm run mainline:features` 统一分析。完整 JSON 和逐关 Markdown 报告保存在本地 `builds/level-features/`，不进入手机运行包。报告绑定目录 ID、原始目录 SHA256、关卡结构键和探测预算，按难度档、精确分数、颜色数、十关波次和五十关阶段汇总。手机不执行新特征搜索。

标签可以共存。主类型只用于浏览，按固定优先级选择一个；不能将它解释为唯一解题方法。新候选的 `features` 是制作辅助信息；选择结果保存轮次、角色、主类型及标签，完整分支证据留在绑定目录哈希的离线报告。生产独立重算标签后才能接入题库。

## 证据范围

| 证据 | 能支持的判断 | 边界 |
| --- | --- | --- |
| 开局结构事实 | 色层交替、连续色块、底色重复和颜色分散程度 | 不单独证明需要某种策略或有趣。 |
| 参考路线观察 | 准备动作、中转瓶复用、部分接收及露出底色 | 只描述这条路线，不证明所有解法必须如此。 |
| 原有已审计选择证据 | 首步、约三分之一、约三分之二处的选择后果 | 来自原人类代理的规范化最短路线，不能直接映射到另一条路线的同下标局面。 |
| 新增精确分支探测 | 指定前段或收尾局面的死路、最短后续距离与绕路成本 | 只针对观察点；预算不足为未知。 |
| 原有规划级证据 | 小棋盘仍需要较高的模型规划级 | 是指定策略的代理，不是玩家实测难度。 |

新增探测先独立求观察点的剩余最短距离，再逐一求不同后继的最短距离。`regret = 1 + 后继最短距离 - 当前最短距离`；多出至少 3 步视为明显绕路，完全穷尽且无解才记死路。已找到的路线完整回放；未知分支保留原因，不计为死路或安全。

探测去除等容量瓶位置互换造成的相同后继、没有实际变化的动作和立即退回上一步的状态。可解分支保留完整后续路线，方便人工查看。前段和收尾任一观察未完成时，主类型显示“观察证据未完成”；其他已有证据的标签仍保留。

## 前段与收尾观察点

当前主线开局装水瓶均为满瓶，第一步只能倒入空瓶。因此不能用第零步的“合并是否有风险”识别反直觉合并。

新增前段观察点沿 `content.solution` 搜索：在前约三分之一段内，找到第一次存在真实合并机会的局面。真实合并用总连续颜色段数减少来判定。该点若有产生合并、却导致死路或至少 3 步绕路的选择，就标为“前段表面进展有风险”。这只是反直觉的结构代理，仍需玩家判断该动作是否确实有诱惑。

收尾观察点为 `路线长度 - max(3, ceil(路线长度 / 5))`，下限为零，通常位于后约五分之一处。短题的观察点可能仍在较早位置；标签不等于严格的后段风险峰值。没有标记也不证明其他收尾局面没有风险。

## 内部标签与判定

| 标签 ID | 中文标签 | 判定条件 |
| --- | --- | --- |
| early-deception | 前段表面进展有风险 | 前段完整检查中，存在减少颜色段却造成死路或至少 3 步绕路的动作。 |
| early-risk | 前段观察点后果分化 | 前段完整检查中，至少一个动作造成死路或至少 3 步绕路。 |
| opening-risk | 首步后果分化 | 原代理第零步观察中存在死路或高成本绕路。 |
| multiple-safe-openings | 多个低代价首步 | 原代理至少两种不重复首步能在额外不超过 2 步的范围内完成。 |
| repeated-decision-risk | 多个观察点有风险 | 原代理至少两个观察点的风险值达到 0.25。 |
| midroute-risk | 中段观察点有风险 | 原代理非第零步观察中存在死路或高成本绕路。 |
| space-tight-route | 参考路线中转空间紧张 | 至少四分之一的倒水前局面没有整只空瓶。 |
| space-reuse-route | 参考路线空瓶多色复用 | 同一瓶在不同空瓶状态下接收过至少两种颜色；追加到非空瓶不算新用途。 |
| preparation-chain-route | 参考路线连续准备 | 连续至少两次倒水未减少总颜色段数，且不是纯瓶位互换。 |
| partial-transfer-route | 参考路线部分接收 | 转移量小于来源顶部连续同色段，因目标剩余容量而截断。 |
| bottom-release-route | 参考路线露出单层底色 | 移走异色顶部后，来源只剩一份底色。 |
| late-risk | 收尾观察点有风险 | 收尾完整检查中存在死路或至少 3 步绕路。 |
| small-board-planning | 小棋盘较高规划代理 | 总瓶数最多 7，原规划级至少 5。 |
| alternating-start | 开局交替色层 | 至少一瓶为四层 ABAB，且 A 与 B 不同。 |
| adjacent-block-start | 开局连续色块较多 | 初始相邻同色对数占装水瓶相邻层位置至少四分之一。 |
| repeated-bottom-start | 开局底色重复 | 初始装水瓶之间至少有一种底色重复。 |

路线证据附关键动作下标、准备链位置、复用瓶 ID 和颜色等。下标从零开始，表示倒水之前的局面。结构指标还保留四层四色瓶数、底色种类数和每色跨瓶数量。

主类型的浏览优先级为：观察证据未完成、前段合并诱惑、连续准备、空间周转、收尾选择、宽松多开局、多段风险、其他整理。空间周转要求路线无整只空瓶比例至少 0.35 且存在多色空瓶复用；宽松多开局要求至少三个低代价首步且原首步没有危险选择。“其他整理”是兜底分类，不表示题目容易。

## 波次与阶段建议

实施状态：已采用 20 关主峰与 10 关次峰的组合方案，原 `thousand-ramp-v1` 已由 `thousand-mountain-v1` 替代。下面保留节奏设计的理由与周期对照，现行数值以[制作配方](production-plan.md)为准。

### 体验目标：有挑战的高峰与清楚的缓冲

用户当前感觉整体难度偏弱，而且从第 1 关到第 1000 关的上升过于平滑。下一版同时解决两件事：提供真正需要思考的高峰题，以及让高峰之后出现可感知的放松。重新排序可以改善节奏；提高高峰的实际挑战还需要更强的候选题和真人试玩。

期望节奏为：**爬坡 → 高峰 → 明显回落 → 恢复信心 → 再爬坡 → 更高的高峰**。每 10 或 20 关形成一轮，较长范围内高峰逐渐升高。谷底可随玩家熟练度缓慢抬高，但每轮仍须相对上一座高峰明显降低，不能让后段连续维持高压。

前三关保留基础教学。早期第一轮正式挑战就应让玩家体验到“半山腰”或更高的难度，即用户提出的达到预期挑战范围约 50% 或更高的目标；不将高难体验全部留到几百关以后。这是相对于预期挑战范围的体验目标，尚未定义统一尺度，不能直接换算成 `human-decision-v1 ≥ 50`，也不能按当前题库最高分的一半机械选题。

### 两种待比较的周期

下表是讨论时的两种角色草案。现行实现每十关先两关缓冲，再五关爬坡、两关蓄势和一关挑战；每二十关的后一个挑战为主峰。首轮前三关教学单独处理。

| 周期 | 缓冲与恢复 | 爬坡 | 高压与高峰 | 下一轮衔接 |
| --- | --- | --- | --- | --- |
| 10 关 | 第 1–2 关 | 第 3–7 关 | 第 8–9 关蓄势，第 10 关到峰 | 第 11 关明显回落，进入新一轮。 |
| 20 关 | 第 1–4 关 | 第 5–14 关，可有小起伏 | 第 15–19 关逐渐加压，第 20 关到峰 | 第 21 关明显回落，留出更长缓冲。 |

10 关方案反馈更频繁；20 关方案给学习、蓄势和恢复更多空间。20 关方案也可保留第 10 关为次峰，第 20 关为主峰，但需实测是否把缓冲挤掉。现行选择 20 关主峰方案，并保留十关次峰；后续仍可通过连续试玩评估周期长度。

爬坡内部允许小幅起伏，不要求每一关的分数都比前一关高。各轮可以采用不同坡形，例如前段缓升、后段陡升，或先经历一个次峰再冲主峰。先比较少量清楚的坡形，避免无规律跳跃。玩家应能感受到积累、挑战和释放。

### 将题型安排到波次角色中

| 角色 | 选题偏好 | 人工审阅重点 |
| --- | --- | --- |
| 缓冲与恢复 | 熟悉思路、较少连续关键决策、容易看见进展；可换底色和色块结构 | 过峰后确实轻松，仍有完成感，避免机械重复。 |
| 爬坡 | 逐步加入准备动作、空瓶用途切换、中段选择，每次引入有限变化 | 能把前面学会的思路用到新局面，压力逐渐增加。 |
| 高压与高峰 | 有清楚巧思的反直觉选择、较长准备链、多阶段决策或特点组合 | 难在判断和规划；想通后能理解原因，解题时间增加不能只来自操作变多。 |

高峰题不能仅凭颜色更多、瓶数更多、参考路线更长或标签更多入选。现有 16 类标签帮助定位候选，精确选择后果和规划证据帮助审阅，真人体验决定是否形成有效挑战。参考路线上的准备链仍不等于必要策略；需要时补充约束搜索证明。

同一思路可在缓冲段以较容易的形式复现，在高峰段组合使用。相邻关尽量改变关键思考方式；“连续同主类型尽量不超过三题、减少高相似度邻接”保留为软偏好，允许有目的的短教学组。全库覆盖范围与各角色的分布分别统计，不能把稀少标签平均摊到每一段。

### 对现有制作配方的影响

筛选前的 `thousand-ramp-v1` 已有每十关一个挑战峰，但普通关整体按代理分升序编排，挑战至少高出本轮普通题 2 分，后段至少高出 5 分。这能形成小波动，却没有保证峰后有明显缓冲，也没有证明这些分差能被玩家感知。

现行编排已允许跨波次普通关回落，改为波次内爬坡与跨波次高峰逐渐升高。每个挑战至少高于前九关 5 分，峰后两关至少回落 12 分，主峰至少高于次峰 4 分。五十关阶段均值只查看整体走势，不用来压平山峰；阈值为暂定制作标准，待真人校准。

现行生产校验、编排、完整目录导入、运行包验证及测试已同步至新配方，没有在原版本名称下放宽约束。若调整难度公式，也需升级评级方法并独立重算。规则、开局质量、可解性、来源重构、完整回放、完整低策略证据和全局结构去重继续作为验收条件。

每完成 20 道主线还有一道凝固副关卡，节奏评估应覆盖玩家实际经历的“主线高峰 → 副关卡 → 下一轮”。副关卡可能延长压力，需要分别试玩凝固与融化后的体验，避免预定缓冲被额外挑战抵消。本方案暂不改变副关卡出现位置、挑战关奖励或其他游戏行为。

### 下一版选关报告需要显示什么

每题附波次编号、波次角色、题型标签及其证据。每轮显示峰值、谷值、峰谷幅度、峰后回落、与上一轮的高峰差，以及爬坡中的变化；先采用现有代理分描述，再与试玩结果对照。内部角色标签服务于制作，不新增玩家界面标签。

真人试玩记录独立完成情况、思考用时、撤销与提示使用，并询问高峰是否值得挑战、回落是否带来恢复感；这些指标共同解释体验，不把单个时长或提示次数直接当作难度。按五十关检查高峰走势、缓冲效果、题型覆盖和相邻重复。

若候选不足，分别报告“缺少足够强的高峰题”和“缺少合适的缓冲题”，再定向筛选或构造。现行算法已有暂定峰谷目标、增长曲线与周期阈值；它们与早期 50% 的体验尺度一起接受试玩校准。
