# 通用关卡核心

更新日期：2026 年 10 月 6 日。

目前已实现多色、多瓶模型、普通倒水规则、不可变会话、通用求解器和 JSON 编码解码，以及[带 seed 的生成与内容验证工具](generation.md)。现有四瓶演示使用这些模块，绘图与动画继续使用已经通过真机试玩的方案。难度评分、自由游玩、每日题、机关与进度保存仍在后续范围。

## 数据和规则

逻辑颜色是稳定字符串，与 RGB 无关；jade、coral、amber、azure、violet 是当前主题的五种映射。核心允许其他合法颜色 ID，但实际显示前必须有主题映射；当前界面只显示原来的青绿和珊瑚红。新增三色的真机辨识尚未验证。

LevelDefinition 保存格式、规则、关卡 ID、统一容量、颜色目录和带稳定 ID 的瓶子数组。数组顺序对应画面和回放位置，各瓶液体从底到顶保存，一个数组元素代表一层。容量放在关卡层，所有瓶子共享，避免模型看似支持不同容量而完成规则无法解释。

工具输入边界为 2–16 瓶、1–12 色、统一容量 1–8；这些是资源保护边界，不是首版内容规模承诺。纯玩版内容仍优先普通四层瓶、两至五色；当前绘图和布局仍限四层四瓶。不同容量混用、固定底座、隐藏层和解锁不在当前规则中。

每种颜色的总层数必须等于统一容量。完成条件为所有非空瓶均满且单色。关卡或外部棋盘在进入会话、求解或回放前检查数量与引用；合法格式不代表有解。

```json
{
  "format": "bottle-harmony",
  "version": 1,
  "rules": "water-sort",
  "id": "example",
  "capacity": 4,
  "colors": ["jade", "coral"],
  "bottles": [
    { "id": "left", "layers": ["jade", "jade", "jade", "coral"] },
    { "id": "right", "layers": ["coral", "coral", "coral", "jade"] },
    { "id": "spare-a", "layers": [] },
    { "id": "spare-b", "layers": [] }
  ]
}
```

来源顶部最大连续同色段，只能进入空瓶或顶部同色瓶；转移量取连续段长度和目标剩余容量的较小值。移动过程中不混合颜色、不自行切分成任意少量。规则函数接受显式容量；调用者必须使用该关卡的容量，不依赖四层默认值处理其他容量。

## 会话与表现接口

createSession 复制并冻结关卡和棋盘。moveSession 返回新会话与事件，事件包括前后棋盘、来源/目标 ID、索引、颜色和层数。拒绝操作返回 null，不新增历史。undoSession 和 resetSession 免费、无限制；没有历史时撤销返回原会话。

状态分为 playing、stalled、solved。stalled 仅表示没有当前合法移动，不表示已运行完整求解，也不退出或清空棋盘。整关完成后停止接受新倒水，但仍可撤销和重开；途中单色满瓶不额外锁定。

界面先提交新会话，再播放事件。动画结束只释放交互；切后台直接显示已提交状态。演示一步按当前局面重新求解，分段执行并在各段之间让出 JS 线程；切后台或卸载时取消搜索，旧搜索结果不能再触发倒水。

## 求解与可替换接口

createSolver(board, options) 返回 SolverTask；调用 step(maxExpansions, sliceMilliseconds) 推进搜索，未结束返回 null，结束返回结果。cancel() 释放搜索数据。solveBoard 是供制作工具和测试使用的同步包装；手机应采用分段入口。

| 结果 | 含义 |
|---|---|
| solved | 找到最短合法路线；通过 replaySolution 验证真实瓶子索引下的每一步 |
| unsolvable | 完整搜索结束，确实无解 |
| limitReached | 状态数、活跃搜索时间超限或被取消；尚未证明无解 |
| invalid | 输入棋盘或预算非法，附原因 |

实现是广度优先搜索，合并普通等容量瓶交换产生的对称状态。状态键将颜色映射为内部字符并排序瓶内容，实际节点仍保留真实顺序和前驱操作，因此恢复的路线直接可回放。已展开节点的液体数组及时释放；不在每个节点复制整条路径。仅合并具有相同规则角色的普通瓶，不适用于未来固定瓶或机关。

默认预算为 30,000 个不同状态、250 毫秒活跃搜索时间。统计访问状态、展开状态、合法转移、最大待展开队列和活跃耗时。暂停期间不计活跃时间。状态预算间接限制内存，当前没有独立的精确字节内存上限；垃圾回收、调度和单次分配可能超过目标切片时长，切片是协作调度而非硬实时保证。

深度指标为倒水操作次数，每次最大连续段转移算一步。只有 solved 结果声明最短；搜索统计不等于玩家难度评分。当前没有四档评价器。

## 编码与导入

encodeLevel 输出可读 JSON，decodeLevel 检查格式版本、规则、唯一 ID、颜色引用、容量和总量，并返回冻结的独立副本。输入上限 32,768 个字符；拒绝未支持字段和规则，预发布阶段只维护一个当前格式。

关卡 JSON 只编码实际布局，不编码会话或历史。生成来源、seed、候选编号、配置和参考解法放在单独的内容记录中，见[内容池格式](generation.md)。原始关卡导入仍需要求解；内容记录导入必须重建候选并完整回放解法，不能因为 JSON 有效就发布。

## 验证与性能基准

```sh
npm run typecheck
npm run lint
npm test
npm run benchmark:solver
```

核心与内容工具共 25 个测试。核心覆盖规则与动画几何，以及模型/JSON 非法输入、任意逻辑颜色、不同统一容量、不可变会话、撤销完成、卡住局面、有解/无解/超限/取消、分段一致性、五色回放。另以未合并对称的完整搜索对照全部 90 种三色两层排列，核对可解性和最短距离；新增生成验证覆盖内容可重现、去重、拒绝策略和文件工具。

以下为本机 Node.js 24.20.0、Apple M1、macOS arm64 的结果。每组先预热，再测五次，预算 30,000 状态/250 毫秒；不是手机或 Hermes 的性能结果，也不是所有同规模题的性能保证。

| 固定样例 | 活跃耗时中位数 | 搜索结果 | 访问状态 | 步数 |
|---|---:|---|---:|---:|
| 两色四瓶演示 | 1.4 ms | 五次均有解 | 67 | 7 |
| 四色六瓶循环排列 | 18.9 ms | 五次均有解 | 980 | 13 |
| 五色七瓶循环排列 | 48.8 ms | 五次均有解 | 2,479 | 16 |
| 八色十瓶压力排列 | 250.0 ms | 五次均达到时间预算 | 首次 12,133，随运行变化 | 未验证 |

基准逐切片采样 Node 堆使用；五色样例最大采样增量约 15.6 MiB、压力样例约 33.5 MiB，包含临时分配，不是准确峰值或手机内存。压力样例最大切片约 12.9 ms，说明目标 4 ms 不能代替实测。脚本输出各次原始统计和环境，找到路线就再次完整回放；压力样例不会被当作可游玩内容输出。

## 手机测量和 C++ 决策

下一轮在 iPhone 和低端 Android 的 Release 构建中复用相同排列和预算，记录搜索总耗时、每个切片最长耗时、内存和动画流畅度，再加入更杂乱的两至五色样本。已通过的视觉演示真机验收不能代替这次通用搜索测量。

先根据结果改善状态编码、分配和搜索策略，以及制作工具预生成内容池。若仍无法满足设备预算，再用 C++ 实现同一个任务接口：普通数据输入、分段/取消、同样结果状态和统计，最后由 TypeScript 规则回放检查。C++ 也需要避免同步阻塞界面，并不能消除状态空间增长。

目前没有引入 C++ 或原生依赖。带 seed 的候选生成器与内容验证工具已完成，普通四层、两至五色；每个接纳题通过求解和回放。下一项建议以人工校准题集建立四档评价，最后接动态布局和连续游玩。
