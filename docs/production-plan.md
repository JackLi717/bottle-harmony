# 千关主线与人类难度代理模型

更新日期：2026 年 10 月 7 日。当前制作配方 `thousand-ramp-v1`，难度模型 `human-decision-v1`，内容 ID `mainline-1000-v3`。

## 游戏边界

主线固定 1000 关，按序解锁；已通关关卡可重玩，重玩局面和待完成主线局面分别保存。撤销与重来免费；每个新主线关卡的第一次一步提示免费，之后每次消耗一张提示券。首次通关普通关获得一张提示券，每十关挑战获得两张，最多持有五张；重玩不发奖，提示券不足时仍可免费撤销或重来。每十关一轮，前九关是普通题，第十关是本轮挑战；每五轮组成一个仅用于制作的五十关阶段。玩家界面仍以关卡号为主，没有章节、额外玩法或难度选择。完成第 1000 关后不产生第 1001 关。

同一局最多 11 色、12 瓶，四层容量，一个或两个空瓶。所有主线初始瓶中，同一种颜色最多两层，包含不相邻层；因此没有开局完成瓶。按新分数属于 D3/D4 的关卡，每个初始装水瓶至少三色。该限制只用于制作和导入，不限制游玩中正常合并。前三关保留两三色教学，其他关卡至少四色。所有参考解法不超过 60 次倒水。

## 为什么改评价方法

旧 `planning-depth-v1` 和 `planning-load-v1` 把指定策略的等级作为排序主项。它能证明低级策略的失败反例，却没有直接衡量玩家眼前多个可选倒水中，错误选择会导致什么后果。原千关还按旧等级定死配额，使后段同级题之间不一定逐步变难。旧证据仍保存在完整目录供内部对照，见[难度校准](difficulty-calibration.md)。

新模型是**人类难度的结构代理**，不是玩家实验结果。它衡量需要分辨危险选择的负担，并保留规划、空间、颜色辨认和操作长度因素。方法版本固定；不能用同一版本名悄悄更换权重。

### 决策后果

制作时先独立求最短完整路线，按精确结构键规范化瓶位和颜色名，取路线开头、约三分之一和约三分之二处三个观察点。每点枚举不同的合法倒水后继局面，略过明显的立即撤销以及不必打乱的已完成瓶，再用完整求解器逐一求其剩余最短路径。相对原路径的额外倒水 `regret` 不超过 2 次视为可恢复选择；多出 3 次以上是高成本绕路；确证无法完成为死路。若错误动作表面上减少颜色段数，风险权重增加。相同状态只算一次，避免空瓶对称和瓶位差异虚增选择数。超出求解预算，整题分数为 unknown，不当作高难或无解。

### 固定 0–100 分

| 项目 | 上限 | 来源 |
|---|---:|---|
| 规划 | 10 | 旧模型经完整验证的内部级 1–8 |
| 选择风险峰值 | 35 | 三个观察点的危险选择比例，兼顾峰值和均值 |
| 风险反复出现 | 10 | 三个观察点中风险达到 0.25 的比例 |
| 空间压力 | 15 | 单空瓶与最短路线中没有空瓶的状态比例 |
| 视觉规模 | 15 | 颜色数 2–11 |
| 操作量 | 15 | 最短倒水数；30 次左右达到该项上限 |

加权公式与决定后果的精确定义见 `src/game/humanDifficulty.ts`。制作分只对已验证的完整求解结果计算，不使用搜索耗时、机器访问状态数、动画时间或玩家历史。分档为 D1：0–19，D2：20–34，D3：35–54，D4：55–100。分档用于内部内容与已获授权的礼花数量，普通游玩页不显示数字。C06/C07 都是 14 步，新模型能把错误选择后果较重的 C07 排在前面。此对照只提供方向性证据，后续仍需真人盲测检验权重和分界。

## 一千关编排

配方不再指定旧 D1/D2/D3/D4 和八级的数量。先剔除旧池中 150 道低风险、分数集中在 18–30 的题，并加入 150 道经完整求解、开局质量筛查的五色与六色中难度题。所有题目按精确结构去重，保留三道教学题。从整体候选池抽出各轮挑战题，其余普通题按新分数升序排列。每轮前九关的普通分数不下降，第十关高于本轮普通最高分至少 2 分；第 14–20 阶段至少高 5 分。100 道挑战题的分数不下降，最后五轮使用最高分候选。20 个阶段的平均分严格上升，相邻阶段不跳升超过 6 分。由此普通线稳步上升，十关收尾有明显峰值，下一轮回到已上升的普通线。

颜色数仅是柔性制作偏好，不能替代难度分。普通题在早段偏好 6–9 色，中段包括较有决策负担的五六色局面，后段偏好 7–11 色；挑战题不设置颜色偏好。大局面可能容易，小局面也可能难。最终验收读取实际分数和来源，不能只按颜色数或旧标签声称渐进。

当前实题分布为 D1 115、D2 380、D3 409、D4 96。第一阶段平均分 14.90，第十阶段 31.28，第二十阶段 58.92；末关得分 70，最后五个挑战关为 66、67、68、68、70。普通关优先颜色范围内占 845/897 道（不含前三道教学）；其余属于允许的软偏好例外。数字描述当前题库，不作为下一版固定配额。

`src/game/productionPlan.ts` 定义位置、软颜色偏好及分数坡度校验；`scripts/mainline.ts` 构建和独立复核，`src/game/mainlineCatalog.ts` 验证随包完整证据，`src/game/mainlinePlayable.ts` 验证手机使用的精简投影。内容 ID 由 v2 更新至 v3；未发布的旧版本地进度按现有失效存档提示重新开始，没有新增迁移体系。

## 生产和验收

生成器支持 `balanced-shuffle-v1` 和 `layered-shuffle-v1`。每个接纳题保存生成参数、实际局面、结构键、参考解法、旧规划证据、新人类代理证据与固定编号。验证时重新构造来源、完整回放、求最短路线、完整检查低级策略、重算新分、检查 1000 个结构键互异及难度坡度。超过预算即失败，不用不完整报告填缺口。`assets/levels/mainline-catalog.json` 为完整制作包；`mainline-play.json` 是由它严格生成的精简运行包。手机启动只载入后者，不做完整策略搜索；内部调试按需加载完整包。

```sh
npm run mainline:build -- --input assets/levels/mainline-catalog.json --output builds/mainline-v3-catalog.json
npm run mainline:verify -- --input builds/mainline-v3-catalog.json --output builds/mainline-v3-play.json
npm run mainline:audit -- assets/levels/mainline-catalog.json builds/mainline-start-audit.json
npm test
npm run typecheck
npm run lint
```

`builds/` 内的本地候选与报告用于制作，不随手机发布。`mainline:verify` 逐题独立重算后才允许替换两份资产。本次重建与独立复算均为 1000/1000，通过后再次从已安装目录构建得到逐字节相同的完整包。开局审计为 0 个异常关卡，110 项自动测试、TypeScript 和 ESLint 均通过。桌面验证不等于手机手感或性能验证；仍须在设备上做持续游玩、提示时延、渲染和存储测量，结合真实玩家反馈再次校准分数权重。视觉、十五种免费容器外观、倒水交互、礼花与音效均使用既定规则，难度重编排不引入新机制。
