# 千关主线与人类难度代理模型

更新日期：2026 年 10 月 8 日。当前制作配方 `thousand-mountain-v1`，难度模型 `human-decision-v1`，内容 ID `mainline-1000-v5`。

## 游戏边界

主线固定 1000 关，按序解锁；已通关关卡可重玩，重玩局面和待完成主线局面分别保存。撤销与重来免费；每个新主线关卡的第一次一步提示免费，之后每次消耗一张提示券。首次通关普通关获得一张提示券，每十关挑战获得两张，最多持有五张；重玩不发奖，提示券不足时仍可免费撤销或重来。每二十关一轮，第十关为次峰、第二十关为主峰，两段爬坡均有缓冲；仍保留每十关的挑战身份及奖励。每五十关汇总一个仅用于制作的阶段。正式玩家界面仍以原关号为主，没有章节或难度选择；内部构建另有不计进度的全题难度试玩。完成第 1000 关后不产生第 1001 关。

另有用户批准的 50 道凝固目标瓶副关卡，每完成 20 道原主线出现一道，不替换原 1000 道编号。副关卡开局没有整只空瓶，四格空位分散在部分装水的瓶里；指定目标瓶的最底一层凝固，不能倒出，其余规则不变。玩家可免费点火焰融化底层，以较宽松的普通倒水规则完成；重来恢复凝固。每道均在凝固和融化两种状态下完整求解、路线回放，并按含目标瓶身份的结构键去重。此内容用独立目录 `assets/levels/solid-side-50.json`，其首步风险和路线长度仅用于副关卡内部渐进，不冒充现有主线的 `human-decision-v1` 分数。

原主线同一局最多 11 色、12 瓶，四层容量，一个或两个空瓶。所有主线初始瓶中，同一种颜色最多两层，包含不相邻层；因此没有开局完成瓶。按新分数属于 D3/D4 的关卡，每个初始装水瓶至少三色。该限制只用于制作和导入，不限制游玩中正常合并。前三关保留两三色教学，其他关卡至少四色。所有参考解法不超过 60 次倒水。

双空瓶题有 293 关。离线逐题移除末尾空瓶并完整求解后，9 关可解，284 关确证无解，无预算未知；排除两道可单空瓶完成的教学，其余 7 关提供可选的本关备用瓶。第二个以淡化玻璃占据原瓶位，点击瓶身即可免费启用；启用保留已倒水和撤销历史，重来不重新锁定，下一关不携带。重玩局面独立。所有缓冲关均不会默认锁住备用瓶，100 个高峰也按完整评级的原瓶数开局。备用瓶不改变原双空瓶题的生产分数；单空瓶变体不沿用该难度分。名单与内容 ID 绑定，更换题目须重新完整验证。

## 为什么改评价方法

旧 `planning-depth-v1` 和 `planning-load-v1` 把指定策略的等级作为排序主项。它能证明低级策略的失败反例，却没有直接衡量玩家眼前多个可选倒水中，错误选择会导致什么后果。原千关还按旧等级定死配额，使后段同级题之间不一定逐步变难。旧证据仍保存在完整目录供内部对照，见[难度校准](difficulty-calibration.md)。

新模型是**人类难度的结构代理**，不是玩家实验结果。它衡量需要分辨危险选择的负担，并保留规划、空间、颜色辨认和操作长度因素。方法版本固定；不能用同一版本名悄悄更换权重。

### 决策后果

制作时先独立求最短完整路线，按精确结构键规范化瓶位和颜色名，取路线开头、约三分之一和约三分之二处三个观察点。每点枚举不同的合法倒水后继局面，略过明显的立即撤销以及不必打乱的已完成瓶，再用完整求解器逐一求其剩余最短路径。相对原路径的额外倒水 `regret` 不超过 2 次视为可恢复选择；多出 3 次以上是高成本绕路；确证无法完成为死路。若错误动作表面上减少颜色段数，风险权重增加。相同状态只算一次，避免空瓶对称和瓶位差异虚增选择数。超出求解预算，整题分数为 unknown，不当作高难或无解。

### 固定 0–100 分

| 项目 | 上限 | 来源 |
|---|---:|---|
| 规划 | 10 | 旧模型经完整验证的内部级 1–8 |
| 选择风险峰值 | 35 | 三个观察点的危险选择比例，兼顾峰值和均值 |
| 风险反复出现 | 10 | 三个观察点中风险达到 0.25 的比例 |
| 空间压力 | 15 | 单空瓶与最短路线中没有空瓶的状态比例 |
| 视觉规模 | 15 | 颜色数 2–11 |
| 操作量 | 15 | 最短倒水数；30 次左右达到该项上限 |

加权公式与决定后果的精确定义见 `src/game/humanDifficulty.ts`。制作分只对已验证的完整求解结果计算，不使用搜索耗时、机器访问状态数、动画时间或玩家历史。分档为 D1：0–19，D2：20–34，D3：35–54，D4：55–100。分档用于内部内容与已获授权的礼花数量，普通游玩页不显示数字。C06/C07 都是 14 步，新模型能把错误选择后果较重的 C07 排在前面。此对照只提供方向性证据，后续仍需真人盲测检验权重和分界。

## 一千关编排

`classic-features-v1` 已用于重新筛选与编排。完整目录逐题保存轮次、波次角色、主类型及多标签；关键局面和分支证据保存在离线报告，不进入手机精简包。标签未知不作未命中，路线观察不作必要策略证明。题型覆盖范围是审阅用软建议，没有固定配额。算法定义见[经典关卡特征与选关策略](level-feature-design.md)，实题结果见[重新筛选与节奏评价](level-selection-evaluation.md)。

现行 `thousand-mountain-v1` 为 50 个二十关周期。前三关保留教学，普通关允许跨波次回落；第十关为次峰，第二十关为主峰。主峰与次峰两条序列分别不下降，主峰至少高于本轮次峰 4 分；每个挑战峰至少高于前九关最高分 5 分。峰后两关至少回落 12 分。爬坡内允许最多 2 分的小回落，按角色目标选题，不再要求全局普通关递增或各类高峰混在一条递增序列。整数代理分允许几轮持平，较长范围内高峰上升。

第一个周期的次峰目标 40、主峰目标 45，最后一个周期分别为 69、74；缓冲目标从 18 缓慢抬升到 41，第二段缓冲增加 2 分。挑战在目标以上 3 分内选择，其他非教学题与角色目标相差最多 8 分。前三关之外第一段练习目标另定为 14、20、24、28、32、35，逐步接入首个挑战。目标是暂定制作尺度，用户的早期“半山腰／50%”体验尚不能换算成该代理分。

高峰至少具备规划级 4；目标低于 55 时选择风险峰值贡献至少 5 分，其他高峰至少 8 分，以免只靠颜色数和操作量入选。缓冲限制选择风险峰值贡献不超过 12 分、风险反复贡献不超过 3 分，参考路线没有两步连续准备；双空瓶缓冲还须证明移除空瓶后无解，保证实际开局不会默认锁住备用瓶。颜色数只是软偏好：缓冲偏好四至七色，其余非教学题可用四至十一色，不能代替难度证据。

从 1760 道完整候选中选出千题，原布局保留 574 道，另选 426 道；本轮新增生成 420 道六色中段与八九色高峰候选。先安排稀缺高峰与缓冲，再用可调整已分配候选的匹配检查爬坡供给，最后交换兼容位置以减少相邻重复。这是有约束的制作选择，不宣称全局最优。来源为 526 道全打乱题、474 道一层底色混排题；不使用固定双层底色生成题。所有题目精确结构互异，所有瓶内同色最多两层，高档每个装水瓶至少三色；没有全瓶底层成对的开局。

当前 D1/D2/D3/D4 实际为 8/315/510/167，不作为固定配额。平均分 42.051，挑战峰均分 57.04，第 10、20 关分别 40、45 分，末关 76 分。实际峰后回落最小 17、平均 26.21 分。五十关阶段均分从 25.84 升至 55.14，只用于查看长期走势，没有沿用旧阶段均值增幅硬约束。

`src/game/productionPlan.ts` 定义角色目标与峰谷校验，`src/game/waveSelection.ts` 执行选择和相邻优化，`scripts/replan-mainline.ts` 输出完整目录及绑定哈希的特征报告。完整目录导入与手机精简包使用同一配方检查。`scripts/mainline.ts verify` 另外独立重算原规划、人类代理及新特征标签。内容 ID 更新至 v5；现有内容绑定会让旧未发布进度从第一关建立新记录，不增加迁移或历史题库。

每二十关后的凝固副关卡保持现有内容与位置，其规则与分数尺度不同，不混入主线曲线。实际体验是主峰、副关卡、下一轮缓冲；仍需把凝固与融化版本一起连续试玩，检查压力是否过长。
## 生产和验收

生成器支持 `balanced-shuffle-v1`、`anchored-shuffle-v1` 和保留作历史来源验证的 `layered-shuffle-v1`；现行主线只采用前两种。每个接纳题保存生成参数、实际局面、结构键、参考解法、旧规划证据、新人类代理证据与固定编号。验证时重新构造来源、完整回放、求最短路线、完整检查低级策略、重算新分、检查 1000 个结构键互异及峰谷节奏、角色标签。超过预算即失败，不用不完整报告填缺口。`assets/levels/mainline-catalog.json` 为完整制作包；`mainline-play.json` 是由它严格生成的精简运行包。手机启动只载入后者，不做完整策略搜索；内部调试按需加载完整包。

```sh
npm run mainline:build -- --input assets/levels/mainline-catalog.json --output builds/mainline-v5-catalog.json
npm run mainline:verify -- --input builds/mainline-v5-catalog.json --output builds/mainline-v5-play.json
npm run mainline:audit -- assets/levels/mainline-catalog.json builds/mainline-start-audit.json
npm test
npm run typecheck
npm run lint
```

`builds/` 内的本地候选与报告用于制作，不随手机发布。`mainline:verify` 逐题独立重算后才允许替换两份资产。本轮 v5 全部 1000 关的来源、路线、规划、人类代理和前段／收尾标签均独立复核一致，精简包严格匹配完整目录；备用瓶最终审计未知数为零。副关卡内容保持原样，既有 50/50 双状态验证继续有效。桌面验证不等于手机手感或性能验证；仍须在设备上做持续游玩、提示时延、渲染和存储测量，结合真实玩家反馈校准两类题目的难度代理。
