## 一 统计实体与完整性

| 实体 | 定义及唯一性 |
| --- | --- |
| 安装 | 当前玩家 SQLite 的随机安装 ID；仅本地使用，不上传该 ID，不等于自然人、下载或跨重装身份 |
| 应用会话 | 数据库准备完成／进入前台至离开前台；`inactive` 和 `background` 合并为一次离开边界 |
| 棋盘访问 | 实际显示未完成棋盘至离开／后台；同一挑战可有多次访问 |
| 经典挑战 | 实际进入某题至第一次逻辑完成，跨干净暂停、重启和多次有效重来累计 |
| 经典尝试 | 初始尝试及每次有效重来后的尝试；撤销不新建尝试 |
| 记忆尝试 | 观察开始至完成、重来或换题；重来／百题循环为新尝试，第一次自动揭晓只判断一次 |
| 提示请求 | 请求 ID 关联请求、最终结果和执行；重复结果回调只累计一次 |
| 首次体验 | `(mode, level_id, rules)` 唯一首次进入；记录当时内容版本、观察起点及首次完成冻结摘要 |
| 首次完成 | 游戏 `completions` 负责正式完成／奖励；统计事实与其在同一事务形成，统计不负责授予权益 |

正式模式为 `mainline`、`side`、`memory`。经典完成后继续操作为 `post-mainline`／`post-side`，明确选已完成题为 `replay-mainline`／`replay-side`，记忆完成后的操作为 `post-memory`。模式分别统计；内部预览、自动验证和教学示范不进入正式棋盘事实。

不完整的既有局面在新增观察起点标记 `partial`。启动发现未关闭的访问时，保留已提交时间，标记挑战、尝试及首次体验的观察缺口；未结束提示结果改为 `interrupted`。已完整提交的暂停不会仅因重新启动被降级。首次完成后冻结原摘要；撤销最后一步、再完成、重玩或清理明细不改写首通。

回主页、后台、尚未返回、未完成、预算未知均不是失败或卸载。`partial` 不进入完整首次体验的窗口完成率和无辅助记忆分母。正常明细过期不等于观察缺口。

## 二 时间、日期与活跃口径

| 字段 | 计入范围 |
| --- | --- |
| `foreground_ms` | 未完成棋盘可见且前台的实测区间；排除主页、后台、教学示范、完成后的礼花和等待 |
| `blocked_ms` | 上述区间内输入被动画、搜索、覆盖界面限制的并集，重叠原因只算一次 |
| `available_ms` | 经典 `foreground_ms - blocked_ms`；可能包括发呆，不称纯思考时间 |
| `observation_ms` | 记忆初始完整观察的可用时间 |
| `peek_ms` | 记忆主动再次查看的可用时间 |
| `hidden_ms` | 第一次揭晓前的可操作隐藏整理 |
| `cleanup_ms` | 答错揭晓后的可操作显色整理 |
| 总跨度 | 首次进入至完成的墙钟间隔，仅作日历跨度，不当作游玩时长 |

持续时间使用 `performance.now()`，在动作、可见性、输入限制、阶段及前后台边界切片，并约每 10 秒提交检查点。进程间隔不补算；检查点并不保证最多只损失十秒，保存排队或失败会扩大缺口。新增时钟不改变既有计时器契约。

切片保存投影 UTC 结束时间及测量时冻结的 UTC 分钟偏移，跨本地午夜精确拆分；改时区后的新片段使用新偏移。墙钟改变不产生负持续时间。任意系统时钟跳变的独立质量事件尚未完成，日期分析仍受设备时间可靠性限制。

有效游玩日：某模式棋盘累计前台至少十秒，或有一次有效倒水／记忆 Ready／查看。首次有效日为该模式激活日。普通日汇总保留实际本地日／偏移；回访另用激活时冻结偏移记录 `cohort-active`，旅行不会把队列时区改掉。应用打开不替代有效游玩。

D1／D7／D30：第 0 日激活队列中，目标日有有效游玩的安装数／目标日已完整结束的激活安装数。当前本地报告只显示本安装是否回访及是否成熟，不能推断总体留存。GA4 的原生留存使用其自身用户与日期规则，不能冒充本产品严格口径。

## 三 指标目录与计算

所有比例同时给出分子、分母、观察截止、窗口、版本与质量过滤；零分母为未知。没有采集的项目保持待实施，不能用零替代。

| 指标组 | 已实现事实和报告 | 使用边界／尚待补齐 |
| --- | --- | --- |
| 开始与活跃 | 数据准备完成、前后台、首次有效手动倒水耗时、有效日、模式激活与回访、记忆教学展示／完成 | 启动前失败、内容准备请求分母、可交互延迟、恢复成功率尚待专门性能诊断；`app_ready` 仅表示成功准备，不可计算启动成功率 |
| 进展 | 实际首次进入、唯一首通、尝试结果、主线／副关／记忆与重玩隔离、1／3／10／20／100／1000 里程碑（按该模式实际编号） | 记忆编号里程碑不是“完成任意 N 道”的计数；不同关的曝光人群不同，不能直接横比 |
| 窗口完成 | 本地 24 小时／7 日等指定窗口的首次体验完成率、成熟／未成熟／partial／未完成数 | 分母只取完整观察且 `entered_at <= asOf-W`；分子另要求 `completed_at <= entered_at+W`；在线自由表中的完成事件／开始事件之比不是该完成率 |
| 逐题投入 | 首次挑战跨重来的累计时间、尝试和访问；完成冻结、当前未完成累加器、按题长期总和与桶分布 | 未完成者时间不填零；重玩和完成后另列；不根据长停留推断满意或困难 |
| 操作 | 成功倒水、实际提示倒水、撤销、有效重来、查看、融化、备用瓶、完成路线长度 | 撤销不减少累计倒水；无效果操作不算成功；路线与已证明最短路的比例尚未自动报告 |
| 辅助组合 | 全挑战是否曾执行提示、融化、备用瓶；请求／搜索结果／实际执行／资源来源分开 | 重来不擦除曾用辅助；找到路线不等于执行；未知不等于无解；提示与后来完成仅有关联 |
| 卡住恢复 | 无合法动作进入、恢复动作、提醒实际展示／关闭及计数 | 沿用现有检查，无逐步全搜索；完整的逐次卡住到后续完成归因尚待分析扩展 |
| 提示券 | 逐次实际扣券、首通计划奖励／实得／上限截断 | `计划=实得+截断`；奖励事件不再携带累计消耗，避免双计；最终一步扣券与奖励同事务；余额事实以游戏钱包为准 |
| 记忆质量 | 每尝试首次揭晓对错，首次体验／重复，完整无辅助子集，直接 `remembered`／显色 `recovered`，隐藏与显色时间 | 无辅助为完整观察、查看零、实际提示零，允许撤销；请求但未执行不排除；答错后完成不改成记对 |
| 偏好 | 实际设置变更：声音、符号、语言、容器；值有白名单 | 选择量不能证明可辨识性；按款式长期曝光及记忆偏好时长未全面扩展 |
| 数据健康 | 未关闭访问及请求、失败写入恢复后的有界计数、上传待发／过期／丢弃、观察边界与版本 | 无法恢复的启动／写入故障只能从受控设备日志观察；没有接入 Crashlytics；无退出不等于崩溃 |
| 设备性能 | 现有提示与构建诊断继续保留 | 启动、事务排队、帧时间、内存、音频错位需真机 Release 测量，桌面结果不冒充手机证据 |

记忆正确率分别报告 `first_answer_correct/(first_answer_correct+first_answer_wrong)`、重复体验对应比例，以及完整无辅助的 `*_unassisted_correct/(*_unassisted_correct+*_unassisted_wrong)`。粗对错计数含 partial 的描述与完整样本分开。长久摘要按质量、辅助、题目、内容、规则和指标版本分组。

内容校准可按经典 D1–D4、波次角色、阶段、颜色数筛选；这些是离线代理和生产标签，不是玩家验证的难度。后期关只由持续玩家进入，提示使用者也可能本来更困难，不由相关性宣称因果。记忆搭桥行为、个人能力分、偏好练习与真人校准仍属后续工作，未新增产品界面。

推荐／Premium／购买没有实施，因此不发送推荐达标、结算、付费门槛、交易、收入或 LTV 事件。未来随对应功能记录参与／交易自己的幂等账本；自邀和重装参与仍允许，统计不能变成自然人去重或权益凭据。

## 四 本地存储与事务

```text
逻辑接受动作／页面边界 → 模式适配与单调时间切片
                         ↓ 玩家库串行事务
进度／钱包／偏好 + 原有统计 + product-metrics-v1 事实／摘要
                         + 在线分析开启时的 metric_outbox + 修订号
                         ↓ 提交后
                  有界发送器 → 原生 SDK → Google
```

动画、网络和长搜索不进入数据库事务。保存失败保留队首，后续修订不能跳过，原子回滚后按顺序重试；失败计数先有界保存在内存，成功恢复后记录。新增统计 schema 失败不会清库或假装首次启动。

运行仍为只读 `content.sqlite` 和独立可写 `player.sqlite`。闭测已开始，旧的无玩家重建授权不再适用。新表使用 `CREATE TABLE IF NOT EXISTS` 增量建立观察边界；不重置进度、钱包、偏好、教学或安装身份，不增加旧 JSON／AsyncStorage 导入、双写或回退。SQLite 字段中的受约束 JSON 是表内编码，并非第二种持久化技术。

| 表／元数据 | 用途与保留 |
| --- | --- |
| `metric_runs` | 当前挑战累加器及有界已结束挑战；时间、操作、尝试、曾用辅助 |
| `metric_attempts`／`metric_visits`／`metric_app_sessions` | 有界尝试、访问、应用会话与边界完整性 |
| `metric_firsts` | 长期首次进入、首次完成和冻结摘要；唯一键防止重新累计 |
| `metric_summary` | 按模式／题目／内容／规则／版本／质量／辅助／指标／桶的长期计数、总和和直方图 |
| `metric_days` | 按日／偏移／模式／版本的时长、动作、活跃及冻结时区回访标志 |
| `metric_requests` | 请求级结果去重及是否执行；有界明细 |
| `metric_outbox` | 仅采集开启时的新上传事件、开关 epoch、重试次数；非权益账本 |
| `product-metrics-*`／`metrics-activation:*` | 观察版本、开始时间、激活日及冻结偏移 |
| `analytics-*`／`metrics-last-prune` | 环境、开关 epoch、丢弃与独立清理水位 |

时间桶上界为毫秒 `0,10000,30000,60000,120000,300000,600000,1200000,1800000,3600000,+∞`；次数桶为 `0,1,2,3,5,10,20,50,+∞`。保存样本数／总和／桶数；合并兼容桶后报告 P50／P90 所在区间，不能平均各安装中位数，也不能伪装为精确百分位。零值独立成桶。

明细采用最近 30 天和最多 5 万条预算，当前开放挑战／恢复所需数据受保护。共用保存队列按独立水位每跨越 100 修订执行检查，避免其他写入越过整百后长期不清理。首次事实、长期摘要和观察边界不随明细删除。删除行不保证数据库文件立即缩小；磁盘、索引、WAL／SHM 和清理成本仍需设备测量。

## 五 Google 事件契约与交付

统一白名单在 `src/analytics/contracts.ts`，27 种业务事件；最多 25 参数，字段名最多 40 字符、字符串最多 100 字符、数字必须有限。每条带随机单事件 `event_id`、业务时间 `event_at`、应用／指标／构建环境版本。题目事件另带模式、稳定题目 ID、内容／规则、完整性、首次体验及必要生产标签。

| 事件 | 语义 |
| --- | --- |
| `bh_app_ready`／`bh_app_foreground`／`bh_app_background` | 成功准备及前后台边界 |
| `bh_puzzle_start`／`bh_puzzle_visit`／`bh_puzzle_leave` | 新挑战、访问、关闭访问及本片段用时 |
| `bh_attempt_end` | 尝试以重来、完成或明确换题结束 |
| `bh_puzzle_complete` | 一次挑战逻辑完成，结果、正式首通标志、辅助及最终路线 |
| `bh_puzzle_timing`／`bh_puzzle_operations` | 完成挑战累计时间／操作；与访问和动作事件分别分析 |
| `bh_puzzle_action`／`bh_first_action` | 有效语义动作与首次有效手动倒水耗时 |
| `bh_hint_request`／`bh_hint_result`／`bh_hint_execute` | 请求、一次最终结果、实际执行；资源来源明确 |
| `bh_stalled`／`bh_stalled_recovery`／`bh_stalled_notice` | 卡住进入、恢复动作、实际提醒展示或关闭 |
| `bh_credit_change`／`bh_credit_spend` | 首通奖励／截断与逐次实际消耗，互不重复 |
| `bh_memory_answer`／`bh_memory_check` | 首次揭晓及检查结果，不覆盖原对错 |
| `bh_preference`／`bh_tutorial` | 有效偏好变更、教学展示／完成 |
| `bh_active_day`／`bh_milestone` | 冻结激活时区的有效日与正式里程碑 |
| `bh_quality` | 有界技术质量类别与计数，不含自由错误文本 |

不上传本地安装／会话／挑战／请求 ID、完整棋盘、源目标液体记录、原始日志、交易凭据或自由文本；单事件随机 ID 可关联发送重试，但不建立产品自己的跨重装身份。Firebase 原生 SDK 会使用自己的应用实例／安装标识并处理 IP 等网络元数据；不宣称完全匿名、无任何标识或无法形成用户报告。不开启广告 ID、IDFV、SSAID、自动页面上报、广告个性化或广告存储，不设置实名 `user_id`。

按 2026 年 10 月 10 日用户明确决定，支持在线分析的手机／平板首次使用默认开启在线分析，不显示询问弹窗或设置开关；本地统计持续保存。初始化用 `INSERT OR IGNORE` 写入默认值，已有明确关闭选择继续保留，不重置存档、不补传此前历史。只有采集开启且环境为 Production／Test 时才将新业务事件同事务加入 outbox；Web、TV、离线及尚未配置环境不创建上传队列。原生静态默认值继续关闭，启动读回 SQLite 后按保存偏好配置 SDK，因此不会用原生默认开启覆盖用户关闭选择。SDK `analytics_storage` 信号随内部采集状态设置，是 SDK 配置，不作为用户曾点击同意的证明。内部停用机制（不作为公开设置）先停止新派发，清空 SQLite 待发队列、增加开关 epoch、关闭 SDK 收集并重置本机 Analytics 数据。已经发出的单次调用无法撤回，已被 Google 接收的数据不因本机关闭而远程删除。

队列预算两天／一万条，按修订顺序批量最多 100 条、失败最多五次；前台、提交后和三十秒心跳触发。环境切换丢弃另一环境的待发事件。发送不阻塞游戏，队列不可用不更改游戏规则；上传故障保留有界待发事实。

原生 `logEvent` 成功只代表 SDK 接受，随后由 SDK 自己联网、缓存和重试，不代表服务端确认。SQLite 提交与 SDK 调用无法跨系统原子提交，崩溃窗口可能重复；GA4 不保证按自定义 `event_id` 去重。本地事实可准确去重，在线报告是开启分析的安装的趋势观测，不能当作精确钱包／推荐／交易账本。当前没有 BigQuery、服务端汇总或购买验证；不将队列描述为已经实现服务端 exactly-once。

事件 `event_at` 是业务时间参数，GA4 原生事件日期仍按 SDK 接收／发送及属性规则处理；有界晚发、内部停用和离线构建都会影响覆盖率。GA4 用户数也不是本地安装数或自然人数，两个模式用户数不能相加。

## 六 环境、项目及在线报告

在线报表可从模式、内容、规则、指标版本等现有变量进一步筛选。跨地区排查结合 GA4 自带国家／地区、操作系统、设备及应用版本报告；这些是 SDK 观测维度，不需上传 GPS 或自行识别玩家。Google 服务受网络、系统设置及当地可达性影响，不能保证所有地区、所有安装均有上报。不要将不同生命周期事件的时长总和相加，不把同页多个事件的用户数相加，不把混合版本／partial 样本默认用于校准。默认前十行仅是显示行数，分析逐关时应提高行数或筛选题号。自定义定义需要后续采集才产生数据，不回填此前事件。

受 GA4 探索每份最多二十维度／二十指标限制，核心与明细分成两份。未将高基数单事件 ID 注册维度；稳定题目数量较多，GA4 标准汇总可能出现 `(other)`，逐题分析用探索并限定模式／内容，精确本地事实仍在 SQLite。在线 P50／P90、严格窗口完成率、成熟队列留存未用自由表事件比值冒充；目前以本地导出准确复核，未来如需总体精确重算再单独评审免费仓库／导出方案。

隐私政策说明默认采集的数据、Google SDK 处理、改进关卡／可靠性的用途，以及不接受时停止使用并卸载；卸载不能删除 Google 已接收的报告。默认开启、无开关是用户确认的产品决定，不构成对所有地区／平台均可免同意采集的认定。发布前须核对分发地区、适用规则和平台审核要求；若当地要求事先同意，单独的隐私政策告知或“不接受请卸载”不能替代该同意。参考 [Apple 5.1.1](https://developer.apple.com/app-store/review/guidelines/#data-collection-and-storage)、[Google Play 用户数据规则](https://support.google.com/googleplay/android-developer/answer/10144311)。尚未据此开放公开发行。

Google 配置与申报口径（10 月 10 日核对）：SDK 支持自动采集；Play Data safety 支持将实际无法选择退出的收集申报为 Required／必需。按当前默认开启、无公开退出入口的实际行为，相关收集项填写必需，不填写可选。“必需”描述实际产品行为，不表示统计为游戏运行所必需，也不是 Google 对该采集方式的合规推荐或用户已同意的证明。Google 明确说明 Data safety 本身没有新增用户同意机制，适用时仍需遵守 User Data 的告知和同意要求。因此不预设所有统计、所有地区都必须弹窗或设置开关，也不将默认采集配置视为全球豁免。用户于 10 月 10 日明确改为 13 岁及以上，Console 已保存 13–15、16–17、18+；没有实现年龄验证。13–17 在部分地区仍可能属于儿童，年龄声明不证明全球免同意。参考 [Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469)、[Firebase 采集配置](https://firebase.google.com/docs/analytics/android/configure-data-collection)。

Firebase Analytics／GA4 可免费使用，项目维持 Spark；不启用账单、付费导出、BigQuery、Crashlytics 或推荐后端。免费能力与限制参考 [Firebase Analytics](https://firebase.google.com/docs/analytics)、[价格](https://firebase.google.com/pricing)、[GA4 探索限制](https://support.google.com/analytics/answer/7579450)。服务端保留和删除由 GA4 设置与 Google 规则管理，本轮没有另设无限保留。

## 七 本地报告、验证与发布边界

```sh
npm run analytics:report -- /absolute/path/player.sqlite
npm run analytics:report -- /absolute/path/player.sqlite 2026-10-20T00:00:00Z 1
```

Node.js 24 只读打开明确提供的玩家库，输出 `builds/analytics/local-report.json` 和 `local-report.html`，包括覆盖／发送、窗口首次体验完成、单安装回访、首次冻结事实、桶分布、记忆／辅助、长期摘要、每日活动与未完成挑战。命令不上传数据，不导出安装 ID，不自动读取手机私有库；数据库可能含个人游玩记录，分享导出须明确授权。

已有自动验证覆盖：跨重来／干净暂停累计和首通冻结；中断 partial；请求回调去重；记忆完成后撤销与重复循环；跨午夜、时区和墙钟变化；首次默认开启／保留关闭选择／不补历史／离线不建队列；发送故障和关闭中的队列隔离；全部参数限额；奖励／消耗不重复；写入失败回滚和有序重试；成熟／未成熟／partial 分母。既有存储回归覆盖全 1050 经典关卡、长撤销历史和资源守恒。

当前发布批次已通过自动回归、类型及代码检查；Test Android 启动到 Google 收件及 Production 候选离线 SDK 接受的范围由[设备支持](device-support.md)统一维护。最终包、Data safety、13+ 与公开政策部署的实际证据由[发布记录](release-readiness.md)维护，不在本文重复版本修改过程。
